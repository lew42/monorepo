2026-08-26 - add step 6: census your OWN new prefix against itself. A set of parts plus a set of variants named after those parts collides: .demo-mini-crumbs was both the crumb strip and the picture called crumbs, so the picture's root wore the strip's align-items:center and shrank to its content, silently. The framework already has the answer - page--<name>, two dashes, for the instance stamp.

2026-09-05 (layout-system) - step 2 should census your VIEW CLASS NAMES as well as the class names you type, because they are the same namespace. `View.classify()` kebab-cases every constructor in the chain, so a part called `LayoutsPair` wears `.layouts-pair` - the two-track flex row it builds - and its toggle, its pair and its explanation each became a 50% track of it. Nothing threw; the demo simply laid out sideways at 1280. The `code` skill warns about a subclass named after a FRAMEWORK word (`Rail`, `Stage`); the collision that actually bit was with the module's OWN new class, which is exactly what this skill exists to catch. Check-shape: grep your module for `class [A-Z]` and run the kebab-case of each name through step 2 alongside the strings.

2026-09-05 (paging-mechanisms-v2) - seconding the line above from an independent task the same night: `class Swapper extends View` stamped `.swapper`, an UNPREFIXED global class, and the `.paging-swapper` rules written for it matched nothing. Nothing threw and the page looked plausible because the children were block-level anyway; it surfaced only when a probe read the root's className. Two agents hit the same thing in one night, so step 2 really does want `grep -n 'class [A-Z]' <module>` beside the string census - and step 3's "prefix with the owning module" applies to the CLASS NAME, which is where it is least obvious.

- 2026-09-05 (paging-v3): the skill checks class names you TYPE, and says nothing about the ones a class DECLARATION mints. `View.classify()` walks the constructor chain and adds every name lowercased, so `class Stage extends View` wore the framework's own `.stage` layout word (`container-type: inline-size; overflow: hidden`) and shrink-wrapped itself to 307px inside a 1546px frame with nothing thrown. Add a step: **a View subclass's NAME is a CSS class — census it like any other, and prefix it (`PagingStage` → `.paging-stage`).**
