2026-08-26 - add step 6: census your OWN new prefix against itself. A set of parts plus a set of variants named after those parts collides: .demo-mini-crumbs was both the crumb strip and the picture called crumbs, so the picture's root wore the strip's align-items:center and shrank to its content, silently. The framework already has the answer - page--<name>, two dashes, for the instance stamp.

- 2026-09-06 (layout-a): rule 6 says never start a class with `page-` unless you are core/Page — but a SECOND core module that extends Page has no honest alternative when its own word is already taken (`layout-` is ext/layout's, with twelve importers). `core/Layout` took `page-layout-` and declared it in css-scopes.txt under the core block. Worth one line in the skill: `page-<module>-` is available to a core module whose class extends Page, declared like any other prefix — it is a sub-namespace, not a squat.

- 2026-09-06 (section-b): SECOND occurrence of the line above, same day, different module — `core/Section` took `page-section-` for exactly the same reason (`section-` is /imagine/sections' and `.section` is a live rule in core/new/1/site/styles.css). Two core Page subclasses in one day both had to reason past rule 6 from scratch; it is a rule waiting to be written, not a one-off.
