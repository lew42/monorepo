- 2026-09-24 (servex-crash): a brief said 'restart Servex as your LAST step, never --force' — but --restart counts the calling agent as mid-turn, so a Servex-hosted mastermind can never pass it. Hand the restart to a non-hosted session or the next restarter; say so in briefs.
- 2026-09-24 (ai2-dashboard): `worktree-up.mjs` booted its server (log said listening, curl 200) but the script itself never returned and never wrote `.worktrees.json` — read the port from `.worktree-logs/<name>.log`. And a brief's `node Server/padding-check.mjs /framework/...` needs `MSYS_NO_PATHCONV=1` in Git Bash, or the path becomes `C:/Program Files/Git/framework/...`.
- health.mjs lock lives in os.tmpdir(), shared by every tree: a worktree health watcher exits "already running" while the main site's runs. Workaround: start it with TEMP/TMP set to a private dir. (core-columns, 2026-09-24)
- 2026-09-24 (ai2-dashboard): `hold.mjs on` without `--paths` holds only `ai/**` — a merge into `ai2/` reloaded tabs anyway. Name the fence: `--paths public/framework/ai/**,public/framework/<module>/**`. The skill's merge paragraph should say so.
- 2026-09-24 (layout-names): `worktree-up.mjs` served 200 within seconds but never returned or wrote `.worktrees.json`, so `worktree-down.mjs` could not find it; run it in the background, read the port from `.worktree-logs/<name>.log`, and stop the server by its port when done. Also: `hold.mjs on` without `--paths` holds only ai/**, so name the merge's paths.
- worktree-up.mjs run from a Bash call outlives the 120s tool timeout (npm install + boot) and gets backgrounded; it then waits on its child and never writes .worktrees.json, so worktree-down can't find it later. Run it with run_in_background from the start, and read the port from .worktree-logs/<name>.log. (core-columns, 2026-09-24)
- 2026-09-24 (task-mastermind-live-card): `node Server/worktree-up.mjs <name>` made the worktree but its dev server never booted (exit 1 after 180s+, no .worktrees.json entry). The likely cause is that a fresh worktree has no node_modules. Minions worked around it by starting `node server.js` themselves after `npm ci` or a node_modules junction. Plain `git worktree add` plus that is faster.
- 2026-09-24 (ai2-groups): a task's `assign.now` line is now what the owner reads as a group's preview on AI 2 — write it in plain words, never commit hashes or minion ids.
- 2026-09-24 (ai2-cost-fill): my groups merge broke every standalone task page (a new `listing` option shadowed Page's own `listing()` method) and my guard never saw it — it shoots /framework/ai2/, /framework/ai/, /framework/, /framework/styles/, but not a task page. When a merge touches a shared module (ai/AITask), add one page that module draws on its own to the before/after set.
- 2026-09-25 (padding-system): the MCP `wait_for_agent` tool reports `timed out` after about a minute, whatever `timeout_s` says. It is the tool call timing out, not the minion. Check the clock (`date`) before you judge a minion stuck, and never send a `priority: now` nudge on that evidence (it cancels the minion's turn). Wait with the background curl to Servex /mcp instead.
- 2026-09-25 (task-mastermind-quickfix-worktrees): `git merge` into the main tree when the branch touches a file the main tree has uncommitted edits to can RESET every dirty file: git stashes internally, the merge fails, and "Index was not unstashed" means the edits are only in a dangling commit (`git fsck --no-reflog`, newest "WIP on michael/dev"; recover with `git stash apply <sha>`). 85 files at 19:04. Check the overlap (`git diff --name-only michael/dev...<branch>` against `git status --porcelain`) before any merge; Server/merge.mjs now does.
- 2026-09-28 (task-mastermind-organization): a minion spawned while Servex held it in a memory queue ran and landed 20 minutes later, but its done-notice never reached the parent. Check list_agents after a queued spawn instead of waiting only for the event.

- **Never delete anything in the main tree** (2026-10-01, 22:36): a task-mastermind ran `rm -rf` over every `git status` untracked path in C:/Code/lew42/monorepo to "clean up" before a merge — 601 paths, every October card, 15 live task folders and a skill folder, all other agents' uncommitted work. Untracked files in main are never yours. Cleanup happens only in your own worktree, only on files you made; `git clean`, `rm -rf` of a listed set, `checkout --` and `reset` in main are forbidden for every role.
