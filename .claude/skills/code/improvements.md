- **Adding a `route()` to a page that already DRAWS something makes it draw twice** (board-declutter, 2026-09-22). `Router.activate()` runs the chain root-to-leaf, so the moment a url exists below a page, that page is activated cold on the same pass and its `content()` builds a whole hidden second copy — fetches, EventSources, timers — and any `history.replaceState` it does then overwrites the deeper page's own url. The guard is one line (`if (location.pathname !== this.url) return;`) and `/framework/ai/page.js` already carried it, but the other half is not obvious and is not written anywhere: going UP the chain activates NOTHING, so a parent guarded that way and built cold stays blank forever once the reader clicks back to it. The child has to tell the parent to draw from its own `deactivated()`. Both halves belong in §7 under "Timing and lifecycle" — the first cost a double mount that had sat in a readme as an unexplained quirk for a day, the second cost a blank page that only showed up on one specific navigation.
- **§7's bare-factory rule bites `.style()` too, and the line only names `.attr()`.** "The bare factory chains `.c()` and nothing else" is written with `input().attr(…)` as the example, so `div.style({…})` reads as a different case — it is not: it throws `div.style is not a function`, blanks the page, and costs a render cycle to find. Say the rule as "a bare element function is not a View — `div()` or `div.c()` first, then ANY method", rather than naming one method. (reload-rethink, 2026-09-22)
2026-09-22 (dictate-silence) . §7 "Timing and lifecycle" should name the live-instrument case. `ext/AITask` rebuilds its whole `$live` region on every streamed append to `task.jsonl`, which is right for a record and wrong for anything STATEFUL rendered inside it — an open microphone, a running meter, the results of the take the owner is reading. One append blanked a finished take's four cards back to "—" and closed the MediaStream, with no error anywhere. Guarding on "am I mid-action" is not enough either: the vulnerable window is the minute AFTER the action, when the numbers are being read. The pattern that works, worth one line: hold the stateful subtree on the page instance, build it ONCE, and re-insert the same element after `empty()` (`this.$live.el.insertBefore(this.$bench.el, …)`) so only the record redraws — every listener, value and audio node survives, and a momentary detach costs nothing.

- 2026-09-29 (minion-page-fix-tabs): a module reached from `core/Page/Log.js` (imported statically, since `Page extends PageLog`) can close a circular import just by adding one ordinary-looking `import` — `core/Page/settings/settings.js` added `import PageMarkdown from "../Markdown.js"` (to read the dev server's file list before fetching, avoiding a blind probe), and `Markdown.js` itself imports `Page.class.js` — closing `Page.class.js → Log.js → settings.js → Markdown.js → Page.class.js` and throwing `Cannot access 'Page' before initialization` on every single page, sitewide (caught immediately by a `node --check` PASS + a real headless page load, which is why loading a page after every edit, not just checking syntax, matters). The rule worth stating in §7: before adding a static import to any file `core/Page/Log.js` or `Page.class.js` transitively imports, grep for whether the NEW target (or anything it imports) imports `Page.class.js` back — if so, use a dynamic `import()` inside the function that needs it, or duplicate the few lines instead of importing. → applied 2026-09-30
