2026-09-06 (graduate-3) . say in the traps section that `export { A, B } from "./x.js"` is a PASS-THROUGH, not a binding: it publishes the names without putting them in the module's own scope, so any code in the same file that reads one throws `A is not defined` at import time. Moving five word lists out of `imagine/paging/blocks.js` into `core/Page/words.js` and re-exporting them would have blanked every page in the realm, because `CONTROLS` two hundred lines below lists `NAVIGATION` and `SURFACES` by name - the fix is to `import` AND `export` them, both lines. It is the same shape as the `render()`/`naming()` shadowing traps already listed: nothing warns, and the failure is a whole realm, not a line.


2026-09-13 (self-evident-critique-2) . the heredoc rule in the traps section needs its other half: even a QUOTED delimiter (`<<'PY'`) fails once the payload is a few KB of prose - a python block appending eighteen jsonl lines died with `bash: -c: line 18: unexpected EOF while looking for matching \x27` and nothing was written, while the same bytes written to a `.py` file with the Write tool and then run with `python <path>` worked first try. So the rule is not "quote the delimiter when there is a backslash", it is "anything longer than a few lines goes through the Write tool"; the inline heredoc is for one-liners only.
