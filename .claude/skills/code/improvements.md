- **A captured callback's RETURN VALUE is appended.** `div.c("pages", $p => this.regions.set(name, $p))` returns the `Map` and painted a literal `[object Map]` in the page; nothing threw. §7 lists the `.append(bare fn)` trap but not this one, and the arrow-with-expression-body form is the natural way to write "capture this box". Block body for any callback whose last expression is not a view. (2026-08-27, core/Page panels demo)

- 2026-08-27 (column-polish): §7 warns that shadowing a `View` member breaks silently, but not the REVERSE — adding a **new core method** named after a plain noun collides with page state that already exists. `Page.opens()` was shadowed by `overview/columns/uses/inbox`'s `opens: 0` field and killed the whole page with `this.opens is not a function`. The rule that would have caught it: a new method on `Page`/`View`/`App` gets its family's prefix (`default_column`, not `opens`), and `grep -rn "opens[:=]" public/` before naming.

- 2026-08-29 (vary-labs): `demo.app(root)` on a columns() tree with a nested `classes: "default"` cascade (host → default child → default grandchild) renders all three, then hides depth 2/3 — `demo.app`'s own `mark()` strips every `.page.default` in the box on every `show()` and only re-adds it to `page.chain()` of whatever it is showing, which for `demo.app(root)` is `[root]` alone. `examples/looks/backgrounds` already dodges this by returning `root.children.get(name)` (the deepest page) instead of the root, but nothing says why — worth a line in `new-page` or `layout` for "previewing a nested default cascade in a demo.app box: hand it the leaf, not the root." Separately, `width: "full"` on any column (even correctly nested) collapsed the site's own left sidebar to 0px — reproduces on the framework's own `core/Page/overview/columns/finder/guides/words/full/`, so it's a real core `Page.css`/shell interaction, not a one-off.
