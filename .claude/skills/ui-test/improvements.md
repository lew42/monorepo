# ui-test — improvements

Append one line whenever this skill misled you or was silent about a trap that then bit you.

- 2026-08-27 (pg-ux-research, want only — the facts were applied to SKILL.md/drive.mjs by the mastermind, same day): `watch` accepting a selector that matches MANY elements and reporting each, plus a `baseline` verb, so a rect-sweep needs no hand-rolled eval. (drive.mjs crash on mid-run navigation: FIXED — rects/metrics/screenshot now swallow the destroyed context, flag `navigated mid-step`, and carry on.)
- 2026-09-04 (omnibox-prototype): the `offscreen-x` flag compares a watched rect against `vp.width`, a const captured ONCE from the plan's initial viewport — a mid-run `viewport w h` resize actually resizes the page but never updates `vp`, so anything past the OLD width false-positives as offscreen after every later resize (drive.mjs line ~16 vs ~85). Cost one detour chasing a phantom 3440px overflow; the real check (`doc.sw <= doc.cw`) was fine the whole time. Fix: update `vp` inside the `viewport` verb handler, or compute the threshold from a live `page.viewportSize()` each flag check.
- 2026-09-04 (paging-clarity): warn that a plan file written through a shell heredoc mangles backslashes, producing either an invalid plan or a broken eval. A regex inside an eval arrived as an invalid JSON escape and drive.mjs died at JSON.parse; a string-split escape that DID parse reached the browser as a literal newline and threw "Invalid or unexpected token" - twice, with the step's own error field hiding the cause. What worked: build the plan with a small python/node script (json.dumps does the escaping) and keep every eval backslash-free (use .textContent rather than an innerText regex).
- 2026-09-04 (imagine-shells): the plan's `out` dir written as a Git-Bash-style path (`/c/Users/.../scratchpad/foo`) is NOT rewritten by MSYS_NO_PATHCONV like a bare CLI arg is — drive.mjs is a Node process, so it silently joined it as a relative path under the invoking drive, writing screenshots to `C:\c\Users\...` (a literal `c` folder off the drive root) instead of the intended scratchpad path. No error, `steps.json` even printed the mangled path in its own summary line. Fix: always write `out` as a real Windows path (`C:/Users/...`) in the plan JSON, never the `/c/...` bash form.
- 2026-09-04 (imagine-cms): watching a `.page--<name>` selector on a core/Page columns page always flags `zero-size`/`missing`, even on a page that renders fine — core/Page gives every column page's own wrapper `display: contents` (doc/columns.md), so `getBoundingClientRect()` on it is legitimately `{0,0,0,0}` by design, not a layout bug. Cost one detour re-verifying the click actually worked (it did — location.pathname and the child's innerText proved it) before realizing the flag was noise. Worth a line in the skill: on a columns page, watch `.page-column-body` (a real box) instead of `.page--<name>` (a `display:contents` wrapper) if you want the flag to mean anything.
- 2026-09-05 (paging-templates): name the SYMPTOM a LiveReload mid-load reload produces, not just the cause — while sibling agents were saving under `public/`, `goto` reported `pageerror: TypeError: Chaining cycle detected for promise #<Promise>` twice on a brand-new page, which reads exactly like a static ESM import cycle in the module you just wrote. Cost five bisecting probes (dynamic-importing each new module in isolation — all `ok`) before a re-run on a quiet tree came back clean. The tell: the error appears on the `goto` step only, is not reproducible, and every module imports fine under `import(...)`. Worth one line: a promise-cycle pageerror during load is a reload race, not your import graph.

- 2026-09-05 (paging-mechanisms-v2): the "a columns page holds TWO of every selector" trap is wider than the `default` sibling the skill names - EVERY column in the chain is in the DOM, so a hub that teaches a gesture and the leaf page that demonstrates it carry the SAME module classes. `[...document.querySelectorAll('.paging-tab')].find(e => e.textContent === 'Pricing')` clicked the HUB's miniature three columns away; every rect then read unchanged and the caption never updated, which looks exactly like a dead click handler. Cost one full debugging pass through View.click() and press(). Second half of the same lesson: a chip built as `icon(name) + span(label)` has `textContent` "layerscard-in" - the icon ligature IS text - so match with `.endsWith(label)`, never `=== label`. Scope by the page's own root (find the `.page` whose innerText starts with its takeaway) and the two go away together.
- 2026-09-05 (ux-design): a plan run with `plan.out` omitted (the skill's own doc never says it's optional or required) writes into a REPO-ROOT `ui-test-out/` dir, not the scratchpad - `drive.mjs` line ~15 is `resolve(plan.out ?? "ui-test-out")`, resolved against the invoking process's cwd. Ran the sample plan shape without `out` from the repo root and it silently wrote outside every stated fence (only `public/imagine/<realm>/` and the task dir are allowed); caught it by `git status` noise, not an error. Worth a line: `out` is not optional in practice - always set it to a scratchpad path, or the default lands in the repo.
- 2026-09-05 (ux-shells): `click "text=<card title>"` on a `.page-preview` card timed out 30s (no error, just TimeoutError) even though the card and its link render fine and are visible in the screenshot. Cause: `.page-preview-link::after` (Page.css) is spread `position:absolute; inset:0` over the WHOLE card so the whole thing is clickable, and it paints on top of the link's own child text — Playwright's actionability check requires the element receiving the hit to be the target or a DESCENDANT of it, and here the hit resolves to the ANCESTOR `<a>` instead, which fails the check forever. Same family as the documented ":hover ancestor reveals child" trap, but with no hover involved — any full-card overlay pseudo-element on a real site (not just this one) will do this to a text-based click. Fix: click the anchor itself by a stable attribute (`a[href='...']`), never the title text inside it, whenever the card pattern uses an `::after` overlay for its click target.
- 2026-09-05 (ux-vary): compounding the known out-omitted trap above — the stray repo-root `ui-test-out/` is not just outside the fence, it is already GIT-TRACKED (a prior reviewer's same mistake got committed). `rm -rf ui-test-out` to clean up the fence violation showed as tracked deletions in `git status`, nearly discarding committed history instead of just my own scratch output. Recovered per-file with `git show HEAD:<path> > <path>` (never `checkout --`, which the brief bans outright). Worth a line: before deleting any out-of-fence dir you didn't expect to exist, check `git status` on it first — it may already be someone else's committed mistake, not empty scratch space.
- 2026-09-05 (ux-stream): the `/c/...` path trap above (2026-09-04, imagine-shells) is not `drive.mjs`-specific — it bit again in a from-scratch Playwright script, on a `page.screenshot({ path })` argument built as a plain JS string literal (not even a CLI arg, so `MSYS_NO_PATHCONV` was never in play). Node on Windows treats a leading `/` as "root of the current drive", so `/c/Code/lew42/monorepo/...` silently wrote to `C:\c\Code\lew42\monorepo\...` — a stray `C:\c\` tree, no error, script logged "success" with the intended-looking path in its own console.log. Third recorded occurrence of the same shape across two skills' worth of scripts. Worth promoting out of improvements.md and into the main SKILL.md text: **any path a Node script writes to must be a real Windows path (`C:/...`), full stop — never `/c/...`, whether it comes from argv, a plan file, or a literal in the source.** Cheapest guard: write to a relative/bare filename in the scratchpad cwd and `cp` the result with Bash afterward, where `/c/...` is native and safe.
- 2026-09-05 (nav-stability): **a click auto-scrolls, and that scroll reads as a layout jump.** Playwright scrolls the target into view before clicking, so any plan measuring a `watch` rect across a click on something below the fold reports the SCROLL, not the mechanism - and there is no error, just a plausible-looking number. Scroll the target into view (`scrollIntoViewIfNeeded`) BEFORE taking the "before" reading. Second half of the same lesson: **scroll anchoring can absorb a height change** - when a box shrinks inside a scrolled container the browser may hold the content below it still and move the BOX instead, so a viewport reading depends on where you happened to be scrolled (measured: the same swap read 1px or 258px depending on scroll position). When the claim is about a component, measure offsets INSIDE that component's own box, not against the viewport.

- 2026-09-05 (paging-fix-2): the skill's "a columns page holds TWO of every selector" trap has a second shape it does not name — **an APP SHELL builds its home page on every cold load and hides it with CSS**, so a deep page's DOM holds the hub's whole content too. `document.querySelectorAll(".paging-row")` returned 24 with 4 visible, and Playwright's first match was one of the 20 hidden ones: a bare 30s timeout, reading exactly like a broken control. Scope every selector to the ACTIVE page (`.page.active-page …`) or to the visible region, and filter probe results by `getBoundingClientRect().width > 0` — a hidden element still answers `elementFromPoint` questions with plausible-looking numbers.

- 2026-09-05 (paging-fix-3): the `/c/...` trap has one more entry point the skill does not name - **the plan's own `out:` field and the plan's own path on the command line**. Passing `/c/Users/.../plan.json` as argv died with ENOENT on a C:\c\Users path before a single step ran, and MSYS_NO_PATHCONV=1 does not help because the mangling is Node's, not bash's. Both the argv path and `out:` must be Windows-form (`C:/Users/...`). Worth one line in the Output section beside "plans and out dirs go in the session scratchpad", which is where an agent reads the path convention and currently shows only a `<scratchpad>` placeholder. Second, unrelated: **a plan is JSON, so a regex inside an `eval` step needs its backslashes doubled** - a \s+ written straight into a shell heredoc arrives as one backslash and the runner dies with "Bad escaped character in JSON at position N", which reads like a runner bug rather than an escaping one. Write plans with the Write tool or json.dumps, never a heredoc.
