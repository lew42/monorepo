# layout — improvements

Any agent may append. One line each: `YYYY-MM-DD · what should change · why (the evidence)`.
A recurring line is a rule waiting to be written; the owner promotes.

- **PROPOSAL (changes the five-question ritual, not fail-safe):** A live readout is part of its
  control, and the skill's five questions never ask where the consequence lands.
  `/framework/styles/system/studies/color/` opened with a sentence that two sliders 923px further
  down rewrote — 2,073px at 400 — so dragging changed something the reader could not see, and at
  400 the rewrap shoved the whole wall of grounds 42px. Every numeric check passed: one measure,
  one rhythm, no overflow, no constant. Proposed new clause beside Q5: for every control, say how
  far its visible consequence is from it, and what moves when that consequence changes size — and
  a readout that grows a line needs a reserved `min-height` so it doesn't reflow its neighbours.
  This adds a required step for every future agent, so it needs the owner's yes, not an autonomous
  edit. (polish-critic, 2026-09-17)

- 2026-09-22 (prompt-lifecycle): a headless COUNT can be silently doubled, and the measure cycle
  never says to check. `/framework/ai/v/3/` builds its whole page twice on every load — two
  `.v3-wall`s, two of every view, one hidden — so `locator('.v3-prompt-row').count()` read 10 for
  5 rows and `querySelector('.v3-prompts')` returned the HIDDEN copy: `width 0`,
  `grid-template-columns: "none"`, which reads exactly like a broken layout. The check that would
  have caught it in one line is to assert the count of the CONTAINER before trusting any count
  inside it, and to take geometry from `[...document.querySelectorAll(sel)].at(-1)` (or filter by
  `checkVisibility()`) rather than `querySelector`. "Look at it, then cycle" already warns that a
  hidden `<details>` still reports geometry; this is the same failure one level up, from a whole
  duplicated page rather than one collapsed element.
2026-09-22 (dictate-silence) . "look at it" is in the skill, but nothing says a screenshot is the ONLY instrument for a whole class of defect. Two in one task, both invisible to every numeric check: a level-meter fill painted with a non-existent custom property (transparent bars, correct numbers, zero console errors, four widths clean), and a five-card stat row that measured `rows: 1` at 1280 right up until a `min-width: fit-content` fix made the cards wider and silently pushed the fifth onto its own line. Worth one line in "Look at it, then cycle": geometry assertions prove POSITION, never PAINT — after any change to a colour, a fill, a gradient or a card's width basis, re-open the screenshot, because `scrollWidth`, `getBoundingClientRect` and a clean console all agree with each other on a page that renders wrong.
- **A layout invariant can be measured against the wrong box and pass or fail for the wrong reason** (layout-analysis, 2026-09-22). "Look at it, then cycle" says no text or framed box at x:0, and its exclude list says to skip anything whose nearest scrolling ancestor declares `overflow-x: auto|scroll`. I measured ink against that scroller's box instead of skipping it, and a 238px rail plus a code block turned a real 980px inset into 0 and a real 28px inset into 1 — 15 false violations at 400 out of 16. Two clauses worth adding: the reference edge for "how far is this from the edge" is the innermost content REGION (`.pages`), not the page (on a topic shell the page contains the sidebar and every reading is 0); and a scrolling ancestor means the element is EXCLUDED, never re-measured against it — and only when it really scrolls (`scrollWidth > clientWidth`), because a box that merely declares `overflow-x: auto` is not one.
2026-09-22 (ai2-master-detail) . a two-column shell told `height: 100%` is NOT bounded, and nothing anywhere says so. A grid's implicit ROW is `auto`, so it grows with its content however tall the grid itself is: `.ai2` measured a correct 900px while the rail inside it stood 23,429px, ran off the bottom clipped by an ancestor's `overflow: hidden`, with no scrollbar, no overflow flag, `scrollWidth === clientWidth`, and nothing in the console. Every numeric check the skill names passed. The fix is one declaration, `grid-template-rows: minmax(0, 1fr)`, and the diagnostic that found it was walking the box chain UPWARD from the thing that should have scrolled, reading `height`/`scrollHeight`/`clientHeight`/`flex` at each level — which found it in one pass. Worth a line beside "Scrollbars are a decision": for any full-height shell, assert that the box you MEANT to scroll actually reports `scrollHeight > clientHeight`; "I gave the container a height" is not the same claim, and the two differ silently for a grid row, a flex item with no `min-height: 0`, and an `align-items: flex-start` parent alike.
2026-09-22 (ai2-master-detail round 2) . a grid region must NAME ITS OWN ROW whenever any sibling can be `display: none` at some width, and nothing in the skill says so. A card page was `grid-template-rows: auto minmax(0, 1fr) auto` with three children — a back link (hidden above 40em), the ideas, a footer — so above 40em the back link created no grid item, the other two shifted up one, and the FOOTER inherited the `1fr`: 749px tall, starting a third of the way down a 900px column, with the ideas squeezed into 121px. Every assertion in the proof still passed, including the one that mattered ("the footer's top does not move while five sentences stream in") — it genuinely never moved, it was simply in the wrong place. Only the screenshot showed it, which is the same lesson as the dictate-silence line above, one level up: geometry assertions prove POSITION, and a position can be stably wrong. The fix is `grid-row: 1/2/3` on each region, which is immune to a hidden sibling; the check is to read back `gridTemplateRows` and confirm the row you expected to be `1fr` is the one that got it.
- 2026-09-22 (padding-law): **A page's left and right padding is not padding — it is the first and last TRACK of the page shell's grid.** So any rule that gives a `.page` its own `grid-template-columns` deletes both gutters unless it restates them, and `.page`'s `padding: var(--page-pad, var(--pad-y) 0)` has no inline half to catch it. `ext/toc` did exactly this and every ToC page above 82em put its `h1` flush against the sidebar; `.page:has(> .page-related)` in Page.css restates all four tracks and was always right. Check with `node Server/padding-check.mjs <url>`.
