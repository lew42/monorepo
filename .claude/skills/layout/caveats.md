# Layout caveats — what has bitten

One line each; the detail is where the link points.

- **52em is not 75 characters here — it is 83–103** in Montserrat; the safe ceiling for any copy is ~42em. The token is the finding, not the page. `ext/DesignTool/knowledge/characters-per-line.md`.
- **`.grid.auto` with a large `--column` is wrong for prose** — its `1fr` maximum is unbounded and one column takes the whole width (112 chars/line at 1280). `1fr` is for tiles; prose needs a ceiling. `ext/DesignTool/knowledge/bounds.md`.
- **A full-row item's inside must be able to stack** — a fixed three-track grid crushed the detail column to 16px at 400; `flex-wrap` + a `20em` basis is the same three places above ~34em, one column below.
- **Rail + article wastes a mega monitor** (18% of 3440 used) — the answer is a third region, a checkbox in the Docs layout, not a rewrite. `ext/DesignTool/knowledge/widescreen.md`.
- **A preview that renders a live thing breaks on cold paint** — `zoom` has no stable width while the wall lays out (`ext/editor` was the only live thumb and the only broken one). Take the default card or screenshot it.
- **A scroller cannot live in a wrapping row** — a flex line sizes to content, so `overflow-y: auto` has nothing to do once the row wraps; all three boxes declare it.
- **`.page.full` zeroes `--measure` and `--page-pad`**, and the title renders outside `content()` — declare the two tokens instead. `core/Page/readme.md`.
- **A tab an agent drives is HIDDEN, and hidden tabs do not lay out** — no rAF, no ResizeObserver, frozen `getBoundingClientRect()`. Check `document.visibilityState`; measure headless or with `mcp__site__shot`. Claim a tab you drive (`/framework/dev/Claim/`, `import("/framework/dev/Claim/claim.js").then(m => m.claim("claude", "<slug>"))`) so the owner knows it's yours, and release it when the task lands.
- **`frame()` was clamped by `framework.css`'s `iframe { max-width: 100% }`** — a 3440 run in a 1920 browser measured 1920; wide numbers recorded before the DesignTool.css fix are suspect.
- **Don't measure "dead space" by sampling points in the fold** — that rewards a TALL box and punishes a short one, the opposite of the intent. The number to report is the audit's own measure: the widest painted element's span against the viewport. Sample points are a second opinion, never the finding (2026-09-05).
- **`analyze()` and `rate()` disagree on purpose** — analyze reports failures (a clean page scores 100), rate ranks; ask both. Discount an `alignment` cluster at one repeated em offset (it is padding); `dead-space` needs four text blocks; a clean score is not proof of no vertical overflow (`sweep()`). `ext/DesignTool/knowledge/false-positives.md`, `blind-spots.md`.
- **Never measure a repo while agents are editing it** — a page read 92, 87, 84 across three passes under an uncommitted diff.

- 2026-08-18 (figma-spec-sheet): a page built through `demo.layout()` cannot paint its ground inline. `frame()` re-styles what `layout()` returns with `background: ""` (unless `twin:`), which wipes an inline value — and a bare `.page` is transparent, so on the demo stage's dark board every line of prose was `--ink` on near-`--ink`: present, measurable, invisible. Use the **`.surface`/`.wash` class**, which survives the re-style. Worth a line beside "a class that does not exist paints nothing".
- Bled card walls touch the viewport edge (padding study, 2026-09-01): `bleed` is paint-only — framed boxes and text ride the padded track. Detail: /layouts/doc/studies/approved/.
- Fixed spacing reads fine at 1280 and cramped at 3440 (2026-09-01, superseded 2026-09-06): `:where(*)` sets `--pad`/`--gap`/`--flow` as one clamp × the `--size` knob; columns pads scale by `cqi`. A hand-typed 1em pad on a wide-capable container is the smell. The numbers: /framework/styles/system/studies/size/.
- **`.page.active-page` measures 0x0** (2026-09-05, ux-gallery): it's `display: contents` — nested pages are peers, so the box has no box. Measure its direct child `.page-column-body` instead (`activePage.querySelector(":scope > .page-column-body")`); that element also floors at `min-height: 100%`, so its `scrollHeight` reads viewport-pinned for any page shorter than the screen — real for "does this page scroll", not for "did the content get shorter". ⚠ FINDING the right page is the other half of the trap: `.page.active-ancestor` returns the site's own shell — every `/imagine/…` url nests under it, so scoping there measures the site nav rail and every ancestor rail above your target too. Derive the class from the URL's own LAST segment instead — `document.querySelector(".page.page--" + location.pathname.split("/").filter(Boolean).pop())` — which held across leaf pages, hyphenated and numeric names, and dynamically-routed pages with no dir of their own, and correctly includes a default child shown open beside a landing page (confirmed on 31 pages, `ai/2026-09-05/spacing-audit-a/`).
- **A container query cannot restyle the element that declares the container** (2026-09-05, ux-game — the third time: `ext/Panel/toolbar` and `/framework/ai/`'s own card hit it in August, `ai/2026-08-17/layout-primitives/proposal.md`, "a rail cannot query itself"). `container: name / inline-size` on `.foo`, then `@container name (...) { .foo {...} }`, silently never fires — the container's own box measures correctly but the query never re-styles the element that IS the container. Put `container-type` on a wrapper one level up and query a DESCENDANT selector instead. Caught this time only because a 400px card rendered its own readout column 200px past the viewport with zero console error.
- **`order` moves the paint, not the rhythm** (2026-09-17, `/layouts/browse/` item page): `.page-title + *` and `.flow > * + *` follow DOM order, so a box moved with `order` keeps the margin of the place it was written and butts against its new neighbour; and `order: -1` lands ABOVE the page's own h1 (same grid, default order 0). Restate the margin at the drawn position, or reorder the DOM — under 40rem the browser rebuilds the row in JS on a `matchMedia` change.
- **A column WIDTH cannot control a column COUNT** (2026-09-17, practice-critic): `auto-fill` lands on whatever fits, so a fixed item count with gaps in its divisors shows a short last row at widths BETWEEN the ones you measured — 24 tiles sat on 5 columns over 2240–2480 and 7 over 2880–3120, 12 cards on 5 over 2800–3360. When the count is fixed, write the counts out as container queries and check each is a divisor.
- **Four widths cannot see a wall hole or a wall that steps BACKWARDS** (2026-09-17): a count that only appears between two of them, and a count that DROPS when a region arrives (2 columns at 720 became 1 at 800 when the rail turned into a column). Sweep the count every 80px from 400 to 3440 — 39 loads, about four minutes.
- **`position: sticky` on a grid item under `align-items: start` can never fire** (2026-09-17): the item is exactly as tall as its content, so sticky has zero travel — a panel sat with 1,940px of nothing under it and every numeric check passed. The box that stretches and the box that sticks must be two boxes.
- **Three ways a headless probe measures nothing here** (2026-09-17): `document.querySelector(".page")` returns the FIRST `.page`, a hidden one — want `.page.active-page`; `getPropertyValue("--gap")` returns the literal `clamp()`, never px, so `parseFloat` is NaN and every threshold passes — paint the token on a probe div and measure the div; `--measure` is `40em`, so `parseFloat` reads 40 and every paragraph is "past the measure" — the ceiling is the element's own computed `max-width` in px.
- **A `scroll-margin-top` that has to clear a sticky bar belongs in `rem`, not `em`** — the body font here is a viewport clamp (14→18px), so an `em` margin is SMALLEST exactly where a wrapping chip bar is TALLEST: `6em` measured 84px against an 85px bar at 400 and left the heading's top 15px hidden. `6rem` (a constant 16px root) clears a 51–85px bar at every width with one value. Same family as "floors belong in rem; only a rail belongs in em" (/layouts/browse/, 2026-09-17).
- **A headless measurement of any `em`-based width is unstable until the fonts land** — every column width on this site is a `clamp(40em, 42cqi, 46em)`, so the same page at the same viewport read 1051px before the webfont arrived and 992px after, with no code change between the two crawls. `waitUntil: "networkidle"` is not enough. Add `await page.evaluate(() => document.fonts.ready)` plus a short settle before the first measurement, and prove it by measuring the same page three times before trusting a before/after table (calls-core, 2026-09-18).
