- 2026-09-05 (paging-templates) · the `container-type: size` caveat should say `inline-size` counts too, whenever the box is shrink-to-fit · `/blog/blog.css`'s `.blog-hero` declares `container: blog-hero / inline-size` AND `align-self: start`; on the blog front it lands in a stretched track so the two never meet, but reused inside a flex COLUMN the `start` makes the width fit-content and an inline-size container may not be sized by its own contents — the hero measured a few px wide and set its own title one character per line, no error, no overflow flag. Rule shape: before reusing another module's box in a new container, read back BOTH its `container-type` and whether your container stretches it.
- 2026-09-05 (paging-templates) · say that a fix aimed at ANOTHER module's rule must out-specify it, not merely be written later · `.templates-blog-hero { align-self: stretch }` at (0,1,0) lost to `.blog-hero` at (0,1,0) because `blog.css` is appended by `View.stylesheet` when `Post.js` is imported — which happens AFTER the importing module's own sheet. Load order in `@layer theme` follows the IMPORT graph, not the file you are editing; `.templates-blog > .blog-hero` (0,2,0) was the fix.
