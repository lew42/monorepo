# css — improvements

Any agent may append. One line each: `YYYY-MM-DD · what should change · why (the evidence)`.
A recurring line is a rule waiting to be written; the owner promotes.
- 2026-09-05 (paging-templates) · the `container-type: size` caveat should say `inline-size` counts too, whenever the box is shrink-to-fit · `/blog/blog.css`'s `.blog-hero` declares `container: blog-hero / inline-size` AND `align-self: start`; on the blog front it lands in a stretched track so the two never meet, but reused inside a flex COLUMN the `start` makes the width fit-content and an inline-size container may not be sized by its own contents — the hero measured a few px wide and set its own title one character per line, no error, no overflow flag. Rule shape: before reusing another module's box in a new container, read back BOTH its `container-type` and whether your container stretches it.
- 2026-09-05 (paging-templates) · say that a fix aimed at ANOTHER module's rule must out-specify it, not merely be written later · `.templates-blog-hero { align-self: stretch }` at (0,1,0) lost to `.blog-hero` at (0,1,0) because `blog.css` is appended by `View.stylesheet` when `Post.js` is imported — which happens AFTER the importing module's own sheet. Load order in `@layer theme` follows the IMPORT graph, not the file you are editing; `.templates-blog > .blog-hero` (0,2,0) was the fix.
- 2026-09-05 spacing-judge: caveats.md's spacing-tokens line names `--pad-default: clamp(1em, 1.3%, 2em)` / `--gap-default: clamp(...)` as what :root carries; it now carries three RAMPS and every element derives the `-default` tokens on `:where(*)` x `--spacing` - a theme retunes a ramp, never a default (a subtree `--pad-default:` is re-derived underneath it). The vw-not-% rule for gaps still holds. /imagine/design/spacing/decision.md.

- 2026-09-05 (paging-fix-2): a `<select>` in a flex row is a flex item and shrinks below its content, and writing `padding: 0.2em 0.4em` on it removes the end reserve the browser draws its arrow in. Both make a control that was sized to fit clip its own longest value ("Top tabs" reading "Top tab") with nothing in the CSS that looks like a width. The fix is `flex: none` and *no* width, font-size or padding shorthand — let the browser size it.
- 2026-09-05: an icon font's line box is its own `font-size`, not the surrounding prose's, so in an `align-items: flex-start` row an icon beside a line of text sits ~5px above it. `line-height: inherit` on the icon is the fix; a margin nudge is not (it breaks at the next type scale).
