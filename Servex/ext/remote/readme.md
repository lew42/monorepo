# ext/remote — the tunnel MCP the Claude voice app talks to

`RemoteMCP.js` serves `POST /mcp/remote` (reached through `Server/Tunnel.mjs`, bearer token in the path or header). It serves the **whole Servex tool registry** (`servex.mcp`, the same tools every local session has) plus `ask_mastermind` (ask the voice mastermind, or any agent with `to`; it waits a few seconds, then returns a ticket with the status and the mastermind's first sentence) and `voice_hear` (hear an ask's status and answer the moment they change). A mastermind stuck at the spawn gate hands asks to the agent named in `remote.fallback` (a one-line file beside `remote.token`, in `%LOCALAPPDATA%/lew42/servex/`; or `REMOTE_MCP_FALLBACK`). How it works: [doc/remote-tools.md](doc/remote-tools.md), "The bridge". Calls run as caller `voice-app`, which says nothing about who called: a spawn from a tab takes its parent from the tab's `session_id` ([rule](../agents/doc/architecture.md)), and Servex agents have this connector blocked (`disallowedTools` in `Agents.door()`) so they use their own door. The voice-agent directives live only in `RemoteMCP.INSTRUCTIONS`. Test: `node Servex/ext/remote/RemoteMCP.test.mjs`.
