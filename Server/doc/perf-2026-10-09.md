Observed by the owner while dictating: whisper threw an error, the page would not reload, the site "crashes a lot". At the check (16:23) the site answered 200 in 0.27 s, so the stall is intermittent.

Measured, not guessed:
- **41 dev-server node processes** (one per worktree/pool slot) plus ~13 Servex and ~6 front-desk processes; 78 of ours use ~5 GB; free RAM ~7.7 of 32 GB; Chrome has 28-43 processes.
- **The main server (`Server/run.js`) rebuilds "Framework Directories" on 19,697 of 54,330 logged requests** (36%): every `/framework/` page hit re-walks the tree. It is the top CPU node process (~2100 CPU-seconds).
- **`monorepo.out` is 36 MB**: every socket message and RPC is `console.log`ged synchronously.
- **Whisper reloaded its 1.6 GB model on the GPU at 16:23** (14 s). The crash error itself is not in `whisper.jsonl`; the restart reason is unknown.
- Pool churn: worktrees qf-1 and qf-9 started and ended several times within seconds at 16:23, each booting a dev server.

Next steps (cheap first): cache the directory rebuild (only on file change), drop per-message console logging, cap pool dev servers (start on demand), find why whisper restarts (log its exit code in Servex).

## Result (2026-10-10, server-perf task)

1. **Directory rebuild**: already off since 17:45 (`directory-off.md`); with `DIRECTORY_JSON=on` it is not per request but per `rename` event, debounced. Nothing more to do.
2. **Logging**: done. `Socket message` and `RPC:` lines are gone; `SOCKET_LOG=on` brings the message line back. Errors kept. Needs a dev-server restart.
3. **Pool dev servers**: finding only. `Servex/Pool.js` `prepare()` runs `worktree-up.mjs`, which boots a dev server for every slot and requires it to answer ("never answered" is an error), so each qf-N checkout/reset boots one. Starting it on first request means changing Pool semantics (a slot's `booted` guarantee, the baseline in `Pool.js` ~576), which is owned by the Servex agents; not edited here.
4. **Whisper**: both supervisors already log exit code and signal (`Servex/Process.js` `exited()` to `whisper.jsonl`; `Server/plugins/Whisper.js` to the dev server's stdout, i.e. `monorepo.out`). The 16:23 reload with no `whisper.jsonl` line fits a dev server's own whisper (one started without `NO_WHISPER=1`, e.g. by hand) restarting, whose lines go to `monorepo.out`, not `whisper.jsonl`. No restart loop code found; grep `monorepo.out` for `[whisper]` to confirm next time.
