# Role: one Servex role as an object

`Role` is one row of `ROLES` in [Servex/agents/roles.js](/framework/servex/fs/agents/roles.js) (the one source of the rows) as a plain object: name, tier, model, effort, permission mode, readme, skills, id prefix, alias, compact_after, singleton, renew, retired. It uses no node or DOM imports, so Servex and the pages share it.

## On disk
- `Role.js`: the class. `Role.from_rows(ROLES)` builds it in node; `Role.load()` reads `roles.json` in the browser; `Role.agents()` reads Servex's live agent list; `role.instances(agents)` filters the agents in that role; `Role.from_agent_id(roles, id)` guesses an older session's role from its agent id.
- `roles.json`: generated by `node Servex/agents/roles-json.mjs` (`--check` exits 1 when stale). Run it after editing roles.js.
- `RoleView.js`: draws one role, the exact file(s) its system prompt is built from (`RoleView.sources`: `Servex/agents/roles/<readme>.md`, `.claude/skills/<skill>/SKILL.md`, and a path-spawned mastermind's own readme chain + `mastermind.md`, shown as an editor-openable path since they sit outside `public/`), and its live agents; used by [/framework/servex/roles/](/framework/servex/roles/) and by a session's *Models and tokens* tab. Not yet shown: whether those files actually landed in the prompt (`Servex/agents/roles.js`'s `path_check`, logged to `skills.jsonl` outside `public/`) and the literal prompt text — both need a small new read route, proposed at [mastermind-roles-and-settling/report.md](/framework/ai/sessions/2026/10/25/session-e06424f1/mastermind-roles-and-settling/report.md).

## Recording a session's role
`open_task()` (Agents.js) writes `role` into a Servex agent's `assign` line; the SessionStart hook writes `role: "vscode mastermind"` into a VS Code tab's line 1. Older sessions fall back to the live registry, then to the agent id's prefix.
