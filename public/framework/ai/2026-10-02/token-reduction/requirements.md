# Token reduction built into Servex, so it can't be forgotten and can't backfire: requirements

Budget: $10.

The owner, 2026-10-02 (trimmed): "checking usage should be an automatic process, so it's fresh… all the masterminds should be loading usage automatically. Being over should mean they're using lesser models and fewer models, not doing redundant checks… if it used to use a minion to do a review, maybe it just does it itself if it has the files already in memory… any other token-reducing strategies should be built into the system automatically, in a way that doesn't backfire."
#CLAUDE.md now carries the rule ("Usage pace", under Systems that shape every turn). This task makes the code enforce it.

## Build, by node (law 7), in this order (biggest saving first)
1. **Stop paying for finished agents.** The openrouter report found finished agents get woken about every 7 minutes, and every wake is billed. When a task has `landed_at`, Servex stops its minions and reviewers at once, and the heartbeat never wakes an agent that has nothing queued and no open task.
2. **Usage in every mastermind's prompt.** Usage.js keeps `ai/usage.json` fresh (about every 15 min). Servex prepends one line to every mastermind and task-mastermind start and wake: `Usage: 5h 12% · week 35% of 26% elapsed → pace 1.35 (OVER): Sonnet default, fewer agents, self-review`. Minions don't get it.
3. **The model policy at spawn.** When pace > 1, `spawn_agent` turns an `opus` request into `sonnet` unless the call carries `reason: "…"`, and Fable is never spawned. The result says what it did. It never changes an agent that's already running.
4. **Budgets. NOW FIRST** (2026-10-02 late: two Gemini masterminds spent about $17 of OpenRouter money in 20 minutes, reading and never acting; known issue `openrouter-runaway-turn`). Servex reads `Budget: $X` from the brief. At 100% it tells the mastermind once. At 150% it stops spawning new minions for that task and posts one Inbox card (with the cost, what's done, and Continue / Stop).
   - **Per-agent hard cap, checked during the turn: already written by -10** in `Servex/agents/Agents.js` (`meter()`, `cap_usd()`, `over_cap()`, `read_budget()`, after `assistant()`). It is untested and not yet live. Every OpenRouter model call is priced by `/generation` as soon as it settles. Past the cap ($3 for a mastermind, $1 otherwise, or the spawn's `budget_usd`), Servex interrupts and drops one Inbox note. **Your job here:**
     - test it with a fake `generation_cost`: a turn crossing the cap is interrupted once, and the note is posted once;
     - add `budget_usd` to the `spawn_agent` tool schema (`tools.js`);
     - extend the cap to Claude agents, pricing each call's usage with tiers.js prices, since the SDK only reports cost at the turn's end;
     - show "spent / cap" on the agent's row on the Agents page.
   - **Read budget, also written:** an OpenRouter agent's Read, Grep, Glob and page reads before its first write or spawn. It warns at 25 and interrupts at 40. Test both.
   - **Accounting:** run `ai/2026-10-02/servex-mastermind/or-reconcile.mjs` (Servex vs its ledger vs OpenRouter's own `/generation` records, per agent). Then fix what it shows:
     - if the ledger's `key_diff` turns booked another agent's spend, make `key_diff` refuse while two OpenRouter agents are working;
     - if the usage's cache_creation equals cache_read in every call, the proxy maps OpenRouter's cached tokens into both fields, so no token-based cost or context figure may add them both.
5. **Reviews.** When over pace, merge.mjs accepts a review report written by the task's own mastermind for non-page changes (code, docs, hooks). A page or layout change still needs the screenshot review at the four widths. The rule this enforces is in `Server/doc/review.md`, "Who reviews": the mastermind reads the diff first, and a fresh reviewer runs only on doubt or for a page. Give the mastermind's read its own record, replacing today's `--size none --why "mastermind read: …"` stand-in. Also have `merge.mjs` run `review.mjs --turns` before its gate, so `review.jsonl` always holds the answers written in `task.jsonl` (2026-10-02: 30 of 57 `review.jsonl` files held no answers at all).

6. **Revive keeps the provider; finished minions aren't woken.** Evidence: a FINISHED free-model agent (`minion-lib-h1-page`, nvidia/nemotron-3-ultra:free, 2026-10-01) was woken 9 times by heartbeat status checks and revives, and its cost went from $0 to $2.84. The revive seems to drop the OpenRouter `provider` and run it on Claude. Log: `%LOCALAPPDATA%/lew42/servex/logs/agent-minion-lib-h1-page.jsonl`.
7. **Riding along, not a saving:** a correctness bug found while reading this code, fixed here because it's already open. A message to an unstarted, queued agent was routed to its stopped predecessor (`send_to_agent mastermind-servex-10` → "mastermind-servex-9 was not woken"). Queued agents should hold their messages (`held_messages`).

8. **Stopping an agent kills its process, and the reconcile catches one that's left over.** Evidence (vscode-mastermind, 2026-10-02 ~19:50): `minion-panel2` read `stopped` in Servex, but its claude.exe (pid 27100, 351 MB) was still alive and had to be ended by hand. Two things to check in `Servex.reconcile()` (`Servex/Servex.js` ~1103):
   - It only recognises a process whose command line carries `--resume` or `--session-id <uuid>`. Check whether an SDK-spawned claude.exe carries either. If it doesn't, match the process by the agent's recorded `claude_pid` instead.
   - **It revives stopped agents.** A `stopped` row that has a `spec` gets "adopted": the leftover process is killed, then the agent is spawned again on the same session. That breaks the stop_agent promise ("nothing revives it by itself") and pays for a wake nobody asked for. Adopt only `dormant` rows; for a `stopped` row, kill the process and nothing more.
   - Also make `stop_agent` itself confirm the process is gone (kill by `claude_pid`, then check), and log `stopped-stray` when the reconcile has to do it.
   - Test: an agent marked stopped whose process is still alive is killed within one reconcile, and is not respawned.
9. **Reviewers use Sonnet when over pace.** Evidence: `reviewer-card-pipeline-4` ran on claude-opus-5-5 at pace 1.45. `Server/review.mjs` (line 764: `size === "full" ? "claude-opus-5-5" : "claude-sonnet-5"`; reported twice, by vscode-mastermind and task-mastermind-prompt-refine) picks Opus for any `full`-size review and passes it to spawn_agent as an explicit model. Item 3's policy turns that into Sonnet once it's built; also have `review.mjs` choose Sonnet itself when `ai/usage.json` shows pace > 1, unless `--model` is given (that flag is the stated reason). Test: a full-size review at pace 1.45 spawns Sonnet; with `--model claude-opus-5-5`, Opus.

10. **A long-lived assistant's context stays small, measured.** The owner suspects a context full of repeated instructions caused the fast assistant's "go on" loop. The `every-prompt` skill's "re-invoke on EVERY prompt" line is removed (the Servex mastermind's `apply-every-prompt-once.mjs`). mastermind-servex-10 checked the code: Servex does **not** prepend a skill or brief to each message. `roles.opening()` wraps only the first turn, Layers' card assistant gets `page-assistant.md` once as `system` with `setting_sources: []`, and the voice `session-fast` gets `session-fast.md` once as `system` with no skills at all. So in the voice session the loop has another cause. Measure first, then fix:
   - From the agent logs (`%LOCALAPPDATA%/lew42/servex/logs/agent-<id>.jsonl`, or the SDK session file), write a node tool, `Servex/agents/context-size.mjs <id>`, that prints input tokens per turn. Run it on a `session-fast` from a long voice session, and on a VS Code `/every-prompt` tab session if one exists, over 10 messages. Put the before and after table in task.jsonl as an `experiment` line.
   - If a session-fast grows without bound, give it the same rule Layers' `stale()` gives a card assistant: start fresh past about 30k tokens, carrying only the last few lines as `context`. That rule already exists in Layers; reuse it, don't write a second one.

11. **Retire `master-assistant`.** (the owner + vscode-mastermind, 2026-10-02; checked by mastermind-servex-10.) The voice pair is site-wide and page-aware, and `Layers.listen()` sends every owner prompt on a card to it (`card_prompt_session`). But `Global.boot()` still starts `master-assistant` on Opus at every Servex start, and `Global.heard()`, on the same card events, queues every page-less owner prompt to it. So those lines are heard twice, the second time on Opus. Remove:
   - the boot spawn and the `page_less`/`queue`/`flush` feed in `Global.js`;
   - Layers' `ROOT_ASSISTANT`: an agent's message to the page `/` goes to `mastermind-servex`;
   - the direct-child landing/block/error feed: landings already reach their parents by wake, and the owner by cards.
   Keep `master-assistant` in `roles.js` as an alias of `session-smart`, so old callers don't break. Update `global.test.mjs` and `layers.test.mjs`. Test: a page-less owner prompt reaches the voice pair once, and no `master-assistant` is spawned at boot.
12. **Use the one pace reader.** `Servex/Usage.js` `Usage.pick()` already turns pace into a model for the smart assistant. Items 3 and 9 call it (or a `Usage.pace()` split out of it); they don't read `usage.json` a second way.
13. **Over pace, route jobs to OpenRouter** (the owner, 2026-10-02 23:00). The goal is to take load off the Claude windows: the week was at 54% and the 5-hour window at 45%, while OpenRouter had $137 of $150 left. When pace > 1 (item 12's reader), `spawn_agent` picks the model by the job:
   - **Audits, identification scans, prompt refining (the echo):** `google/gemini-3.8-flash` takes most of it. It was closest to the consensus in the audit pilot (distance 0.2; Sonnet 0.6).
   - **Small fenced code tasks with a smoke test:** `deepseek/deepseek-v4-pro` takes most of it, with the no-images rule. It matched Sonnet at about 0.2× the cost in the paired trial.
   - **Visual, multi-file or judgment work:** stays on Sonnet.
   - **It's a trial, not a verdict** (the owner's correction, 2026-10-02). The pilot was one round: 5 tasks, 4 judges. So the route rotates a share of each cheap job (start at about 1 in 4) to the other cheap models, such as DeepSeek, GPT-6 Luna and others. That keeps their scores updating. A model is dropped from the rotation only for a clear, repeated problem (incidents, failed machine checks), never for one low round. The weights and the rotation share come from `ai/2026-10-02/model-weights/` ("No model is written off from one round"), not from a list typed here. Until that lands, the favourite and the rotation list sit in one table in code.
   - **How:** use the existing pieces only. The job comes from the spawn's role, or a `job:` field on `spawn_agent`. The model id goes through the slash rule and the `provider` field (`Agents.js`, `tiers.js`), and cost through `Servex/ext/openrouter/reconcile.mjs`. Every routing decision writes one `{type:"route", job, id, model, pace, why}` line to Servex's system log. An explicit `model` on the spawn always wins.
   - **The spend guard must allow it.** `provider.js` defaults `OR_MONTHLY_USD` to 50, so the guard would refuse the load at about $6 a day. Set it to the owner's $150 (`SERVEX_OR_MONTHLY_USD` through the keeper, or the default in `provider.js`).

Check its `refine_step` output against two Sonnet-era items on the same page before widening it. Then fold `model_for` into this rule. The in-process `clean()`/`structure()` calls stay on Claude until Servex's own env carries the key (Echo.js's HOTFIX note); `askOnce` takes `env`, so `env_for("openrouter")` is the fix.

## Never backfires
- Never stop an agent in the middle of a tool call. Never touch the logging, guard or merge paths. Never downgrade the owner's VS Code session.
- Each rule logs one line to Servex's system log when it fires, so a wrong call is visible and can be reverted.
- Tests for each rule, including "a landed task's agents are stopped" and "Opus with a reason is kept".

## Rules
The #Servex mastermind owns it. A pool worktree, `merge.mjs`, and `sustain.mjs --restart` after landing. Never wait on the owner.

## Spend follows results (the owner, 2026-10-02 late; replaces flat per-agent caps)
"Spending $10 or $20 to figure out if it would work could be useful if it's promising, but blowing $20 without results is not acceptable." Evidence: a Gemini 3.8 Flash mastermind spent $13 in 20 minutes on 134 file reads and produced nothing.
- Each agent starts with **$2 to its first result** (a commit, a step done with its check passing, a page line, a minion brief). Each verified result unlocks **the next $3**, up to the brief's `Budget:` (or $20).
- No result by the gate: Servex interrupts between tool calls and posts one Inbox card (spend, what it read, what it produced; Continue +$5 / Stop).
- 40 reads without a result is a warning line, not a stop. The Sessions grid shows "spend since last result".
