# /framework/: a new home page that shows everything in the framework, with dark class cards: requirements

The owner, 2026-10-02 (dictated, trimmed): "When I go to the framework page, I want to see all the things in the framework. I think we're neglecting our /framework page… move [the current one] to /framework/old, back up the old version… make a new framework default page… sections, like the sidebar sections, Core, and then the icon items… Let's use dark-themed cards for classes from now on… whether it's an inline reference or a card… it differentiates it from a standard content page: it's a class… Each class should have an icon… the navigation icons should render from the page's icon property, so when we edit a page's icon it updates everywhere… I don't mind if this is a big sprawling page… use horizontally friendly layouts… don't limit the width, use all the space, show a grid, but use our responsive padding so the huge space gets enough padding and gap… If they're big cards, in a 1000px container, full-width sections stack into three rows; on a 3000px monitor, three columns of about 1000px each. We could call that verb sprawling… [whether] column heights can be adaptive is a big question."

## Build
1. **Back up:** the current /framework/ page moves to `/framework/old/` (a declared child, so it routes). Nothing is deleted.
2. **The new /framework/ page:** one section per sidebar section (Core, UX, UI, Extensions, Styles, Utilities, Dev server, Servex, Design, Code…), in the sidebar's order, read from the same page tree the sidebar uses (one source; never a hand-typed list). Each section is a grid of icon items, one per module: icon, name, and its one-line description (from the page's own `description`).
3. **Dark class cards:** a module that IS a class (its page documents a class: core/Page, core/Item, core/List, ext/filesystem's FsFile, ext/Inbox…) renders as a DARK-themed card. Plain content pages stay light. Use one CSS word (e.g. `.class-card`, a dark ground on the existing theme tokens) so ext/Mention can use the same look for an inline class reference. Add the inline dark look to ext/Mention for a reference that resolves to a class page.
4. **Icons from one source:** every icon (sidebar, cards, mentions, breadcrumbs) is read from the page's own `icon` property. Find any hard-coded copies and remove them. Check: change one page's icon and every surface updates.
5. **Sprawl:** the page uses the full width with responsive padding and gaps (the site's clamp tokens). Sections use `repeat(auto-fit, minmax(min(100%, 60rem), 1fr))`, so at 1000px they stack, and at 3440px about three sit side by side. Inside a section, the module grid uses `minmax(min(100%, 16rem), 1fr)`. Never a 12-wide row of tiny text. Name the pattern "sprawl" in /framework/design/layout/ in one line.
6. Coordinate with @task-mastermind-panel2-sessions: sprawl and adaptive panel heights belong to Panel 2 later. Use plain grid here; don't wait for it.

## Rules
A Sonnet task mastermind with at most 1 minion. A pool worktree, `merge.mjs`, and the review skill at all four widths (400, 1200, 1920, 3440). Never wait on the owner.
