# reply-in-place — a reply and a microphone on every item of the hierarchy; the reply reaches Claude with that item as its context, and the answer lands live beside it

Load the `minion` skill first. Then this brief.

**Three laws.** Less is more (one button pair, one rpc that exists, one line format that exists). Clear beats brief by far. Prioritize (text reply with context first; the mic second; the immediate minion third).
**Length budget:** a reply control is two small buttons and a box; the answer is a `chat` line under the item. Your landing report is one screen with one round trip proven.
**The reader is the overwhelmed newcomer.** A press does something visible within a second.

## What exists — reuse, do not fork

- `ext/Ask` (`Ask.js`, `chat.js`, `pick.js`, `readme.md`, `doc/`): `ask(prompt, { model, tools, context, shot })` and `chat({ task })` — a turn is a fresh `claude -p --resume` process on the dev server, bound to the tab that asked; **the first message on a `task` forks that task's `session_id` and later ones resume the fork** (`doc/fork.md`); `task` is a path under `public/` and is the fence; the exchange is appended to that task's `task.jsonl` as `chat` lines (`doc/record.md`); `context` already travels; tool scoping is per call and opt-in (`tools`). `Server/plugins/Ask.js` runs the turn.
- The hierarchy on a task page (`ext/AITask`): the Asks tab (`asks.js`: cards with `ask.id`), the Decisions tab (`decisions.js`: rows with `decision.id`), the run's task cards on the day dashboard (`card.js`), `chat` lines rendered by `conversation.js`. Every verb merges by id; appends stream to open tabs over the socket without a reload (`ext/JSONL` `live()`); `rpc:append` is the browser's writer.
- The run task: `/framework/ai/2026-09-17/mastermind-layout-browser/` (session `cfca18c9-a470-4295-a088-a13479fdd040`) — the mastermind's session; a reply on one of its asks forks THAT session, which already knows every ask.

## Deliverables

1. **Reply, in place.** On every ask card, decision row and task card: a small **reply** button that opens a one-line box under the item (Escape closes; nothing else on the page moves). Send → `chat({ task: <that task's path>, context: { kind: "ask"|"decision"|"task", id, summary or about, quote, status, tasks or options } })` through `ext/Ask` — the turn's prompt opens with a plain sentence naming the item ("The owner is replying to ask `even-columns`: <summary>. Their words: …") so nothing has to be re-explained; the reply and the answer land as `chat` lines carrying `about: { kind, id }` in that task's `task.jsonl` (extend the `chat` line by that one optional field; document it), and the item renders its thread under itself, live, newest last. Off the dev server the button is not drawn.
2. **The microphone.** Beside reply, a **mic** button: the browser's `SpeechRecognition` (Chrome, desktop and Android — say so in one line where it is missing) transcribes into the same box, interim results shown, Send as before. The alternative (server-side transcription) goes in `doc/decisions.md` with when it wins (Firefox, iOS Safari, noisy rooms).
3. **The immediate minion.** A reply's turn is a Sonnet by default (`model: "sonnet"`) with tools scoped to that task's dir and `rpc:append` (read `doc/decisions.md` on tool scoping and pass the smallest set that lets it write lines): its instruction is to act on the reply as a minion for that item — answer, and where the reply is a request, write the structured lines (`ask` / `decision` / `log`, merged by id) into the task's `task.jsonl` so they appear on the tab within seconds — and to leave a `log` line "reply handled: <one line>" the mastermind reads at its next wake. Prove one round trip headless with `model: "haiku"`, at most two real turns (each costs money): reply on an ask → the chat line appears under the card → the answer appears → a `log` line lands.
4. **Real-time dictation into asks** (the owner "creating tasks as I speak"): the run task's page gets one **dictate** box at the top of the Asks tab (mic or text) whose turn's instruction is: split this dictation into asks — one `ask` line each with `id`, `summary`, `quote` (verbatim sentence), `topic`, `status: "open"`, `prompt` (the chat line's own id) — and append them; they stream onto the tab as they land. The mastermind harvests `open` asks at its next wake. Prove it once with a two-sentence dictation (haiku).
5. **Docs:** `ext/Ask/readme.md` Use (reply, mic, dictate: three lines), `doc/decisions.md` (the record: which session a reply forks and why, the cost per reply, the transcription alternative, what tools a reply turn gets), `ext/AITask/doc/asks.md` (the reply control, the `about` field), `ext/JSONL/doc/task-jsonl.md` (`chat.about`).
