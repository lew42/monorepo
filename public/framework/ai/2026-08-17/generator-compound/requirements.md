# Does the self-improving loop compound?

This is the heart of Mike's original ask: *"how do we create a self-improving
system, so that when you're done, the generator generates stronger layouts?"*

The loop exists and has been run **once**. `SHAPES` weights in
`styles/layouts/space/model.js` were refit from run 2's lift³. **Nobody has
tested whether a second turn of the crank helps, plateaus, or overfits.**
That is the whole question here, and a plateau is just as publishable as a lift.

## The measurement

**Fitness is worst-width, not mean** — that is deliberate, keep it.

1. **Freeze the taste tier.** Change nothing under `ext/LayoutTool/`. If the
   rulebook moves, every number below is uncomparable and the run is wasted.
   (The last run burned ~1M tokens regenerating baselines because the tier kept
   moving underneath them. Do not repeat it.)
2. **Round 3 baseline.** Run `sweep()` at the *current* committed weights, same
   n and same seed range as round 2 so it is a like-for-like comparison. Record
   mean fitness, ceiling, and the worst-width distribution.
3. **Credit and refit.** `credit()` → `proposal()` → apply the proposed weights
   to `model.js`.
4. **Round 4.** Re-sweep with the refit weights, same n, same seeds.
5. **Answer the question with a number:** did mean fitness rise, flatten, or
   fall from round 3 → round 4, and by how much? Report the delta on **mean**,
   on **ceiling**, and on the **10th percentile** (the floor matters more than
   the ceiling for a generator Mike will actually click).

## The trap to watch for

**Overfitting to the seed range.** If round 4 improves on the seeds it was
fitted from but not on fresh ones, the loop is memorising, not learning. So
also sweep a **held-out seed range never used for fitting** and report both
numbers. If held-out fitness does not improve, say so plainly — *that is the
finding*, and it means the loop needs a different signal, not more turns.

## Deliverables, in this order

1. **The numbers as `log` lines in your own `task.jsonl`.** Not a `findings.md`
   — the harness blocks subagents writing report files, and RULE#15 wants them
   in the log anyway.
2. **`model.js` left at whichever weights actually measured best** — round 3's or
   round 4's. If round 4 is worse, revert and log that you did.
3. A short **Decisions** entry in `space/readme.md`: does the loop compound,
   yes/no, with the deltas.

If you run short of time, cut the held-out sweep **last** — it is the most
valuable single number here. Cut the readme entry first.

## Working notes

- **Foreground is the default.** A two-minute blocking command is normal. If you
  do background something, poll it — don't wait on it:
  `while (-not (Test-Path out.json)) { Start-Sleep 15 }`
- Headless browser: recycle the context every ~40 navigations; the renderer
  wedges after ~85–110 in one context. Never wait for `networkidle` — the
  live-reload socket never idles. Scope selectors to `.active-page`.
- Hidden tabs run no rAF and no ResizeObserver, so a hidden tab measures
  garbage. Keep the page visible.
- Check usage before wide work.
