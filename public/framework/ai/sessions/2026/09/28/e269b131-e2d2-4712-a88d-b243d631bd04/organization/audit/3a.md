# 3a — core/Page docs + the page skill, as a new user

Screenshot: [3a-page-1920.png](./3a-page-1920.png) — `/framework/core/Page/` at 1920, Overview tab.
Source: [`page.js`](/framework/core/Page/page.js), [`readme.md`](/framework/core/Page/readme.md), `doc/*.md`, `overview/*/page.js`, `.claude/skills/page/SKILL.md`.

## Findings

- **buried** — Top tabs are OVERVIEW, GENERATOR, **OLD**, PAGE.JSONL, API, DOCS, FILES. `OLD` (the pre-Overview docs, kept "as reference") sits second-to-third, between two live tabs a new reader needs. It should move to the end, or off the top tabs entirely (a line in DOCS instead). [/framework/core/Page/old/](/framework/core/Page/old/)
- **wrong** — Left-nav order under **Page** (Generator, Old, page.jsonl, Overview, API, Docs, Files) does not match the top-tab order (Overview, Generator, Old, page.jsonl, API, Docs, Files). A reader who clicks a left-nav item and looks up expects the same order.
- **missing** — The Overview wall's `Building blocks` band starts with `columns`, and `columns()` is the single biggest layout decision on any page (ask 10 names three layout tiers). But nothing on the Overview page itself says "start here" — the readme says it ("start with navigation or layout"), the page doesn't. A first-time visitor lands on 29 cards with no reading order.
- **buried** — `doc/layout.md` is an **admittedly unsolved problem** ("We need a strong, simple strategy... and we do not have one yet" — 2026-08-17) but is reachable from `doc/layout-overview.md`'s "Nested or full" bullet with no warning it's open. A reader can walk into an unfinished note believing it's settled guidance.
- **unlinked** — `doc/columns.md` (the real API for `columns()`, ask 10's "layout 3: fill") is linked from the readme's "Read next" list and from the columns overview card, but not from `doc/layout.md`/`layout-overview.md`'s five-idea list in a way that says it's the fill-layout doc — a reader hunting for "three or more columns" has to already know the word `columns`.
- **verbose** — `readme.md`'s "Read next" list is nine links with no grouping (navigation, layout, jsonl, markdown, api, watch-out, more-features, decisions/findings, files) — flat, no priority signal about which three matter to a first-time reader.
- **wrong** — The page skill (`ux/Content` structured-content table, added 2026-09-28) is not referenced anywhere in `core/Page/readme.md` or the Overview page, even though it is now the rule for how any Page's content should be built. A reader following core/Page docs won't discover it.

## Simplest first

- **Building a page.js** — `readme.md`'s own example is already minimal and correct, and should stay the very first thing on `core/Page/` (it's currently second, after the Overview wall's own copy of the same two snippets — redundant but not wrong; keep the readme's copy as canonical, let the Overview page just link to it instead of repeating the code).
- **columns()** — `overview/columns/page.js`'s `finder()` demo *is* the simplest working example (one tree, one `site.columns()` call, `width:` words explained inline per node) and it already runs first in its own card. Good — no change needed there.
- **tabs()** — `overview/tabs/page.js`'s `guide()` is three lines of children plus `content(){ this.tabs(); }` — already the simplest possible shape, already first. Good.
- **Overview wall itself** — should open with one sentence ("Start here: build a page.js, or browse a shape below") before the 29-card wall, not the wall cold.

## Suggested structure

Keep the seven top tabs but reorder and reweight:

1. **Overview** (unchanged: the palette wall) — add one opening sentence naming Generator, jsonl and API as the three places to go next.
2. **Generator** — unchanged, it's the "try it without files" tool, earns its place near the top.
3. **API** — move up, ahead of `page.jsonl` and `Old`: it's the reference a working reader returns to most.
4. **page.jsonl** — keep, but rename the tab label to **JSONL** (matches the module's own `doc/jsonl.md` heading) since `page.jsonl` reads as a filename, not a concept.
5. **Docs** — unchanged (the doc/ folder, prose detail).
6. **Files** — unchanged (raw source list).
7. **Old** — moved to last. It is reference-only by the readme's own words; last position matches that.

Left-nav under Page should mirror this order exactly.

**Concept pages that deserve one** (named, linked wherever mentioned): `columns()` / Miller columns, `width:` (small/nothing/large/full), `page.jsonl` as a route, the page grid (main/wide/bleed tracks). **Too trivial for their own page:** `tabs()`, `vtabs()`, `list()` — each is a one-line opt-in already shown fully on its own Overview card; a prose page under them would just repeat the card.

## Value per space

1. `readme.md`'s page.js/page.jsonl pair — fundamental, trivially shown, already first. Keep.
2. `overview/columns/` finder demo — fundamental (layout 3 in the owner's vocabulary), clearly shown, already good.
3. `overview/tabs/` and `overview/page/` (Hello) — smallest possible working examples, good anchors for "what is a page."
4. `doc/navigation.md` — short, links out well, is the right size for what it covers.
5. `doc/api.md` — fundamental (every method), easy to show (it's just a list), but needs the reorder above to sit second not fourth in top tabs.
6. `width:` word (small/nothing/large/full) — fundamental to every column layout, shown inline in the columns demo; deserves a one-line concept page since it's referenced everywhere.
7. `page.jsonl` route — fundamental (ask 9 names it explicitly) but currently only a two-line example in the readme; needs its own worked example (see 3b for the loader mechanics).
8. Page skill's structured-content table (icon card / section / outline) — very fundamental going forward (ask 6, 7) but **not yet linked from core/Page at all** — confusing by omission, not by being hard to show. Fix is cheap: one link.
9. `doc/layout.md` ("Nested or full") — confusing and admittedly unsolved; low value per space until the owner resolves it. Mark it "open question" inline rather than removing it.
10. The `Old` tab's full page tree — genuinely hard to show any value from (it's superseded); earns the least space of anything at top-tab level. Demote, don't delete.
