The pad token:

1. **Does a percentage pad resolve against the parent?** Not exactly: it resolves against the element's *containing block* (CSS 2.1 §8.4, css-box-4). In normal block flow and in flexbox, that is the parent's content box. In a grid, it is the item's own grid area (css-grid-1 §9). In a test, `padding-left: 10%` gave 120 px on a 400 px block inside a 1200 px parent, 120 px on a flex item that was one of three in a 1200 px row, but **40 px** on a grid item in one 400 px track. So your suspicion is right for flex and block, and wrong for grid.
2. **Where it's written doesn't change that.** `--pad` is an unregistered custom property on `:where(*)`, so the `%` is pasted into `padding` and resolved on whichever element uses it. The bigger problem is `2.6% - 1.1em`: it stays on its 1em floor until the containing block is wider than about 80em (~1292 px). So every card gets a flat 1em whatever its width. `--pad` is a word for page regions. `--pad-card` (`clamp(1rem, 2.6%, 2em)`, framework.css:303) already exists for cards.
3. **Can `cqi` on an element resolve against itself?** No. css-contain-3 says a container unit uses the nearest *ancestor* query container, and falls back to the small viewport if there is none. An element that sets `container-type: inline-size` cannot read its own width that way. Measured: `10cqi` on a 400 px container gave 120 px (from its 1200 px ancestor), or 140 px (from the 1400 px viewport) when there was no ancestor container. On its **child** it gave 40 px. A card-level `@container` query has the same limit: it reads the card's parent.
4. **The smallest correct design, with no extra markup: make the side padding grid tracks.** `.card { display: grid; grid-template-columns: var(--p) minmax(0, 1fr) var(--p); padding-block: var(--pad-card) } .card > * { grid-column: 2 }` with `--p: clamp(1rem, 4%, 2em)`. A percentage in a grid track resolves against the card's **own** width (measured: 10% of a 400 px card = 40 px). `.page` already works this way with its `main`/`wide` tracks. The one catch: the card becomes a grid, so a card that was a flex row needs checking.
5. **The other option: an inner wrapper.** Make the card the container (`container-type: inline-size`) and pad its one inner wrapper with `cqi`. That is exact too, but every card's JS needs the extra element. For Dictate today, rows 1–4 above are the fix. The pad token isn't what's wrong on this page.
