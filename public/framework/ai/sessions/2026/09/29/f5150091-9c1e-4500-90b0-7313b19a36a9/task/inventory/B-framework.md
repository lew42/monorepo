## Biggest finds

1. **A "core/Page/layout" directory already exists and already does most of what the owner described today** (standard/split/columns/floating, proven layout choices) — before building a new layout system, read `/framework/core/Page/layout/` and decide reuse vs. replace.
2. **The class-doc top-tabs pattern the owner name-checked today ("works pretty well… go-to until we get a better one") is `ext/Doc`**, not a separate nav component — it's a Page whose own children form the left-rail tab set. This is the concrete precedent to write into the new `core/Page/navigation` page.
3. **`ext/Playground`, named in this brief and in old memory notes, does not exist on disk anymore** — only its task-history screenshots survive under `ai/2026-08-19/`. Anything referencing it as current is stale; `ext/DesignTool` is the tool that actually ships today.
4. **Three different things are all named "layout"** — `core/Layout` (named-arrangement registry), `core/Page/layout` (per-page layout choice), and `ext/layout` (a live-tweak toolbar for demo pages) — plus `/layouts/` (the top-level encyclopedia). The new README needs to disambiguate these by name, or the confusion will compound.
5. **`imagine/paging` is the most complete existing prototype of "persistent nav vs. switching content"** (a rail that never moves + a middle that swaps, config in the url) — it's the closest thing to an answer to the owner's "biggest question with navigation" and should be the first stop before designing anything new.
