2. [fix] **The pattern is below the fold.** At 1920 the first demo starts at y≈600, under a title, a "Folder" row, two paragraphs and a heading, and at 400 it starts at y≈620. The rule "show, don't tell; level 1 above the fold" applies. Fix in `switcher/page.js:28-33`: put the wide/narrow pair directly under the title and cut both intro paragraphs to a single line.
3. [fix] **Every panel repeats page chrome.** Each stand-in child draws its own `h1.page-title` plus a "folder_open Folder" meta row, so every panel reads "index.js / Folder / sentence". That is not what "the full screen … to browse the actual code itself" looks like. Fix: render the children without the title and meta row inside a switcher (a `.switcher .tab-panel` rule, or a flag on the child), so the content area holds only the content.
4. [fix] **The sticky header is not shown working.** The owner asked for a "sticky header on top of the code". Every demo panel is three lines tall, so nothing scrolls under the header, and the stickiness is never seen. Fix: give the narrow frame's panel something long (a real source file, see 1), and add one shot scrolled halfway through it with the header still pinned.
5. [note] **The switcher CSS copies the logic that decides which item is current.** `switcher.css:111-121` repeats `tabs.css`'s `:has(.active, .in-path…)` / `:first-child` fallback so it can hide every tab except the current one. That is reading the active classes, not patching them. But it is a copy, and if `ext/tabs` changes its default-tab rule the two will drift apart. That is the owner's unease in a milder form. Better: have `ext/tabs` stamp the one class it already computes (for example `.tab-current`) and let switcher.css read that.
6. [note] **The demo page needs ten filler pages.** It needs three "index.js" pages and three "app.js" pages (`cmp-w-*`, `narrow-*`, `wide-*`) because `this.default_tab` holds only one value per page (see the comment in `switcher.css:100-106`). As a result, clicking in any switcher changes the url for the whole page, and the other switchers fall back to their first tab. This is fine for a demo, but it is the first thing the real `/fs` instance will run into. Name it in `doc/decide.md` as a known limit.
7. [note] **A core module now depends on an ext module.** `core/Page/layout/switcher/switcher.js:2` imports `/framework/ext/tabs/tabs.js` and patches `Page.prototype`. The CLAUDE.md rule is "imports flow down", so core depending on ext runs the wrong way. Either keep the demo under core and move `switcher()` into `ext/tabs` (as `tabs().ac("switcher")`), or say in the readme why core may import it.
