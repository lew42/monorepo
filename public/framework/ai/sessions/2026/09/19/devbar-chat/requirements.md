## Build

1. **A `chat` tab, first in `tabs`, and the default** (a stored `settings.tab` still wins, so say in the doc how the owner gets back to it). It shows the **live conversation of the current mastermind session**: which session = the `session_id` of the newest run task (`group: "ai-ops"`, or slug starting `mastermind-`; find how `ext/AITask/dashboard.js` enumerates tasks) — fall back to the most recently modified transcript. The owner's messages and the assistant's text as a chat, newest at the bottom, tailing live, sticking to the bottom unless the owner has scrolled up; mid-turn messages shown as the owner's too. The dev bar is a short, wide strip: make the chat usable in it (the bar's own height grip exists — check `width.js` / the grip; a roomy mode if the bar is tall), and keep the text at the site's reading size — no 11 px chat.
2. **Every past session.** Extend `AILogs.js` with `GET /ai-logs/` → a JSON index: for each transcript `{id, started, modified, bytes, first_prompt (first 160 chars of the first real user message), prompts (count of user messages), subagents (count)}`, newest first, loopback only like its sibling. Cache by mtime+size — 1.1 GB must not be re-read on every request (read each file once, streaming, and keep the summary in a small JSON cache under the OS temp dir, never in the repo). The tab gets a session picker (the existing `ext/Dropdown`, or a plain list in a side column if the bar is wide): pick one, read it as a chat. A filter box over the owner's prompts across ALL sessions ("where did I say…") is the stretch goal: `GET /ai-logs/search?q=` streaming matches `{id, at, text}`; build it only if the index landed clean.
3. **The minions of a session.** `GET /ai-logs/<uuid>/subagents/` → `[{file, started, bytes, first_prompt, last_text}]`, and `GET /ai-logs/<uuid>/subagents/<file>` → that transcript (same Range support, same loopback guard, the file name validated against a strict pattern — no path traversal). In the tab: under a session, its minions as a list (what it was told, in one line; what it reported, in one line); open one to read it as a chat — brief in, report out. Read-only, and the tab says so in one plain sentence: the owner cannot type to a minion from here; the mastermind relays.
4. **Sending — the owner talks to the mastermind from the dev bar.** A composer under the live chat, with the `ux/Dictate` mic: on send it APPENDS one line to the run task's `task.jsonl` through the existing append RPC (find it: `Server/plugins/SocketServer/Append.js`, and how `ext/Ask/reply.js` files a `chat` line) — `{"chat": {"at": "…", "from": "owner", "via": "devbar", "msg": "…"}}` — and shows it in the chat at once as "sent to the mastermind's inbox". It does NOT start a headless turn (forking the mastermind's session fails with "Prompt is too long" — measured 2026-09-18). The mastermind reads new `from: owner` chat lines each cycle; say so under the box ("read at the mastermind's next cycle, usually within a few minutes").
5. **Off localhost there is no bridge:** the tab is not drawn at all (the way `ask.js` says "localhost only").

⚠ The owner's live server on port 80 runs the OLD `Server/` code until they restart it (they have been asked to, once). So the tab must degrade plainly when `/ai-logs/` (the index) answers 404 or HTML: the live chat of the current session still works through the existing `/ai-logs/<uuid>` route, and the picker says "restart the dev server once to list past sessions".
