# page-health — an "is it working" watcher: after every change, the pages that changed are loaded in a hidden browser, and whoever made the edit hears about an error at once

Load the `minion` skill first. Then this brief. Model: Sonnet.

**Three laws.** Less is more (a small script, not an agent — a watcher must cost no tokens while nothing is wrong). Clear beats brief by far. Prioritize (errors reaching the editing agent first; the log and its archive second; the dev bar readout last).

## Build — the watcher

1. **`Server/health.mjs` — a standalone script** (`node Server/health.mjs`), not a server plugin: it must not be able to slow or crash the dev server, and it should run beside ANY server. It needs Playwright (global install: `import { chromium } from "file:///C:/Users/mike/AppData/Roaming/npm/node_modules/playwright/index.mjs"` — resolve it from `npm root -g` at start rather than hard-coding the user folder; if it is missing, say so in one line and exit 0).
   - It watches `public/` the same way the server does (reuse `Server/MtimeFilter.js` — reads must not trigger it), debounces ~1.5 s, and maps each changed file to **the pages to check**: a changed `…/page.js` → its own url; any other file under a page's dir → that page; a shared module (`framework/core/**`, `framework.css`, `app.js`, `ui/**`, `ux/**`, `ext/**`) → a fixed **canary set** (`/`, `/framework/`, `/framework/ai/`, `/framework/ai/v/3/`, `/framework/core/Page/`, plus the page of the module itself). At most 8 pages per batch; one headless browser kept open, a fresh context per batch.
   - It loads them against a server it names by env (`HEALTH_BASE`, default `http://localhost:8123` — the mastermind's; never the owner's port 80: it would show up in their server log and count as load), socket blocked, 1280×900, waits for network idle plus 1 s, and collects: uncaught page errors, `console.error`, failed requests and 4xx/5xx (ignore the known-by-design ones — list them in one array with the reason: `/layouts/verdicts.jsonl` 404, sandbox dirs), and "the page drew nothing" (the `.page` box is missing or under 50 px tall). `console.warn` is recorded as a warning, never an error.
   - It respects the reload hold if `.reload-hold.json` exists at the repo root (a sibling is building that today — check the file's presence and an `until` stamp only; while held, queue, and check once on release: half a batch of writes is not a broken page).
2. **The log** — `public/framework/ai/health/<YYYY-MM-DD>.jsonl`, one line per finding: `{"error"|"warning": {at, url, kind, text (first 300 chars), file (the changed file that triggered the check), files}}`, and one `{"ok": {at, url}}` when a page that was failing passes again. Identical findings within a batch collapse. **Archiving, the owner's bloat worry:** a new file each day; at start, files older than 7 days are gzipped into `health/archive/` and older than 30 deleted; a day file that passes 2 MB stops recording warnings (errors only) and says so once.
3. **The feedback reaches whoever made the edit — through the hook that already talks to them.** `.claude/hooks/syntax-guard.mjs` (read it; it is 30 lines, called from `ledger.mjs`'s PostToolUse inside a try) tells an agent at once when its `.js` write does not parse. Add a sibling, `.claude/hooks/health-guard.mjs`, called the same way: on any Edit/Write, read the tail of today's health file and, if there is an `error` newer than this agent's PREVIOUS write whose `file`/`files` includes a file this agent wrote (keep a tiny per-agent list in the OS temp dir, keyed by `agent_id` or `session_id`), print the same `{"decision": "block", "reason": …}` JSON: the url, the error text, "you broke this page N seconds ago — fix it before anything else". Each finding is reported to an agent once. It must never throw and never take more than ~50 ms (tail-read the last 64 KB; no Playwright here). ⚠ You may create `health-guard.mjs` and add the ONE import-in-a-try line to `ledger.mjs` beside the syntax guard's — nothing else in `.claude/hooks/`; `node --check` both and run the mastermind's test pattern (spawn `ledger.mjs post-tool-use` with a JSON stdin) before you leave it.
4. **The mastermind and the owner see it too:** a tiny page `/framework/ai/health/` (today's findings, live through `ext/JSONL`'s `live()`, errors first, each with its url as a link and the file that caused it; an all-clear state that says when the last check ran), and ONE line for the dev bar — do not touch `dev/DevBar/**` (two siblings are in it): write the line's module as `public/framework/ai/health/devbar.js` and leave the one wiring line in your landing report for the mastermind.
5. **Starting it:** the mastermind runs it as a background process beside its own server. Say the command; make a second copy refuse to start (a pid/lock file in the OS temp dir). Do not wire it into `Server/run.js`.
