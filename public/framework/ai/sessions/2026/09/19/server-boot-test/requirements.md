# server-boot-test — the supervisor tries a changed server on a spare port before it touches the live one, and can never wedge

Load the `minion` skill first. Then this brief. Model: Sonnet. Small and sharp: one file of code, two of docs.

**Three laws.** Less is more. Clear beats brief by far. Prioritize (a live server must never go down because of a `Server/` edit — everything else is second).

## Why — read the incident first

`/framework/ai/2026-09-19/incident-site-down/` (its `task.jsonl` has the four `decision` lines): the owner's live site was down four minutes today. A `Server/` file that PARSED but threw at boot was saved into the shared tree; the supervisor (`server.js`, written today by `ai/2026-09-19/server-self/`) killed the healthy child and started the broken one; then, when the fix was saved, `restart()` waited for an `exit` from a child that was already dead, and wedged for ever. Parsing is checked three times in this repo; **booting is checked nowhere**. The mastermind hand-patched the wedge (`server.js`: "Dead already: just spawn"); you build the real thing. **The proof list below is a floor, not a ceiling** — the incident happened because a supervisor was proven on exactly its three listed cases and never on the broken state it exists to recover from. Think of the states yourself; test the ugly ones.

## Build — in `server.js` only

1. **Boot-test before swap.** On a real change under `Server/` or to `server.js`: after `node --check`, fork a CANDIDATE child on a spare port (ask the OS for a free one; env `PORT=<spare>`, plus a flag such as `BOOT_TEST=1` that every side-effecting plugin must honour — read `Server/run.js` and the plugins: the candidate must NOT spawn whisper (`Server/plugins/Whisper.js` already skips non-owner ports — confirm), must NOT rebuild/write `directory.json` files, must not take the reload-hold lock; if a plugin needs one guarding line to honour `BOOT_TEST`, that line is inside your fence). Wait for a real HTTP 200 from the candidate's `/` (deadline ~8 s). **Pass:** kill the candidate, then restart the live child as today. **Fail** (exit, throw, timeout, non-200): kill the candidate, **leave the healthy live child running untouched**, print a plain block with the candidate's last stderr lines, and write `.server-boot-failed.json` at the repo root (`{at, files, error}`; git-ignored; deleted on the next pass) so agents and the owner's tools can see it. The next change tries again.
2. **Never wedge.** No state may wait for ever: every wait on a child's `exit` has a deadline (then `kill` harder — on Windows `child.kill()` then `taskkill /pid <pid> /T /F` as the last resort — and move on); `restarting` cannot stay true past it; if there is no live child and no boot in progress for more than a few seconds, the supervisor boots one. A change that arrives mid-boot-test cancels and restarts the test (debounced) rather than queueing behind it.
3. **Cold start** (the owner runs `node server.js` by hand): if the tree does not boot, the supervisor must not exit and must not spin — it prints the error once, stays up, and boots the server the moment a change makes it bootable. (Today a cold start into a broken tree gives the owner a dead terminal and a down site.)
4. `NO_SUPERVISE=1` still runs the server bare. Every env var still passes through. Ctrl+C still stops everything, candidate included — no orphan `node` processes, ever: count them in your proofs.

## Prove — on `PORT=8143 node server.js`, with SCRATCH breakage only

Never break a real `Server/` file to test: the mastermind's 8123 and the owner's port 80 follow this tree. Instead give the supervisor a test-only env var that names an EXTRA watched dir and an extra module the child imports at boot (a scratch folder under your task dir), and break THAT: (a) a module that throws at import → the live child keeps answering 200 throughout (poll it every 200 ms across the whole episode: zero failures), the failure file appears, the block is printed; (b) fix it → boot test passes, one clean swap, the failure file is gone; (c) a module that hangs at boot (never listens) → deadline, live child untouched; (d) kill the live child by its real PID while idle → the supervisor brings one back by itself; (e) kill the live child, THEN save a change (the incident's exact state) → a server comes back; (f) three saves 100 ms apart → one boot test, one swap; (g) cold start into a broken scratch module → supervisor stays up, then boots when fixed; (h) Ctrl+C / SIGINT mid-boot-test → zero `node` processes of yours left (list PIDs before and after). Log each as pass/fail with the measured downtime in ms (it should be the swap only, ~1–2 s, and zero for every failed candidate).

Never `git stash`, never `find /`, never commit. Write files with the Write or Edit tool, never a bash heredoc. Do not write the owner's name anywhere.
