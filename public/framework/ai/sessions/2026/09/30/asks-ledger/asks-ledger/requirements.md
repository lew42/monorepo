# Asks ledger: stall detection and the view

Budget: $20

The owner (2026-09-30, `.claude/prompts/2026-09-30.jsonl` lines 357, 359, 405): "a lot of tasks are getting kind of left in limbo." Every ask the owner makes is routed to an agent; when that agent stops, goes quiet or dies, nobody notices and the ask is lost. The ledger already exists: `public/framework/ai/asks.jsonl`, one `{"ask":{at, title, words, owner, card, status}}` line per routed ask, written by the owner's VS Code tab (servex-mastermind-opus) at the moment it routes. `words` points at the verbatim file. Statuses: routed → building → landed | stalled | dropped.

## Deliverables

1. **`Servex/asks/Asks.js`** — the ledger's reader and writer, mounted from `Servex.js` in one line (`this.asks = new Asks({servex})`). Append-only: an update is a new line that names the ask (the pair `at` + `title` is its id; pick a shorter stable id if you must, but the tab's existing lines stay readable). `Asks.mark(id, status, why, by)` appends; `Asks.read()` folds latest-status-wins. A CLI, `node Servex/asks/mark.mjs <id> <status> "<why>"`, so a landing agent can mark its ask by hand, and the `finish-task` skill gets one line telling it to (send me the line; I apply skill edits).
2. **Stall detection, one pure function** `stalled(ask, owner_row, now)` with the rule written in its comment: an ask that is not landed/dropped is STALLED when its owner agent is `stopped` or `gone`, or `dormant` with nothing queued to wake it, or has been silent (no turn, no task.jsonl line) for more than 2 hours. Servex ticks it every 60 s from Asks.js's own `setInterval` (NOT `Servex/Heartbeat.js`; task-mastermind-dormant-idle owns that file today). Marking stalled appends a line once (not every tick); an owner that speaks again clears it back to building. `close_task` / a task landing by the owner agent marks the ask landed automatically.
3. **The view.** (a) A STALLED ask surfaces in AI 2's **Needs you** as a row in the same rail/row style the Inbox uses (the owner: "Needs you should look like the Inbox"): title, owner id, how long silent, links to the card and the words. (b) **Every Needs you and Inbox item gets an IMPORTANCE score 1–100, and the list is ranked by it** — one function in `public/framework/ai2/needs-rule.js`, tunable: a blocker (a key, money, something destructive) 90+; an owner question blocking a running task 70+; a stalled ask 60–80 by how long and how much it cost; a decision the system already made 20–40; an FYI under 20. Show the number on the row. (c) The ledger's own page at `/framework/ai/asks/` (`public/framework/ai/asks/page.js`, listed in the ai index's `children:`): a wall of asks grouped by status, newest first, each row linking card and words. Route everything: a click reaches a URL.
4. **Proof** (`proof.md` here): spawn a throwaway minion, append a fake ask owned by it, stop the minion, wait one tick, show the stalled line in asks.jsonl, a headless shot (`mcp__site__shot`, never an owner tab) of Needs you with the row and its score, and the ranked list before/after. Then mark the fake ask dropped.
5. One line to mastermind-servex-9 when merged, with the commit id and whether the change needs a Servex restart (Asks.js does; the ai2 files do not). Do not restart Servex yourself.
