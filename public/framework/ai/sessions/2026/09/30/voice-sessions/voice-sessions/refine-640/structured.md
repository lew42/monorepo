- Any path, any page, could and should have a default mastermind based on the README. [S3]
- Starting a fresh mastermind in any directory should automatically load things top-down, the way any Claude session already auto-loads Claude.md and all the Claude skills — this may need to generalize if you use Open Router or your own harness, since it will have to adapt to be cross-compatible. [S4, S5, S6, S7]
- As you page around during a voice session, jumping from thing to thing, the assistants see which page you're on from navigation updates and should automatically have contextual awareness of what you're talking about. [S8, S9]
- When you ask a question about that thing, the assistants shouldn't dig into the details themselves — that's really spawning a fresh mastermind, fresh context, based on the path alone (the whole README chain). [S10, S11]
- Keep the config/dependency loading to a minimum so the system works no matter the model or provider (Claude, OpenAI, whatever) — build the entire system around the README. [S12]
- A mastermind started in a specific directory has one basic operating principle: load the README, all parent readmes, system prompts, probably some skills, and all tools and MCPs. [S13, S14, S15, S16, S17, S18]
- The gist of the new prompt is baked from all that: "you're a mastermind working in this directory." [S19]
- That mastermind can spawn minions to build things and test fixes, might use a quick fix worktree, and is the technical part — all questions about the technicality get routed there. [S20, S21, S22]
- The smart assistant makes all executive decisions and pulls all triggers; the fast assistant probably doesn't interact much with the mastermind. [S23, S24]
- The fast assistant is literally just doing a quick transcribe — getting the text on screen as fast as possible — and updating UIs or writing a minimal amount of things. [S25, S26]
- Keep a quick model just for instant feedback, to see the results of your words as fast as possible; the roles need to be made explicit, and maybe the two assistants merge in the future. [S27, S28, S29, S30]
- For per-page AI sessions: the per-page mastermind becomes the per-directory README system, so you always assume you're starting fresh — assume everything is in the README's updates, or that the README points to a log if there's a more detailed ongoing process you don't want cluttering the README. [S31, S32]
- Every new mastermind, on a per-directory/per-page basis, should start with a fresh slate, so the README and all referenced documentation must always be kept up to date. [S33, S34, S35, S36, S37]
- For parallel work spawning a worktree, assume that worktree is in a stable state: use the worktree to build the thing first, then update all the documentation, and spawn a fresh mastermind just to load it all up and do a smoke test. [S38, S39, S40]
- The review process should happen after the documentation is updated, so that when you load it all up and ask it to review the README system and everything inside it, it can pull the most current information and do a smoke test for anything unclear or missing. [S41]
