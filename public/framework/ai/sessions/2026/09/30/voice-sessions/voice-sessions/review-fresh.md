# Voice sessions: a fresh review

verdict: fix. Four real bugs, two stale leftovers from the first review, and one big gap: the ✦ button the owner actually presses is still not wired to any of this.

1. **[fix] ask_directory crashes under load and leaks a claude process.** `Servex/agents/directory.js:165` spawns without `urgent` and without a parent, so Servex's gate (`Servex.js` `admission()`, `Global.js:268`: under 4 GB free memory, or 30 live agents) can hold it and return a stand-in. The stand-in has no `emit`, so `directory.js:145` throws `Cannot read properties of undefined (reading 'bind')`. Failure: on a busy afternoon the smart assistant's question errors out, and later the queue drains and starts a directory mastermind that has no question, no parent and no idle timer, so it sits there using memory. Fix: pass `urgent: true`, or wait for the gate's `admitted` event when `agent.queued` is set.

2. **[fix] The idle sweep can kill the smart assistant mid-turn, so the owner gets no reply.** `Servex/agents/Sessions.js:396` stops a pair after 5 minutes without a line in the session file. It never checks whether an agent is `working`, although `room()` at line 385 does. Failure: the owner dictates a long thought, the smart assistant runs `refine.mjs`, reads task logs and spawns a mastermind (the new brief asks it to do all of this), 5 minutes pass, and it is stopped. `heard()` ignores stopped results, so no reply and no error line are written. Fix: skip a pair that has an agent that is `working`.

3. **[fix] A follow-up question after a pause goes to a fresh mastermind that has forgotten everything.** `directory.js:124` reuses an agent only while it is live. After the 10-minute idle stop or a Servex restart, the next question spawns a new agent, even though `directory-sessions.json` saved the old `session_id`. Failure: the owner asks a follow-up 15 minutes later, and the answer starts from nothing. The owner said at 6:55 PM that a follow-up must not start from a fresh mastermind. Fix: when the saved row exists but the agent is not live, reopen it with `host.wake(row.agent)`.

4. **[fix] Every session made before this change is missing from Recent sessions, and "resume within the hour" stops working for them.** `Sessions.js:213` now finds sessions only through `<dir>/ai/log.jsonl`. The live `sessions.json` holds 11 sessions (`v-d2pkfij` and `v-qj7yrho` on /framework/ext/Session/, and eight phone sessions on /framework/). Their pointers are in `page.jsonl`, and no `log.jsonl` exists for them. This is the first review's item 2, and it is still not fixed. Fix: backfill `log.jsonl` once from `sessions.json`, or keep the old `home`/`visited` filter as a fallback.

5. **[fix] The `session_summary` tool still gives the wrong instructions.** `Servex/agents/tools.js:58` says "Call it after your first reply" and says it writes a pointer into `page.jsonl`. The brief (`session-smart.md` step 3) says to call it before the first reply, and the code now writes to `ai/log.jsonl`. This is the first review's item 1, still not fixed.

6. **[fix] `dir_log` refuses every folder outside `public/`.** `Sessions.js:157` makes every folder a site path. `Servex/agents` becomes `/Servex/agents/`, which does not exist under `public/`, so the call throws. Failure: most of what these voice sessions decide is about Servex itself, and the brief says to log it "in the folder the work is ABOUT". That call fails, and the decision is lost when the pair idles out. Fix: accept repo folders, or tell the brief to log Servex decisions in the task folder instead.

7. **[fix] Gap against the owner's words: the ✦ button still does not resume.** Nothing outside `ext/Session/` calls `start()`, `recent()` or `/api/session/*`, in this worktree or on `michael/dev`. The owner's 7:55 PM complaint was about the mobile rail's AI button: "the last session doesn't resume". Resume-within-an-hour and the titled "1 day ago" list exist only on the /framework/ext/Session/ demo page. Also, no page's AI tab reads `ai/log.jsonl`, although design.md says it does. Until the rail calls `start()`, the owner sees no change.

8. **[note] Sessions are keyed by the browser's host, so the phone and the PC never see each other's sessions.** See `Sessions.js:426` and `:435`, and `ServexProxy.js:57`. Failure: the owner starts a session on the phone (`10.0.0.135:8481`) and opens the same page on the PC (`monorepo.localhost`). Recent sessions is empty there, and ✦ starts a new session instead of resuming. A new DHCP address on the LAN hides every phone session too. The owner asked for the opposite at 7:55 PM: "any new session knows everything that happened in any other session".

9. **[note] A Servex restart can silently drop a line from the smart assistant.** The quiet-gap batch lives only in memory (`Sessions.js:300`). Failure: a say in the 1.5 seconds before a restart reaches the fast assistant but never the smart one, and a smart turn that is in progress during the restart ends without a line. After a restart, a Servex line such as "the assistants restarted; your last line was not answered" would make this visible.

10. **[note] The owner's spoken words land as untracked files in the main checkout.** `git status` in the main checkout shows `?? public/framework/ext/Session/ai/`, and nothing gitignores it, so any agent's `git add -A` commits the transcripts. Sessions also always write under Servex's own repo, whatever the host. A page that exists only in a worktree gets its session filed under its nearest parent in the main checkout (`nearest()`, `Sessions.js:125`).

11. **[note] `ai/log.jsonl` will show untitled sessions that never end.** `point()` (`Sessions.js:178`) writes `started` with `title: null` in every folder the session passes through. Only the home folder gets the title update (`:245`), and only the home gets `ended`, and only on an idle stop (`:373`), never after `room()` or a restart. Failure: when an AI tab starts reading this log, a session that passed through a folder shows there as untitled and running forever.

12. **[note] Three items from the first review are still open.** The Recent list is hidden behind "Show them" until a session starts (`ext/Session/page.js:68`; `list()` runs only inside `open()`). The directory mastermind can still write files through Bash under `bypassPermissions` (`directory.js:177`). A refinement sent without `re` still attaches to the newest owner line in its batch (`Sessions.js:256`). There is also no limit on directory masterminds per session: a talk about six folders runs six manager-tier agents at once, each held for 10 minutes.
