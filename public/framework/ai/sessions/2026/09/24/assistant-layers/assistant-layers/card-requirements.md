## The owner's words

"I'd like each card to have its own fast assistant instance. [...] We want each assistant very quick and minimal and not distracted. Each one could have its own session id."

"When a prompt comes in, the fast assistant literally turns it into UI: quick judgments, scaffolding things up as quickly as possible. [...] The second something needs doing, the assistant uses its tool call to create a request, question or task, putting the right part of the prompt into it, and spawns a MANAGER: relatively fast, not a huge deep thinker. One manager per card can probably handle most tasks. [...] The card's manager session id should be RECYCLED: any question asked there before, any work done, any context, is reused for the new question. We'll want UI per card showing what context each agent has, how many tokens, and what percentage of its full window, with the ability to compact or recycle. [...] we might want our own compaction system, so we can log the important details in the proper place."

## Deliverables

1. **`Servex/agents/Layers.js`**: `export default class Layers`, house style (assign-based constructor, every method a seam), built with `{ servex }`, `install()` returns this.
   - **State** kept in `%LOCALAPPDATA%/lew42/servex/layers.json` (write whole file, it is ours alone): `{ cards: { <root card id>: { assistant: {id, session_id, cwd}, manager: {id, session_id, cwd} } } }`. Ids are minted once per card: `assistant-<last segment>` and `manager-<last segment>`; if that id is already recorded for a DIFFERENT card, add `-2`, `-3`.
   - **Hearing the owner**: `servex.cards.on(...)`; for a line with `prompt` and `info.fresh`, find the root card and call `heard(card, prompt)`. Ignore everything else.
   - **`assistant(card)`**: returns the live assistant, resuming it (`resume` + kept `id` + its recorded `cwd`) when it has a session id and is not live, or spawning it fresh: model `model("fast")`, effort `low`, `permission_mode: "bypassPermissions"`, `system` = `card-assistant.md` (below) + "\n\n" + `brief(servex)`, `allowed_tools`: `mcp__servex__card_reply`, `mcp__servex__create_card`, `mcp__servex__card_set`, `mcp__servex__ask_manager`, `mcp__servex__send_to_agent`, `mcp__servex__card_summary`. Its first-spawn `prompt` is the card's transcript followed by "The owner's newest words are the last prompt line. Answer them." (then `heard` must NOT also send that same prompt). Record `session_id` once the agent has one.
   - **Delivery**: every later prompt goes `agents.send(id, text, {from: "owner", reply_to: "card <card>"})`. Do NOT write an `attach` line for the assistant or the manager: Cards' own forwarding would then deliver every prompt twice. The context panel reads our state file instead.
   - **Idle stop**: 30 minutes after an agent's last activity, `stop` it, unless it is a card's assistant whose manager is `working`. Keep the session id. `SERVEX_CARD_IDLE_MS` overrides 30 minutes (the proof will set it low).
   - **Tools** (register all four in `install()`), each using `ctx.caller` for identity and refusing a caller that is not `assistant-*`/`manager-*` of that card where it matters:
     - `card_set({card, type?, title?, status?, tags?})`: append each given field as its own line (`{type: …}`, `{title: …}`, …) to `card`, which must be the caller's root card or a sub-card of it.
     - `ask_manager({card, text})`: `card` is the caller's root card or one of its sub-cards (the assistant makes a request/question/task sub-card first with `create_card`). Resumes or spawns the manager: model `model("manager")`, effort `medium`, `permission_mode: "bypassPermissions"`, `cwd` the repo root (`path.join(HERE, "../..")`), `parent` = the card's assistant id, `prompt` on first spawn = "Load the `sub-mastermind` skill. You are <manager id>, the manager of card <root>. Your session is kept for this card's whole life: every later request on this card comes to you, so keep what you learn. First call `claim_topic({topic, card})` for the topic you are about to work on; if it is refused, message mastermind-servex instead of starting. Start minions with spawn_agent({parent: \"<manager id>\"}). Report on the card with card_reply. Keep your own turns short.\n\n" + transcript + "\n\nRequest from <caller> on <card>: <text>". Later asks are `send`, from the caller. Returns `{ok, manager, state}`.
     - `card_summary({text})`: appends `{summary: {by: caller, text}}` to the caller's root card, then marks the caller for recycling once its current turn ends (see below).
   - **Recycle and compact**:
     - `recycle(id)`: stop the agent and forget its `session_id` (keep its id). The next time it is needed it spawns fresh; its first prompt uses the transcript from the LAST `summary` line onward (the summary included) when there is one.
     - `compact(id)`: `send(id, "Compact now: call card_summary with everything important about this card that is not already in its log: decisions, open questions, and what you were in the middle of. Then stop.", {from: "owner", priority: "next"})`. The recycle happens when `card_summary` is called.
   - **Routes** on `servex.dashboard.router`, with the same CORS helper `Assistant.js`'s `route()` uses: `GET /api/card-agents?card=<id>` → `[{id, role, state, model, session_id, context, window, pct}]` for that card's assistant and manager (`window` 1,000,000 when the model id contains `[1m]`, else 200,000; `pct` = round(100 * context / window), null when context is unknown); `POST /api/agent/:id/compact` and `POST /api/agent/:id/recycle` → `{ok}`.
   - `ask_manager` is also callable from code: `layers.ask_manager({card, text, from, task})`, the Dispatcher's door (next item).
