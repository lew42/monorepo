Generated by `node Servex/leaks.mjs --root <repo> --write report.md` (the three tables below), then the causes by hand from the lifecycle log (`%LOCALAPPDATA%/lew42/servex/logs/lifecycle.jsonl`, since 2026-11-04) and `node Servex/Lifecycle.js --dry`.

## What the numbers say

- **Process start lines (session logs + spawns):** no real leak. Nothing is alive with its owner done; the one "gone" row is a junk line a test wrote (below). The sampled lineage lines are young (the feature landed today), so the table is short.
- **Lifecycle log (servers, health watchers, browsers):** 604 browser "browser closed" ends against 148 browser "found gone" ends; 160 server "found gone" ends (94 run.js, 66 server.js), mostly under the quick-fix slots qf-1..qf-8. "Found gone" means the sweep had to write the end because the process died without a goodbye.
- **Dry sweep right now:** 47 idle agents would close (one-pass reviewers, clarity and similar: not processes), 6 start lines are for dead processes (server.js:38668, run.js:49232, run.js:2848, browser:36520, browser:49408, browser:53524), 14 are kept. No live process is a leak.

## Causes found and fixed

1. **Browser killed by `process.exit()` in the launching script** (148 "found gone" browser ends). `Browser.mjs`'s `exit` hook killed chrome but wrote no end line; the async "browser closed" post usually never left the process. Fixed in `Server/Browser.mjs`: the exit hook writes the end line synchronously (`end_line`), once.
2. **Orphan chrome killed by the watchdog with no end line.** `Server/browser-watchdog.mjs` closed the browser and exited. Fixed: it writes the end line (from the start line's own fields) when it closes the browser, or when it finds both launcher and browser already gone.
3. **`taskkill /T /F` of a tree skips every exit hook inside it** (160 server "found gone" ends). `Pool.kill` and `Lifecycle.close` end a wrapper, and the run.js / server.js / health starts inside it never close.
   Fix: new `Lifecycle.end_killed(dir, why, {skip_id})` ends every open server / health / browser start under the killed path whose pid is dead. `close()` and `Pool.kill` call it.
4. **Safety holes found on the way** (not leaks, but the same close paths): `--stop <pid>` could end the owner's Chrome; the watchdog could kill a *reused* pid; `Lifecycle.kill` trusted its stored pid. Fixed with `owners_own()` / `OUR_CHROME` in `Lifecycle.js` (refuses Chrome without a Playwright marker, Code, Figma and similar) and a command-line check in the watchdog. Proof: `Servex/chrome-pin.test.mjs`.
5. **The sweep stays as the net.** `sweep()`'s "found gone" lines remain for a process that dies without any closer (a power cut); they should now be rare.
