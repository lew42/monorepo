2. **The flex and grid words.** Add as panel keys (persisted like `display` is — `item.set(key)` → `data` → the saver; nothing new to persist):

   - grid: `cols` (auto · 1 · 2 · 3 · 4 — `auto` = today's `auto-fit, minmax(8em,1fr)`), `gap` (same choices), `dense` (off | on). A grid CHILD's `span` (1 · 2 · 3) if it is one row in the rail and one CSS var — skip if it costs more.
   These land as **CSS custom properties written on the body** by `paint.js` `show()` (the single writer of the display class — keep it the single writer of these too): `.panel-body.panel-d-flex { flex-direction: var(--panel-dir, row); gap: var(--panel-gap, .5em); flex-wrap: var(--panel-wrap, nowrap); justify-content: …; align-items: … }`, `.panel-body.panel-d-grid { grid-template-columns: var(--panel-cols, repeat(auto-fit, minmax(8em, 1fr))); gap: …; grid-auto-flow: var(--panel-flow, row) }` in `display.css`. Every rule stays in `@layer theme`. A word only shows in bar/rail when the display mode makes it live (flex words under flex, grid words under grid) — the rail already has that idiom for size rows.
   The `display` overlay (`display.js` `flex_layer` / `grid_layer`) draws what the class did; check it reads the live geometry (it should follow for free) — if it hardcodes 0.5em or the track count anywhere, fix that one read.

## Findings from the grid test-drive (`../panel-grid/`) that land in YOUR files — fix these as part of step 2

- **Every `T` entry wraps its content in ONE div** (`templates.js:62-117`), so a leaf's `display: flex|grid` never sees more than one child on any shipped template — the words are inert on the content they are meant to arrange. Make the display words act on real children: the cleanest read is that a template's `draw($body)` appends its pieces DIRECTLY into the body (no wrapper) for the section adapters that are lists of things (cards, quotes, nav items), or a `cards`/`items` template exists whose N pieces are direct children — pick the smaller change and say which; prove with the computed test in step 4 on that template.
- **flex mode never wraps** (`display.css:8` has no `flex-wrap`) — `wrap` is one of your words.
- **`structure()` never writes `display`** (`generate.js`) — 0 of 8 sown seeds became a grid even when the spec said `grid`. The translator should map the spec's `flex`/`grid` (and `v`, `gap`, `auto`/`three` where the grammar has them) onto the new panel keys, so a preset arrives with its words on.
- A nested split inside a leaf is structurally impossible (a leaf holds no items) — not yours to change; note it in `doc/decisions.md` if you touch that file.
