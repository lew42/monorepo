## Build

1. **The recorder — hook the root Item's events, not the verbs.** `workspace.js` `mount()` (line ~87) already binds `root.on("change" | "add" | "remove")` for save + redraw; a flow subscribes the same way and catches every mutation path (divide/split/close/absorb/sow/drag/set). A step is `{ at, snapshot }` with `snapshot = root.toJSON()` (Panel already serializes losslessly — it is what the saver writes; `core/Item/Item.js` `toJSON()` / `Item.hydrate()`). No diffs, no inverse-operation table. Coalesce a burst (a grip drag fires `change` per pixel — one step per gesture: debounce ~150ms or key on the verb's end, whichever is honest; log which). Memory only — nothing on disk; a `flow.save()` that hands back the JSON array is enough for a test to keep one.
2. **Replay — `Item.hydrate(snapshot)` + redraw.** Stepping to step *n* rebuilds the tree from that snapshot in place (`workspace.js`'s `draw()` already rebuilds DOM from the tree). Recording pauses while replaying, or every replayed step would record itself — say how you guard it. Stepping back to *live* resumes recording from the last snapshot.
3. **The scrubber.** One small strip: `⏮ ◀ n / N ▶ ⏭ · ● rec` + the step's verb if you can name it cheaply from the diff of two snapshots (panels added / removed / a key changed — one clause; skip if it costs more than 15 lines). Mounted by the PAGE beside the workspace (`page.js` on `/` and the `/full/` route), NOT inside the per-panel hover bar. Under 40 lines of CSS, `panel-flow-` prefix, `@layer theme`.
4. **`panel.stage()` — the composition, three lines** (strategy step 5): the same arrangement inside `demo.stage()`'s width dial — `demo.stage(() => panel(seed))` — shown once on `page.js` as a demo block: *"the responsive half: drag the stage's handle and watch the arrangement reflow."* Export the helper from wherever `panel()` is exported if that keeps callers to one import; otherwise the demo alone is enough. Do not build a class.
