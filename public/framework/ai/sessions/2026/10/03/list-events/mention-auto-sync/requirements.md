# Mention index: rebuild itself, never go stale

Relayed via vscode-mastermind → page-item mastermind's queue, item 2 of 2 (budget ~$5 of ~$10
for both; item 1 is a sibling task, `ref-content-rows` — unrelated files, no overlap).

## The ask (the owner, verbatim)

> Cheap, never-stale page references. Owner: loading a whole page (or a big page.jsonl) just to
> get its icon and title is too much; a hand-run cache goes stale; DRY. Today
> `ext/Mention/maps/refs.js` is generated by a script someone must re-run (`sync.mjs`). Make the
> index rebuild itself: when a page.js's icon/title or a page.jsonl's first line changes, the dev
> server (it already watches) updates the one index; page.jsonl pages included. Title renames
> then show everywhere. One index, computed, never typed. Write the decision + the alternative
> the owner floated (a per-folder meta.json snapshot) in one line on your card.

## Scope fence

Touches only: the dev server's watcher under `Server/` (reusing `Server/watch.js`'s one shared
`fs.watch` handle, same pattern as `Server/plugins/Directory.js`), `ext/Mention/sync.mjs`, and
`ext/Mention/maps/refs.js`. Does **not** touch `core/Page/Page.class.js` or anything about
rendering a reference as a content row — that's the sibling task (`ref-content-rows`).

## What already existed (read before building)

- `sync.mjs` pass 1 (cheap, text-only): reads each curated entry's `page.js` text for its
  `icon:` literal.
- `sync.mjs` pass 2 (expensive): loads each page headless to read the live `class_card` fact.
- `Mention.js`'s own `live()`: already reads a LIVE `Page` instance's icon/class_card when one
  exists this session — `refs.js` is explicitly documented (`doc/syntax.md`) as "the fallback's
  fallback," only consulted cold. So the real staleness this task closes is: nobody ever reruns
  `sync.mjs`, so the COLD case (a page nobody's visited yet) can serve a stale icon forever.
- `Server/plugins/Directory.js` is the exact precedent for "one shared watcher, trailing
  debounce, rebuild a generated JSON-ish file, skip on `BOOT_TEST`" — reused verbatim, not
  rebuilt.

## Decision (write this one line on the card too)

**Chosen: a computed-on-change index**, piggybacked on the one `fs.watch` handle `watch.js`
already runs (same plugin shape as `Directory.js`): on a real change to a watched `page.js` or
`page.jsonl`, debounce, re-derive that entry's `icon` (text regex, cheap — no headless browser
on every keystroke) and rewrite `refs.js` only if it actually changed.

**Alternative (the owner's own, rejected):** a per-folder `meta.json` snapshot. Rejected because
it is a second index format next to `refs.js` (Law 6: one of everything) — a reader (or the
sibling's content-row) would need to know to check TWO places depending on the page's shape, and
every page gains a new file to keep in sync with itself. One computed index, one shape, is
simpler and is what the owner's own sentence ("one index, computed, never typed") asks for.

## page.jsonl pages — generalised, not yet exercised

No current `refs.js` entry is backed by a `page.jsonl` page (the curated ~30 are all classic
`page.js` modules). To honour "page.jsonl pages included" the sync function still handles that
shape generically: a url with no `page.js` but a `page.jsonl` reads that file's first (`assign`)
line for `class` (the page template it renders through, e.g. `/framework/ai2/card.js`) and
borrows THAT page's own `icon:` text — so a future curated mention of a jsonl-backed page stays
correct the same way, without a second code path.

**Not automated: `class_card`.** That needs a real headless page load (`sync.mjs` pass 2) —
expensive per edit, and `live()` already covers the hot case. Left as the manual fallback
(`node sync.mjs`), noted in `doc/`.
