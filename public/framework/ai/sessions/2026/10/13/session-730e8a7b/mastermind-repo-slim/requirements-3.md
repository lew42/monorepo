## Asks, as the mastermind reads them

1. **PWA / notifications:** was it done? Look into it, find the state, link it.
2. **The inbox as the clean timeline of everything asked for recently:** prioritized, only the important things, ranked by recency so scrolling shows "here's all the big things I've been asking for". Find out how the inbox is stored today (board.jsonl? page.jsonl? the Inbox class), decide where that data should live, and make it an appendable JSONL set that is loaded, sorted and streamed. One robust system for data structure, streaming and updates shared with the sessions page and the data grid: a preview rail, click for the detail page, a right sidebar per card to talk to it with context.
3. **Durable objects, a proposal:** one per page could make sense for real-time messaging (short-lived, cheap); hundreds for every little thing is not the way. Not a decision.
4. **One global assistant**, not one per page (navigating loses context): a fast assistant transcribes and responds per sentence as Whisper delivers it; a smart variant watches the transcribe/clean/refine process and suggests, hands-off on decisions; the refined prompt goes to a mastermind as soon as it is ready, not per sentence. "I wish that were working."
5. **The iceberg page of what happened recently:** the main things first, click through to the smaller ones. The sessions page stays for cost, timing and what is active, but thousands of sessions are overwhelming; the finished products are what matters.
6. **Indexing and querying thousands of sessions:** a server-side process that holds the session data in memory and filters it in JavaScript (no new database, nothing to install); the dynamic index and the query are the same thing. Lean into JSONL (git-friendly). Check what the earlier indexing design did.
7. **Git tree clean:** which files change and how that affects the commit flow is still an open question (covered by tidy-git-status + repo-size.md).
