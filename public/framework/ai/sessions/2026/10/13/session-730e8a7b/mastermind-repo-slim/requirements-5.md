# Dictation 7, 2026-10-13 ~17:05: models (OpenRouter?), the dictation UX, fast vs smart assistant, automated loops, confidence weights, fresh sessions

## Asks, as the mastermind reads them

1. **Models:** the smart assistant said we are configured for OpenRouter; the owner thought that was reversed yesterday. While Claude tokens exist (and are about to expire), the fast and smart assistants run on Haiku and Sonnet. Paying OpenRouter when not needed is bad. A switch to OpenRouter is needed for when the Claude wall hits, and the owner must be able to SEE which agents run on what.
2. **Dictation UX, "unacceptable after weeks":** chat bubbles came out of order; agents should add chat bubbles and context cards through the page tools. Pipeline: raw Whisper text as delivered → a minimal, robust cleaning pass → refinement and structure into proper cards in real time, per chunk. Chunking: sentence as the baseline; a comma/pause or a word count (more than ~4 words) could send earlier; never process a chunk that adds no value.
3. **One dictation system:** the desktop sidebar and the mobile sheet run the same code; the experience and outcome (cards, processing, refinement, getting it done) is identical. Think through the architecture: what goes where, how dictate, chat and refine nest. Several configurations exist today because the owner asked for them over time; converge.
4. **Fast vs smart assistant:** separate SDK instances with their own context. Fast = Haiku, under 100k tokens, auto-compacts or restarts after ~30 min idle; it reads the live transcription per chunk, cleans it (punctuation, filler words, turns spoken paths like "framework slash AI" into links), passes things to the right place, and does NOT reply in chat unless addressed by name. Smart = the one that responds, checks the cleaned text makes sense, asks to clarify but with a timeout (proceeds with the top-ranked option if the owner does not answer), does the prompt refinement, puts structured content in the right place and hands it to the masterminds; keeps its hands free (no heavy tools). Masterminds execute and may be busy, so prompts queue to them. Persistence: agents log to JSONL as they go so their state survives if they vanish; no handoff files needed.
5. **Functional, automated loops everywhere:** AI must not have to remember to close worktrees or move to the next task; node answers each finished step with the next step's description (automated reprompting), steps pre-programmed once the mastermind approves the plan, each step logged with timestamps, data structures updated by code. Apply this principle across all AI systems.
6. **The AI system page:** `/framework/ai` as a defined system (the readme system is the AI system) with its components documented for AI first and shown to the owner. Directives that resonate go in architecture.md or the readme: don't copy a file by reading and writing it (use move/copy); the open questions of how many minions, which model, which effort, and what they get done; the model-testing system is past work.
7. **Sessions:** make the session system good enough to dig through the data, see what was requested and when, click through to raw logs.
8. **Refinement on past prompts:** test the refinement system day by day in reverse: raw prompts → what was actually requested (command, question, directive) → the outcome needed → confidence that (1) the ask is clear and (2) the outcome is clear.
9. **Confidence weights:** today's numbers (0.9 everywhere) did not match the owner's judgment. Either default 0.5 as "not sure" and move from there, or default 1.0 as a multiplier (>1 more confident, <1 less). Whatever it is, the interpretation must be unmistakable.
10. **Fresh sessions:** start fresh after a round of work (read the readmes and the code with a fresh perspective); reuse a session only when its cache is fresh and the topic continues.
