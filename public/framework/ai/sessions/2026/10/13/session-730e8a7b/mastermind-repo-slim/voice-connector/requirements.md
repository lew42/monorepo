# The Claude app's voice chat reaches the mastermind: one tool, behind a token, through a free Cloudflare quick tunnel

Budget: $12. Load the `sub-mastermind` and `code` skills first. Read `ux/Dictate/doc/voice-bridge.md` (the decision: a connector, not a browser bridge; Road 1) and `ai/doc/cloudflare.md`. The owner's words: `../requirements-13.md` ask 8 ("the tunnel was to allow the voice chat to access my MCPs, the Servex MCP"). Servex already serves its tools to agents in-process (`Servex/agents/tools.js`, `createSdkMcpServer`); this task adds a tiny remote MCP endpoint with ONE tool, read-mostly, so a claude.ai chat (and its voice mode, if voice mode can call connectors) can ask the mastermind a question. Your log is this dir's `task.jsonl`.

## Deliverable

1. **`Servex/ext/remote/RemoteMCP.js` (`class RemoteMCP`)**: an HTTP endpoint on Servex (`/mcp/remote`, Streamable HTTP transport, the MCP spec's JSON-RPC over POST; no new npm dependency: hand-write the three methods `initialize`, `tools/list`, `tools/call`) that requires `Authorization: Bearer <token>` where the token is a random 32-byte value written once to `%LOCALAPPDATA%\lew42\servex\remote.token` (never in the repo, never printed in a log). One tool: `ask_mastermind(question)`: appends a `chat` line from `"owner (voice)"` to the live mastermind run's `task.jsonl` and `send_to_agent`s the mastermind, waits up to 60 s for its reply (a `card_reply`/log line with a matching id), and returns the reply text or "the mastermind is busy; the question is logged at <link>". Every call is one log line in `ai/log.jsonl` (who, what, when, ms). Tested on a private port with curl: no token → 401; `tools/list` → one tool; a call round-trips.
2. **The tunnel**: `node Server/Tunnel.mjs up` (`class Tunnel`) runs `npx cloudflared tunnel --url http://localhost:<servex port>/mcp/remote` (a quick tunnel: free, no account, a random `trycloudflare.com` URL that changes each run), prints the URL once to the terminal and writes it to `%LOCALAPPDATA%\lew42\servex\remote.url`; `down` stops it; `status` shows whether it is up. Nothing else on Servex is reachable through it (the endpoint path is the only route the tunnel targets, and the handler refuses any other path).
3. **The owner's two steps, written in `ux/Dictate/doc/voice-bridge.md`** (section "Try it"): in the Claude app, Settings → Connectors → Add custom connector, paste the URL from `remote.url` and the token from `remote.token` as the bearer; then in a voice chat say "ask the mastermind what landed today". Note what is unknown (whether voice mode on the phone can call a custom connector) and what to look for.
4. Card (title "Voice chat can ask the mastermind: one tool, one token, a free tunnel; two steps for you"); landing line checked with `tail -1`; `merge.mjs`; the live Servex is restarted by the mastermind, then the mastermind runs `Tunnel.mjs up` and posts the two steps on the card (never the token).

Fence: `Servex/ext/remote/**`, `Server/Tunnel.mjs`, the one doc section, the Servex route registration (one line), this task dir. Never expose any path but `/mcp/remote`; never print or commit a token. Sonnet.
