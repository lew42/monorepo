## The trap in the obvious check

`git log michael/dev..<branch>` counts commits, and `merge.mjs` sometimes lands a branch by applying its diff (recording the head in `.merge-landed.json`), so a fully landed branch can still show commits "ahead". Today's list has 80+ `worktree/*` branches ahead by 1–22 commits; most are landed. The check must be **by content**: for every file the branch changed since its merge base, is the branch's version of that file present in michael/dev's history (`git log michael/dev --find-object=<blob>` or a blob-hash lookup), or identical to michael/dev's current file? A branch is "landed" when every changed file passes; otherwise the missing files are the finding.
