1. **The rubric, as a script**: `Server/UndoneVerify.mjs` (`class UndoneVerify`) reads `ai/asks/undone.json`, groups the undone asks by module, and writes one brief per batch (about 25 asks each, so each Haiku run stays under 60k tokens with the module readme chain inlined) into `batches/` here: for each ask, the Haiku must answer `done | undone | unclear` with evidence: the path and line of the thing that does it, or the two or three places it looked and did not find it (the module readme, its `doc/`, `git log --oneline -S"<key words>"`, the task homes). A `--merge` flag reads the batch results back and writes `verified`, `evidence`, `verified_at`, `verified_by` onto each ask in `undone.json`, and prints the two numbers that must agree: asks verified and done + undone + unclear.
