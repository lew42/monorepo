# What every checkup mastermind does (shared by the seven `checkup-*` briefs)

Load the `sub-mastermind` and `code` skills first. Read CLAUDE.md (the laws), `public/framework/ai/handover.md` (its first two LATEST sections, 2026-10-16/17), and the owner's words in `requirements-14.md` beside this file (asks 4 and 5 are yours: "a fresh mastermind working in that directory… a quick checkup… if there's a next step we're waiting on, help figure that out… I don't want you to wait on me… make the executive decision… think about a couple alternatives and then just make a decision, document that a decision was made"). Then the readme chain of each module you touch. Your log is your own dir's `task.jsonl`.

## The job: a checkup, then the next step

For every task your brief lists: (a) **what landed**: its `task.jsonl`, its card, its commits on `michael/dev` (`git log --oneline -- <paths>`; a landing line without the code on dev is NOT landed); (b) **is it live and linked**: the page opens (a headless shot or `check_page`, never the owner's tabs), its docs sit inside the module and are linked from the module readme, nothing it made is untracked (`git status --porcelain -- <dir>`); (c) **what is open**, in one line; (d) **the next step, decided**. The owner (2026-10-17): never wait on the owner. Anything "waiting on the owner's yes" you decide yourself: weigh the one or two alternatives, pick, write a `decision` line (`options` with each alternative's caveat and when it would win), and START it. A next step under about 30 minutes or $5 you do yourself or with ONE Sonnet minion; a bigger one gets a `requirements.md` brief in a new child dir (`node Server/TaskDirs.mjs --new <slug> --parent <your dir>`) and a spawned agent (`spawn_agent` with `task {dir, card, brief}`, your id as `parent`), logged as an `agent` line. Finishing is the point: the owner is "dropping balls all over the place"; a checkup that only lists is a miss.

- **In-flight or dormant agents** are talked to, never edited around: `send_to_agent {id, text, from: "<your id>", reply_to: "message <your id>", revive: true}`; answers arrive by `wait_for_agent` or in their task.jsonl. Never edit inside another agent's directory (the owner's standing rule); your findings about it go in YOUR checkup.md. An agent that has spent hundreds of dollars (`list_agents` shows cost) is not woken for reading: read its files instead; wake it only to hand it a decision it is waiting on.
- **Deliverable:** `checkup.md` in your dir, one screen: a table with one row per task (task, as a link to its dir on the site · state · what is open · decision · next, with the link to where it continues), then **Decisions made for the owner** (each with its alternative), then **Needs the owner** only for credentials, money, deletes git cannot undo, or a push. The same in three or four plain sentences as a `card_reply` on card `2026/10/16/checkup-on-everything-the-voice-sessions` (from your id) when you start and when you land. Names the owner knows (pages, modules, classes), no run labels, judgment calls worded as should/could.
- **Rules:** never push; never restart Servex (write `{"log":{"needs_restart":"<why>"}}` and say it in checkup.md; the parent restarts when nobody is mid-step); never delete (move aside by script with a manifest, say so); never commit screenshots; a change the site loads goes worktree → check → `merge.mjs`; commit records by path (`git add <paths>` then commit; retry on `index.lock`); your dir's files are all committed or gitignored with a one-line reason; `git status --porcelain` clean for everything you touched; the landing line last, checked with `tail -1`. Never run `find /`; never drive the owner's tabs; diff, never shelve uncommitted work with git (the minion skill's never-list).
