verdict: fix
1. [fix] `ai/AISession/AISessionConversation.js` is a second chat renderer. `ext/Chat/Chat.js` already does exactly this job: its `chat({ source, keep })` returns `.view` and `.sync()`, it draws each line once (a `seen` set), has smart scroll, labels each sender, and has `place_card` for inline cards. The brief (law 6: "look before writing one") asks to reuse the existing component, so feed the transcript entries into `ext/Chat` and drop the new class, or say in the doc why it cannot be used.
2. [fix] Step 1 says "stream, never poll", but `AISessionFollow.js:12` only shortens the `setInterval` + `fetch` poll from 3000 to 1000 ms. That is still polling and about 10x slower than the ~100 ms asked for. `doc/realtime.md` describes a dev-socket push (`session_index`), and `ext/JSONL` has `live()`. Use one of those, or add a per-line socket feed. If that has to wait, write it down as an open item in the doc instead of calling the page live.
3. [fix] Step 5 is not met. Cards are read once at load (`AISessionDetail.load_cards`), they sit in the side column instead of inline at their time, and nothing shows that a card the mastermind posts appears live. `doc/session-cards.md` admits this under "Not yet". Nothing confirms that `page_add`/`page_note` actually write `{"card":{title,text,href}}` lines, so the chosen format may never be produced by any tool. Check what the tool writes, then show one real card arriving live, inline (`ext/Chat`'s `place_card` may already cover the inline part).
4. [note] The first `pull()` passes the whole transcript to `on_lines`, so `AISessionConversation.add` draws every message of a long session and only then trims to 200 (`AISessionConversation.js:43-44`). Slice to the newest 200 messages before drawing.
5. [note] The "stay at the bottom" check uses `document.scrollingElement` (`AISessionConversation.js:42`). The page is `width: "fill"` inside a panel, and if the panel scrolls rather than the document, the check is always wrong. Moving to `ext/Chat` (finding 1) fixes this too.
6. [note] The `load_transcript` call is gone from the `Promise.all`, but the static `AISessionDetail.load_transcript` (around line 148) is now dead code. Delete it, or leave a comment saying who still uses it.
7. [note] The "No transcript" message only shows on the follow path. A non-uuid id that falls to `load_lines` and gets nothing shows an empty column.
8. [note] There are no screenshots at 1400 and 3440 in the review folder, so I could not verify steps 3 and 4 ("conversation within ~200 px", "fills the width"). The `cols main-aside` layout looks right in code.
