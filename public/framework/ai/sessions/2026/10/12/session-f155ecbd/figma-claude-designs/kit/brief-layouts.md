# Brief: foundational layouts, each shown four ways (owner, 2026-10-12, night)

Read [brief-ds.md](brief-ds.md) first (page shape, Specimen tiles, tokens only, prime as a splash, hug or fill, schemes as Text modes). The owner: "the simpler and more foundational it is, the more useful it is… take a specific layout and show four or more uses of it, where you just put different things on each side." The goal is a few robust, versatile layouts you can mix and match, not many unique ones.

## The layouts (one section each, simplest first)

1. **Stack** — one column: title, body, action.
2. **Two columns, title left / content right** — left: an accent label, a title, a short gist and maybe 3–4 nav links; right: a card (or list, form, image). The left can be narrow (hug ~1/3) or equal (1/2).
3. **Split 50/50** — two equal halves (text | image, before | after, question | answer).
4. **Media + text** — a fixed image box beside text that fills.
5. **Sidebar + content** — a nav rail (fixed) and a content area that fills.
6. **Three columns** — equal shares (features, stats, plans).
7. **Header / body / footer band** — full-width bands of different grounds.

## For each layout

- A small wireframe tile naming its rule (what hugs, what fills, the gap token).
- **Four or more uses**, same layout, different content: e.g. two-columns as a docs intro + card, a settings page (nav left, form right), a pricing explainer (copy left, plan card right), a profile (identity left, activity right), a diagram caption (text left, flow right).
- Each use in a different scheme across the row (White, Light gray, Dark, near-black dark) so the colour stacking is visible; prime only as a splash.
- How it collapses on a 390 phone (the left goes above the right; the rail becomes a top bar or sheet).
- If a left-side nav suggests switching the right side, wire it as a prototype (clicking a nav item swaps the card via variants or NAVIGATE) and put a big ▶ PROTOTYPE badge above it.
