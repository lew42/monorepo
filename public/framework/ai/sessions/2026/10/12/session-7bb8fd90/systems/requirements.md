# The organizational system: what goes where, when and why (task mastermind brief)

**Owner's ask (2026-10-12, dictated):** an organizational system, "just what goes where and when and why", written briefly (too much text confuses and burns agent time). It records what should always or usually happen: documentation, navigation, readmes, pages. Navigation items get missed; documentation lives in the readme and the page. Also a **system class**: a `System` is anything (code, design, layout, readmes) and the class mostly documents it: where its files live, its rules, maybe functions and templates; extendable with object-oriented JS. The README system is itself a system. Wanted: systems that **self-document, self-heal, recommend, and improve at the right pace** (too fast does nothing; too slow does not help). Also: is there a system-architect mastermind, and does it run on a heartbeat?

## Do, smallest first
1. **Inventory (script + readmes):** what exists: the `system-architect` skill and `ai/sessions/2026/10/09/session-a07780b9/system-architect/` (claude-md-proposal, oo-census), `Servex` heartbeat/TaskLoop, `ai/doc` readme-system notes, any earlier "system class" asks (grep `ai/` for them and link, do not retype). Report in a screen.
2. **`organization.md`** (one page, under ~80 lines, in `ai/doc/` linked from the root and `ai/` readmes): for each of navigation, documentation (readme/doc/page), tasks/sessions, commits, naming: what always happens, what usually happens, who/what enforces it (a script, a hook, an agent), and the check that proves it. Prefer enforced-by-script over a rule an agent must remember.
3. **Class architecture first, then the smallest `System` class** (one file named for the class, per CLAUDE.md): name, root path, readme, rules list, `check()` that returns findings (compute, not recall), `report()`; two real subclasses to prove it (e.g. `NavigationSystem` using the orphan-page check from `ai-system-docs`, `ReadmeSystem` using the readme length/links audit). A live page shows each system as a class card with its latest check result.
4. **Heartbeat:** design and wire (smallest working version) an hourly wake for a system-architect mastermind: runs the checks, files a short report card, makes at most a few small safe fixes per cycle (the "right pace"), then sleeps; reuse Servex `heartbeat`/`TaskLoop` rather than a new scheduler. Respect the usage pace: skip a cycle when `node Server/usage-now.mjs` exits 2.
5. Record decisions and the alternative in `doc/`; everything linked from the site.
