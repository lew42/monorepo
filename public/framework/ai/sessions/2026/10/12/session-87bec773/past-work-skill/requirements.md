# Past work and a plan, before every build: a `past-work` skill (brief)

**Owner (2026-10-12):** "We don't want to set off and build something that's already been built, especially if it's stable and used everywhere." Searching past work should be automatic, short (don't pollute context), recent first. And every task should have an **investigation / plan stage**: how does it work now, what are the relevant pieces, what decisions must be made.

## Done when (tick each with proof)
- [ ] **`.claude/skills/past-work/SKILL.md`:** given a topic, a Haiku minion (under 60k tokens) finds related past tasks, docs and modules (task dirs under `ai/`, `asks.jsonl`, `doc/*.md`, `git log --grep`). It returns at most one screen:
  - what was done, with its date;
  - whether it is still live (checked against the code, not trusted);
  - how it is similar to or different from the new ask;
  - links.

  A mastermind runs it itself or has a minion run it. Backed by a node script that does the searching and counting (law 7); the model only judges.
- [ ] **A topic index** of past-work summaries, generated by script from task landing lines (`outcome`) and tags, linked from `ai/readme.md` and one line in the `new-task` skill. CLAUDE.md gets no new text (ask first); the skills point at it.
- [ ] **Plan stage:** `new-task` and `mastermind` skills say: past-work → investigate (current structure, relevant pieces, decisions to make) → `plan.md` beside `requirements.md` → build. Kept short; written as suggestion, not law.
- [ ] **Proof:** run it on three real topics (page templates, data grid, colour schemes); paste the outputs; measure tokens and time.
- [ ] Commit each step; merge; land.
