# Owner note 1 (2026-10-10, dictated): unify Figma and the framework

Addendum to [requirements.md](requirements.md). The essence, not a spec; the details are the owner's best guess.

1. **Site pages into Figma, if it works.** Prove with one test that `generate_figma_design` can capture a framework page into a Figma file (a page on the local dev server is enough; no public URL needed, see the capture tool's description). Resolution is an open question: choose the viewport yourself (400/1200/1920/3440) and record what you get. Value: Figma's own agent could study and critique our layouts. The owner doubts the fidelity (Figma layout and CSS are different algorithms); measure it and write the verdict down.
2. **Figma into the framework, at scale.** There may be hundreds of Figma files whose essence could be regenerated as framework HTML/CSS/JS. The hard part is not drawing it, it is **how well the MCP documents structure and CSS, and how that maps onto our system**: Figma files differ in hierarchy and properties, and auto layout is often missing, partial or only partly responsive. Expect interpretation: grid or flex, which flex, which of our column/drawer/layout words. Write down which Figma properties tell you what (auto-layout direction, sizing FIXED/HUG/FILL, gaps, constraints) and where the signal runs out, so the mapping is a table, not a guess.
3. **Goal: what the owner sees in Figma is what the browser gives.** The owner expects to design more in Figma and move it to the framework, so the process must become reliable. Treat this as unifying two systems: the Figma file's structure and the framework's layout vocabulary (columns, drawers, layouts, tokens in `styles/`). The layout-algorithm choices depend on how our columns resize and how drawers work, which the owner is not yet clear on: document those from the real code first (`core/Page`, `styles/layouts`, drawer/columns docs) so the mapping targets something known.
4. **Docs live on the module page.** Whatever module the owner names should hold its own documentation (its readme + `doc/`), so a question about it gets "here is what we did and where we are, click through". Make `ext/Figma` the model of that: readme index, observations, decisions, status.
5. **Open threads to link, not repeat:** the page-as-JSONL-views idea (item 5 in requirements.md), and the "code mastermind" discussion from earlier in the day (find its notes under `ai/` and `ai/doc/` and link them if they bear on code generation from designs).
