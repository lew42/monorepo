1. [fix] `ahead()` counts the turns waiting in front of a new ask as `queue.items.length` (Servex/ext/remote/RemoteMCP.js:419). But the SDK reads `queue.stream()` as soon as a message is pushed, so a message that arrives while the agent is working sits in the CLI, not in `items`. The CLI's own count is `queued_turn_count` (Servex/agents/Agents.js:2202). So when the voice mastermind is mid-turn and a minion's "done" message is already waiting, an ask gets `ahead = 1` when the true count is 2.
