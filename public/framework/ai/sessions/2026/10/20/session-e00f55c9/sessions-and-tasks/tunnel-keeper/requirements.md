# Servex keeps the Cloudflare tunnel up, and the owner can always find the current connector URL

Owner, 2026-10-20 (verbatim): "When I click the Servex MCP connector in the Claude app here, and I click the connect button, it says couldn't start sign in, try again. … I don't know if it's because the tunnel needs to be kind of updated. I think there was something about, you know, maybe the tunnel goes, like, dies at some point and then might get a new IP." Budget: $12.

## What is true

- `Server/Tunnel.mjs up` starts a free Cloudflare **quick tunnel** (`npx cloudflared tunnel --url …`) in front of a loopback gateway that passes only `/mcp/remote/<token>` to Servex (`Servex/ext/remote/RemoteMCP.js`). State in `%LOCALAPPDATA%\lew42\servex\remote.tunnel.json`, the full URL in `remote.url`, the bearer token in `remote.token`.
- Nothing supervises it. Today it had been dead since a pid from 2026-10-15; the connector in claude.ai still pointed at the old `*.trycloudflare.com` host, so "couldn't start sign in". The mastermind ran `node Server/Tunnel.mjs up` by hand at 15:05 (new host `library-trial-diff-patent.trycloudflare.com`, same token).
- A quick tunnel gets a **new random hostname every start**, so every restart silently breaks the saved connector. `%LOCALAPPDATA%\lew42\servex\cloudflare.env` holds `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` (never print them).
