# One mastermind role plus a path (agent-base items 11 and 13)

The owner's decision (2026-10-25): there is ONE generic `mastermind` role. Spawning it **at a path** loads that path's readme chain plus an optional `mastermind.md` into the agent's **system prompt** (so it survives compaction). "AI system mastermind" stops being a parentless singleton and becomes a normal mastermind spawned at `public/framework/ai/` by whoever needs it, parented to its spawner, its cost counted there. Servex checks at spawn that the files were loaded and logs which.

## What exists (read these first)
- `Servex/agents/readme-chain.js`: `readme_chain(dir)` returns the root-to-dir readmes; `first_prompt(dir)` formats them. Agents.spawn already prepends this to the FIRST MESSAGE for `spec.task.dir` / `spec.page` (`directory_of(spec)`, Agents.js ~230). The first message is summarized by /compact; the system prompt is not.
- `Servex/agents/roles.js`: `role_system(role)` builds the system-prompt `append` from the role readme + skills; `Agent.role_prompt()` (Agents.js ~1253) passes it to the SDK. The `ai-system-mastermind` row has `singleton: true, renew: {hours: 24, tokens: 100000}`; `singleton_id`, `renew_of` read them.
- Singleton and renewal code: Agents.js (spawn() ~142-153, wake() ~693-698, `renew_due`/`renew` ~1528-1565, ~1609, ~1631, `renew_why`/`renewal_text` ~2304-2315), `Respawn.js`, `policy.js` (SERVEX_ID), `ModuleInbox.js` (FEEDBACK_AGENT spawn, ~83/118), `Server/review.mjs`, `Server/role-spend.mjs`, tests `Servex/agents/singleton.test.mjs`, `roles.test.mjs`.
- Role docs: `Servex/agents/roles/ai-system-mastermind.md` (the role text, currently the singleton's), `roles/mastermind.md` (generic), `roles/readme.md` (index), `public/framework/ai/readme.md`.

## Build
1. **`path` on spawn.** `spawn_agent` (tools.js) and `Agents.spawn` accept `path`, a repo path or a site path (reuse `dir_of` from `directory.js`). Store it on the Agent and in the registry row/recipe so `wake()`/`revive()` keep it.
2. **System-prompt blocks.** `role_system(role, {path})` appends, after the role readme: `<path-readmes path="…">` (the `readme_chain(path)` texts, each headed by its repo path) and, when present, `<path-mastermind file="…">` with `<path>/mastermind.md`, else `<path>/ai/mastermind.md`. Same size cap as `first_prompt`. When `spec.path` is set, do NOT also prepend the chain to the first message (no duplicate); the first-message pointer says the files are in the system prompt, like `opening(..., {in_system})` does.
3. **Servex checks and logs.** At spawn, compute the list of files loaded; verify the final append text contains each file's text; write one line to the `skills` log (`where: "system"`, `path`, `files: [...]`, `ok`) and an agent event `path_loaded`. If a requested file is missing or not in the prompt, log `ok:false` with the names and tell the agent in its first message (do not silently continue).
4. **Retire the singleton.** Remove `singleton` and `renew` from the roles table and delete the code only they used (spawn() singleton block, `renew_due`, `renew`, the wake() renewal branch, `renew_why`, `renewal_text`, `singleton_id`, `renew_of`, the `renew` checks in nudge/sleep_compact, the singleton test). `ai-system-mastermind` stays as an ALIAS word of `mastermind` with a default path `public/framework/ai/` (a small `alias path` map in roles.js; a caller's own `path` wins). Its id becomes the normal `mastermind-<name>` (name from the path leaf, e.g. `mastermind-ai`, `-2` for a second). The live `ai-system-mastermind` session keeps running under its old id; do not touch it. `ModuleInbox` spawns the role with `path` and no parent (it is Servex itself) and tells the live one if it exists.
5. **Docs (same task).** Move the role text of `roles/ai-system-mastermind.md` to `public/framework/ai/mastermind.md` (the path's own file, `git mv`), edited to drop the singleton/renew language (a fresh agent per project; reuse only while the context is small, per `roles/mastermind.md`'s start-fresh rule), and leave `roles/ai-system-mastermind.md` as a 5-line pointer. Add a "Spawned at a path" section to `roles/mastermind.md` (what `path` does, the lookup order, the log line, how to read it). Update `roles/readme.md`, `public/framework/ai/readme.md` and `Servex/doc/*` where they mention the singleton. State in your final report, in plain sentences, exactly what changed in `roles.js` and the singleton code.
6. **Tests.** `node Servex/agents/roles.test.mjs` and the Servex agent tests pass; add one for `role_system(role,{path})` (blocks present, mastermind.md and ai/mastermind.md lookup, missing file reported) and one for the removed alias default path.
