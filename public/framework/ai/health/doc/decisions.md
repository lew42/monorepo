# Page health — decisions, numbers, and what was deliberately left

Built 2026-09-19, `public/framework/ai/2026-09-19/page-health/`. The brief:
[`requirements.md`](/framework/ai/2026-09-19/page-health/requirements.md).

## The mapping rules (`pages_for()` in `Server/health.mjs`)

A page's url IS the directory holding its `page.js` — there is no other routing table on a
no-build site. `nearest_page_url()` walks up from a changed file until a directory with a
`page.js` turns up (stops at `public/` itself, which has its own).

- A changed `…/page.js` → its own url (the walk starts at its own dir, which already has it).
- Any other file under a page's dir → that page (same walk).
- A shared module — path starts `framework/core/`, equals `framework/framework.css`, equals
  `app.js`, or starts `framework/ui/`, `framework/ux/`, `framework/ext/` — → the canary set
  (`/`, `/framework/`, `/framework/ai/`, `/framework/ai/v/3/`, `/framework/core/Page/`) plus the
  module's own page, own page first so it survives the 8-page cap.
- **Proved isolated, not just claimed:** a private copy of a shared-looking module, imported only
  by one scratch page, broke ONLY that page — zero canary checks — because the classification is
  by path, never by what a file's content looks like (2026-09-19 prove step).

Two path prefixes never get checked at all, `KNOWN_PAGES`: `/alex/ /arya/ /castin/ /edric/
/michael/` (the five personal sandboxes — error by design when crawled, the standing convention
several other tasks already document, `core/Page/tools/links.mjs`'s own `SKIP_TOP`). One resource
is ignored inside an otherwise-real page's findings, `KNOWN_REQUESTS`: `/layouts/verdicts.jsonl`
(the owner's own append-only file, absent until they press Approve/Improve once).

## Two console patterns are the watcher's OWN shadow, filtered before they ever become a finding

Blocking the dev socket (`context.routeWebSocket(/.*/, ws => ws.close())` — required by the brief,
so a checked page never keeps a live connection open after its context closes) makes
`dev/Socket/Socket.js` log its own reconnect-with-backoff warnings, and makes every
`JSONL.live()` on the page time out and fall back to `fetch()`, warning about that too. Neither is
a real bug — a real browser tab with the socket open never sees either — so both are filtered
(`KNOWN_CONSOLE`) rather than logged. Measured before the filter: every single page in a batch
carried 3–20+ of these, burying the real findings (2026-09-19).

## The blank-page check reads ALL `.page` elements, not the first

`core/Page/doc/data-children.md` (nested pages are peers via `display: contents`) means a routed
page's DOM holds several `.page` elements, not one — `.locator(".page").first().boundingBox()`
measured `null` on every page checked in this watcher's own first prove-step run, including pages
that were rendering fine, because the FIRST one in DOM order is often an inactive ancestor sitting
at `display: none` (the util-layer arrangement contract `css/caveats.md` warns about). The fix:
`page.evaluate()` finds the tallest VISIBLE `.page` among however many there are; "blank" is that
tallest height being under 50px, not the first match's box.

## Archiving — the owner's own bloat worry

New day file each day; at start (and once an hour after, on a day rollover), files older than 7
days gzip into `health/archive/`, files older than 30 days delete outright (archived ones too).
Proved with three faked day files (`2026-08-10.jsonl` 40 days old, `2026-09-01.jsonl` 18 days,
`2026-09-15.jsonl` 4 days): the 40-day file was gone, the 18-day file was `archive/2026-09-
01.jsonl.gz` (gunzips back to its exact original content), the 4-day file was untouched. A day
file past 2MB stops taking `warning` lines (errors keep recording) and says so once, to the
watcher's own console — deliberately never a new verb in the jsonl.

## `.gitignore` — the day files are disposable, the module isn't

`public/framework/ai/health/*.jsonl` and `.../archive/` are gitignored; `page.js`, `devbar.js`,
`log.js`, `health.css`, this readme and this doc/ are not. Decision logged in this task's
`task.jsonl` (`decision: health-gitignore`): a day file is machine-written console noise,
regenerated by just running the watcher, the same shape as `ai/usage.json` and the `shots/` dirs
— already gitignored for the same reason — never a human's own log line the way a `task.jsonl`
`log`/`decision` line is.

## The hook's exact contract (`health-guard.mjs`)

Wired beside `syntax-guard.mjs` in `ledger.mjs`'s `PostToolUse` handler, one try-wrapped line:

```js
try { (await import("./health-guard.mjs")).default(file, input.agent_id || input.session_id); } catch {}
```

On every `.js`/`.md`/anything `Edit`/`Write`: reads a tiny per-agent state file in the OS temp dir
(`claude-health-<agent_key>.json`, `{files: {relpath: isoAt}, reported: [...]}`), tail-reads the
last 64KB of today's health log (no Playwright, never more than a stat + a small read), and if any
file THIS agent previously wrote has an `error` finding newer than that write — and not already
reported — prints the `{"decision":"block", "reason": "…N seconds ago…"}` JSON the harness feeds
straight back to the agent. Every finding is reported once (a `reported` key of `at|file|url`).
Never throws — everything is inside one outer `try`.

**Proved twice.** Live, unprompted: writing a scratch page that threw got THIS agent blocked at
its very next write, automatically, before the prove step was even reached. Controlled, via `node
.claude/hooks/ledger.mjs post-tool-use` with fabricated per-agent state (two agent ids, one with a
write recorded before the real error's timestamp, one with no record at all): the first got
blocked with the right url/file/elapsed-seconds, the second stayed silent. (⚠ testing this by hand
through a shell: a JSON payload with a Windows path's backslashes gets one layer of escaping eaten
by the Bash tool — `code#7`'s own documented trap — so the file-based/forward-slash-path approach
above is what actually reaches `JSON.parse` intact; the first few attempts silently parsed to
`{}` and no block ever fired.)

## Two spacing lint checks (`card-word`, 2026-09-19)

`lint_findings()`, called once per page from `check_one()`, right after the blank-page check.
Both are WARNINGS (never `error` — they never block a write via `health-guard.mjs`, which only
acts on `error` findings), one combined `page.evaluate()`, capped at ten findings total so one
noisy page can't bury a batch the way the unfiltered console noise once did (`KNOWN_CONSOLE`,
above).

- **(a) a framed box holding text with under 8px of padding on any side.** "Framed" = a visible
  border, or a background different from its parent's — the same definition the `layout` skill
  already uses ("does this thing need a box"). "Holding text" = a direct text-node child, not
  just nested elements. Excludes the framework's own control family
  (`.btn, button, summary, select, textarea, input`) — a first pass with no exclusion flagged
  every button and inline `code` chip on the site (2–5px, correct by design, since a control's
  padding is deliberately its own small `em`) and buried the real card-shaped findings under
  that noise.
- **(b) more than eight sibling rows whose average vertical pitch exceeds 40px.** Pitch = one
  row's top to the next row's top (height + the gap after it), the single number a reader's eye
  actually judges list density by. Filtered first on the cheap `children.length > 8` check
  before any geometry, and rows that share a top (a wrapped grid, not a vertical list) are
  excluded from the pitch average.
- **Reads `getComputedStyle(el).paddingTop/Right/Bottom/Left` directly, not geometrically.**
  `--pad` and `--pad-card` both mix a `%` into a `calc()`, which only fails to resolve through
  `getComputedStyle` (reading back as the literal `clamp(...)` string) on a box with NO layout
  box yet — zero size, an inactive nested `.page` is the common case. Every candidate here is
  pre-filtered to `getBoundingClientRect().width > 0 && height > 0` — a real, painted box — and
  on a real box `getComputedStyle` DOES resolve to the used pixel value (verified 2026-09-19,
  `.claude/skills/css/caveats.md`). `parseFloat` is still guarded for `NaN` and the element is
  skipped, not flagged, if it doesn't parse.
- **Proven** on a scratch violator page (a 4px-padded bordered card, a 16px-padded control
  card, a 10-row list at 60px pitch, a 10-row list at 20px pitch — the first and third flagged,
  the second and fourth correctly not) and run against five real pages. What they found: mostly
  inline `code` chips at ~2–5px vertical padding (the same pattern on nearly every page — by
  design or worth a decision, not this task's call), five `.tab` elements at 2.4px vertical
  padding, and two findings that look like the real thing this check was built to catch —
  `core/Page`'s own `.ui-tree`/`.ui-tree-children` at 49–69px row pitch. One `.ai-highlights`
  wall on `/framework/ai/` measured 142.9px pitch across 41 items — likely a card wall rather
  than a tight list, flagged mechanically either way; worth a look, not necessarily a bug.
  Full numbers: `/framework/ai/2026-09-19/card-word/`.
- **A running watcher must be restarted to pick this up** — editing `Server/health.mjs` restarts
  nothing by itself (this module's own process, not a dev-server dependency, per the section
  above). Not restarted here: the never-kill/restart-the-running-watcher rule.

## What was left, and why

- **The dev-bar wiring itself** — fence (`dev/DevBar/**`), not a missing decision; the two lines
  above are the whole of it.
- **`.claude/skills/new-task/SKILL.md` still describes `note` as `/framework/ai/v/2/`'s own
  verb via a `Run` subclass** — that subclass is gone (this task made `note` a plain `TaskJSONL`
  verb, see `ext/JSONL/doc/task-jsonl.md`). Outside this task's fence (skills aren't in it); logged
  as a finding in this task's `task.jsonl` for the mastermind.
- **Two stray `action` lines landed in this task's own `task.jsonl`** (`.claude/skills/assistant/
  say.mjs`, `.claude/skills/minion/SKILL.md`) from a sibling minion sharing this session's
  `session_id` whose first edit had no `agent_id` pin yet — `ledger.mjs`'s own newest-task-dir
  fallback guessed mine. Documented in the task log rather than hand-edited out (`task.jsonl` is
  append-only).
- **`Server/health.mjs` isn't wired into `Server/run.js`** — on purpose, per the brief: it is a
  separate process, started by whoever wants it running, never a dependency of the dev server
  itself.
- **No nav link to this page from `/framework/ai/`'s own children list** — `public/framework/
  ai/page.js` isn't in this task's fence. The page loads clean at 1600 headless (proved,
  zero console errors, zero failed requests, real content) reached by its own url — the one
  documentation gap is that nothing a reader is already on links to it yet. One line fixes it:
  add `health` to `ai/page.js`'s `children:` string (currently every date this dashboard has, a
  space-separated list) — it already has a `page.js`, so this is the ordinary case, not the
  declared-child-without-a-page.js trap.
