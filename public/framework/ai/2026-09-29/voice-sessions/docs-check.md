# Docs check — voice sessions (ext/Session + Servex/agents)

Read only: `ext/Session` readme chain (via `load_module`), `Servex/agents/readme.md`, `Servex/agents/doc/directory.md`.

- **Contradiction on whether the directory mastermind exists yet.** `Servex/agents/readme.md` calls it "the not-yet-built directory mastermind" (in the roles-reconciliation line), but `doc/directory.md` describes `ask_directory` as a working, already-wired feature with real behavior, watch-outs and a code file (`directory.js`). An agent reading only the readme first would wrongly conclude the feature doesn't exist.
- **`session-fast` / `session-smart` are named but never explained.** `agents/readme.md` says roles were "reconciled 2026-09-29 with the per-voice-session pair (`session-fast`, `session-smart`)" but gives no description of what each does. The `ext/Session` readme separately describes "a fast assistant" and "a smart one" for voice sessions — nothing in either doc states these are the same two roles, so the mapping is a guess, not a documented fact.
- **`Sessions.js` (the actual voice-session server code) is named but not summarized anywhere loaded.** `ext/Session/readme.md`'s only mention is "It needs Servex (`Servex/agents/Sessions.js`, routes `/api/session/new|say|nav`)" — no description of what those three routes do, which agent role they spawn, or how they relate to `Agents.js`/`Dispatcher.js`. An agent asked to change voice-session behavior has to go read the source cold.
- **Whether the `session` id in `ask_directory({session})` is the same id as `Session.start()`'s `{session}` is never stated.** Both docs use the word "session" for what may be two different identifier spaces (a voice-conversation session vs. a directory-mastermind follow-up session) with no line connecting or distinguishing them.
- **No doc says who calls `ask_directory`, or when.** `doc/directory.md` explains the mechanics well, but not the trigger: is it `session-smart` deciding a question needs a folder-scoped answer? A human agent? This is the missing link between the two halves of this reading (`ext/Session` and `ask_directory`).
- **`ext/Session/doc/sessions.md` (file format + the two agents) is the one doc that would answer most of the above, but it's "on demand," not loaded by default** — reasonable for token cost, but means the readme alone under-documents the module for anyone who stops there.
- Minor: `agents/readme.md` is one long general-purpose file covering all of Servex's agent system (roles, wake, dispatcher, tools, experts, ops) with no subsection flagged for voice sessions specifically — the relevant pieces (roles reconciliation, `ask_directory` pointer) are single sentences buried among unrelated topics (jobs, module experts, the Dispatcher), making it easy to skim past them.
- Otherwise the two docs that were read are individually clear and consistent: `directory.md`'s five-step "how it works" and its comparison table against `ask_expert` are well organized and answer "should I use this or that" cleanly.
- `ext/Session`'s readme "Watch out" (Servex needs a restart to pick up the new routes) is a good, concrete trap and is exactly the kind of thing that would silently 404 for an unaware agent.
