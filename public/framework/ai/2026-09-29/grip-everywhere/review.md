1. [fix] `grip.css:270-276` (diff) deletes the `html.grip-sizing { --rail-ease: 0s; cursor: ew-resize; user-select: none; }` rule (and its comment) while adding the new `.grip-y` block in its place — the rule is never re-added anywhere else in the patch. That rule is what kills the shell's drag-easing lag, forces the resize cursor, and stops text selection during every drag, on the x-axis too. Losing it breaks deliverable 1's "byte-identical" promise for every existing caller (drawer, DevBar, Sidebar, Shell) — dragging any rail will now feel laggy (0.18s trail) and can select page text mid-drag. Grep confirms `--rail-ease` only appears once in the whole diff, as a deletion (`grep -n "rail-ease" diff.patch` → line 270 only, no `+` line).
2. [note] `rail.js`'s `size()` writes a saved localStorage height straight to `--sheet-h` with no clamp against the current viewport, unlike `handle()`'s `write` callback which clamps to `window.innerHeight * 0.92`. A height saved on a tall viewport (tablet landscape) and reopened on a short one (phone portrait) could set a `max-block-size` taller than the screen; since the sheet is `position: fixed; inset-block-end: 0`, a genuinely tall thread could push the sheet's top off-screen with no way to reach it. Worth a one-line `Math.min(saved, window.innerHeight * 0.92)` guard to match `write`'s own ceiling.
3. [note] `doc/decisions.md`'s own verification write-up says the touch proof measured a strip at "20px" for the 1.25rem coarse-pointer width, but `grip.css`'s touch block sets `width: 1.25rem` = 20px only at the browser default 16px root font-size — true in the test, but worth flagging since the file's own `rem` warning earlier ("the dev rail's text is 0.8rem…") shows root size assumptions have bitten this module before; no evidence here that it's wrong, just that the number is viewport/zoom-dependent and not restated as such.
