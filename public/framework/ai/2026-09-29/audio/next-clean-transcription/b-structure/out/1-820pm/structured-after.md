## Dictate
- At each stage of that refinement process, this should be built into the dictate documentation, UX, and the mobile rail where dictation happens — want to see a refined prompt, but also be able to dig back into the actual transcribed text [S45]
- As that system evolves, it's headed in the right direction, but will want a modular approach where each layer of the operation could be a different model and a different prompt, because it probably could or should be [S46]
  - Could have a smarter or faster model work from the cleaned-up state, as long as it's sure not to transform meaning [S47]
    - Don't want to switch words [S48]
    - Don't want to drop words [S49]
    - Don't want to really add words, except for a clear mistranscription, or where an extra word is more grammatically correct for fast speech [S50]
      - There are some strong use cases for slight tweaks [S51]
    - Generally the fast assistant's job is to transcribe/clean up the transcription quickly so the text gets on screen for the user as fast as possible [S52]
- In the dictate widget, want lower-level access to the raw Whisper transcription [S53]
  - So it can be understood a bit more, especially while streaming — want to see how it works [S54]
- Converting raw transcriptions into cleaned transcriptions is a good step for the fast assistant, so the UI shows the clean transcription instead of the ahs and ums [S55]
- The idea of strikethroughs and corrections was just to help visualize it, and that can still happen in debug mode, but it isn't necessary — call this "clean transcription mode" [S56]
