## Biggest finds

1. **The navigation-stability question is already answered, with numbers**: `/imagine/paging/navigation/` measured every mechanism (rail, reserved-height, reserved-tabs, full-screen-rail) at 1280 and 3440 and reports exact px moved. This is the owner's #1 navigation question ("is there persistent navigation") — already **decided** and documented, not open.
2. **`/layouts/` is the single existing "encyclopedia + decision" system** (naming law, `decide/` 5-question picker, `browse/` approve/improve wall, `explorer/` 3-pane tree nav) that a page-system README should link to rather than duplicate — it already does almost everything the owner described wanting for pages.
3. **Six realms moved wholesale from `/imagine/` to `/layouts/labs/` on 2026-09-18** (shells, screens, sections, blogx, mag, decks) and left 1-line redirect stubs behind — anyone reading `/imagine/` readmes today is reading stale descriptions of pages that no longer live there; the real content and current readmes are under `/layouts/labs/`.
4. **Two unrelated things are both called "sections"**: `framework/styles/sections/` is content bands *inside* one page (hero, pricing, faq — a "parts of a page" system), while `/layouts/labs/sections/` is *page-division* bands (2/3/4 column bands). The owner's own transcript flagged this ambiguity ("maybe that shouldn't be in layout... sections do need layout") — it needs an explicit decision, not just documentation.
5. **`/imagine/paging/templates/` and `/imagine/paging/make/` are the closest things to a "create a new page, pick its shape, save it" pipeline that already exists** (11 real-machinery templates, one editor that writes a page's 7 layout words into its own `page.json`) — likely the base to extend rather than build fresh for the new page skill/system.
