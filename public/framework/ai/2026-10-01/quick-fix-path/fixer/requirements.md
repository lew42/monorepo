# fixer — the standing warm quick-fixer, and the `quick_fix` door the voice session uses

Read first: `../plan.md` (the hot path and your fence), `../requirements.md`, `../owner-words.md` (the owner's own sentences; the test at landing checks them item by item).

## Fence
`Servex/agents/Fixer.js` (new), `Servex/agents/fixer.md` (its brief, new), small edits in `Servex/agents/Sessions.js` (the smart assistant's tools), `Servex/agents/session-smart.md` (one paragraph), `Servex/agents/Agents.js` only if a flag is needed, `Servex/Pool.js` (a `hold(id, by)` so the ten-minute sweep never reclaims the fixer's slot while it is held), `Servex/doc/fixer.md`, `Servex/agents/readme.md` (one line), tests beside them, and your own task dir. ## Build
1. **`Fixer.js`: one standing agent, `fixer-1`.** Started by Servex at boot like the fast assistant is (find how `assistant-fast` is kept and copy that), role `fixer`, Sonnet, effort `medium`, `permission_mode: bypassPermissions`, `cwd` = a qf slot it takes at boot (`pool.take("fixer-1")`) and HOLDS (`pool.hold`). Kept warm: whatever per-agent dormant time exists when you build (task-mastermind-dormant-idle's `minion-pm-ram` is landing `dormant_after` on `spawn_agent` today; if it is in, use it with a long value; if not, mark the fixer the way the fast assistant is kept from going dormant). After each fix it fast-forwards its slot to `michael/dev` (the pool already does this on take; do it after a merge too) so the next fix starts from the latest.
2. **`quick_fix` tool** for the smart assistant (register it where `session_line` / `session_summary` are): `{page, selection, text, session}`. Node writes `{"quickfix":{"asked_at", "page", "selection", "text", "session", "fixer":"fixer-1"}}` to `public/framework/ai/quick-fix/page.jsonl` (create the page: a `readme.md` of one line, a `page.js` that shows the last fixes with seconds and shot, and the `page.jsonl`; the page is declared by its parent `public/framework/ai/page.js` `children:` — add it) and hands the request to `fixer-1` with `send_to_agent` (priority `now` if the fixer is idle-chatting, normal otherwise). No spawn on the hot path. If the fixer is mid-fix, the request queues behind it; say so to the session in the tool's answer ("fixer busy, 1 ahead").
3. **`fixer.md`**, short, in the shape of `assistant.md`: you hold `<slot>`; the request names the page (`public/<page>/page.js` and its css) and often a `[Selected: label (selector)]`; edit the fewest lines; commit by exact path; run `MSYS_NO_PATHCONV=1 node Server/merge.mjs <slot path> --quick` and read its last JSON line (until `--quick` lands, run plain `merge.mjs`); post ONE line to the session (`session_line` or `card_reply` — whichever the fast assistant uses to talk into a session) with the seconds and the shot path, nothing else; append `{"quickfix":{"landed_at","sha","files","lines","width","ms"}}` — no: NODE appends it. The fixer's `merge.mjs` result is read by node in `Fixer.js` (watch the agent's tool result, or have merge.mjs's JSON line include `asked_at` passed through `--asked <iso>`), and node writes the landed line and `ms`. **Too big** (more than one module, a layout, a new feature, `sizeOf` = `full`, or the fix fails the smoke test twice): one line to the session saying so, `spawn_agent` role `task-mastermind` with the request verbatim and the page, and go back to idle; never stall.
4. **`session-smart.md`**: one paragraph under item 5 — a small, concrete change to the page the owner is on ("make this bold", "this gap is too big", a word, a colour, a size) goes to `quick_fix` at once, with the selection; the fixer decides if it is bigger. Everything else stays as written.
