## The pieces that already exist (read these first; the proposal composes them, it does not reinvent)

- **Selection**: `public/framework/ext/layout/` — `panel.js` owns `select($el)` / `deselect()` / `context(el, fn)`; `layout.js` decides what is selectable (a region, its direct items, items of nested regions — `doc/selection.md`); `body.js` draws the selection into the drawer: `head()`, `body()` (words + tokens + controls), `source($el)` = *the line that would build it* (`tag.c("words")`, from the classList). `ext/drawer/` is the rail itself (`drawer($slot, $body)`, pushes the page, only its ✕ closes; `--devbar` offset; `readme.md` "Watch out" has the resize/offset facts). `ext/Panel/properties.js` puts a selected panel's words in the same rail (`panel-focus` document event).
- **CSS provenance**: `public/framework/ext/CSSDoc/` — `cssdoc(target)` reads every rule that lands on an element out of the live CSSOM: selector, `@layer`, sheet href (or `<style>` when it was `css(\`…\`)` in JS — 14 of 72 sheets have no href), declarations, computed values per specimen. v1 documents one element type from a label; generalising to *the selected element* is its stated v2. `readme.md` "Watch out" lists the traps (detached elements, `:where` splitting, no line-number API).
- **The layers as parts**: `framework.css` (base + util vocabulary), `styles/layers/theme/lew42/lew42.css` (theme), `public/styles.css` (site skin), a module's own `View.stylesheet(import.meta, "x.css")` or `css(\`…\`)` (component). `styles/css-scopes.txt` maps class prefixes to owning modules. Every rule lives in `@layer base | theme | site | util` (CLAUDE.md). So "which part is this from" is answerable from a rule's sheet href + layer + class prefix — the data is already in the CSSOM.
- **JS provenance**: no source-map; but a View knows its module when built through `Page`/`Doc` (`meta: import.meta`) and `View.stylesheet(import.meta, …)` records the sheet's owner. `directory.json` lists every file. `ext/Doc` renders a module's files/methods (`/framework/ext/Doc/`).
- **The two-up**: `ext/demo/twin.js` + `two.js` (a 390 phone beside a 3440 monitor, both live) — the owner found only the LEFT pane selectable. Find why (a `layout.selectable` scope? the right pane out of flow / zoomed? the `context()` registration on one pane?) — a file:line diagnosis, and whether it is a one-line fix.
- **DevBar AI context**: another minion (`../ask-tab-binding/`) is, right now, binding the AI turn to its tab and — as a stretch — passing the current selection into the turn's context. Do not build that; name the one contract it should read (`layout/panel.js`'s `$sel`? a `layout-selected` class query? a document event?) so both proposals agree.
- Today's parallel reads: `../css-audit/` (Opus, reading every CSS file — its `audit.md` may exist by the time you finish; cite it if so), `../panel-complexity/`.
