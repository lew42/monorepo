## The model (the mastermind's reading — make it true, or refute it in your log with a measurement and do the smaller thing)

1. **Default = flow.** `Panel.defaults.h` becomes `hug` (auto: the box is its content), `w` stays `fill`. A floor so an empty panel never collapses: one token, `--panel-min` (pick the number by looking — the Demo's blank starting leaf must still be a box you can aim at; say it in `doc/sizing.md`), applied as `min-block-size` on a hugging panel. Saved documents that never wrote `h` now read `hug` — state in `doc/decisions.md` what changes for the owner's `/data/panels.json` and why that is right (the owner's words above); never rewrite that file.
2. **A workspace root.** `mode: fill` (the app-layout word) keeps today's screen-filling behaviour — the root fills the workspace box and its children fill heights; `mode: document` keeps its stack of hugging sections (`--panel-section` floor) inside a root that fills and scrolls. A **bare root with no workspace height** (the Demo panes, `panel(seed)` anywhere that stops passing `--panel-height`) hugs. Decide the smallest rule that makes `.panel-workspace`'s height follow the root when the root hugs (`height: auto` when no `--panel-height` is set? a class the root writes?) — measure it: a demo pane's workspace must read exactly the root's height, and the playground's must still be the window.
3. **Adding inside grows.** A split (edge click), an `add`, a drop, a `cells` template, typing more text — inside a hugging panel, each grows the panel and its hugging ancestors by what it added; nothing scrolls or crops unless a `fixed` height or a `fill` root says so. The `flex: 1 1 0` chain in `panel.css:15` is where this is lost for a hugging axis — `size.css` already restates `flex-basis: auto` for `.panel-h-hug`'s child; finish the job for whatever else zeroes it, with the fewest rules.
4. **Edge handles — ONE surface, three gestures.** The right and bottom edge strips every panel already has (`split.css`'s `.panel-edge-r` / `.panel-edge-b`) become: **click = split** (today, unchanged), **drag = resize** (a pointerdown that moves ≥ 4px before pointerup is a drag, never a split — a ghost preview must not appear for a drag), **right-click = reset** (the axis returns to its default word: `w: fill` / `h: hug`; it still cancels a live split preview as today). A drag on the right edge writes `w: fixed` + `w_at: <length>`; the bottom edge `h: fixed` + `h_at`. Write the length in **`em` of the panel's own font size** (round to 0.25em) so the arrangement survives a zoom and a 3440 screen — say why in the doc. Top/left stay split-only (the owner: they would not work in flow). Live while dragging (write the custom property each move), commit on pointerup through `item.set()` (persist + one repaint), exactly as `grip.js` does for ratios. The handle must be reachable on a ROOT (the Demo panes: no seam, no sibling — the owner's first line) and on a nested panel; a seam grip (sibling ratio) and an edge handle (own size) never overlap — measure at a nested panel's right edge that is also its parent's seam, and say who wins where (`split.css`'s `--clear` is the precedent).
5. **Demo tab.** `demo/page.js`'s `pane()` stops forcing `--panel-height: 20em` — the panes hug with the floor and grow as the reader follows along; the guide pane's recorded flows still replay (flow.js snapshots carry data, not heights — verify one). If a particular demo needs a starting height, say so per demo, not globally.
