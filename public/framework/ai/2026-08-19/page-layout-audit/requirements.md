## Seed — already measured, don't redo (mastermind, this morning)

`container()` ([core/Page/Page.class.js:160-168](/framework/core/Page/Page.class.js)) picks the box: `parent.regions.get(name)` (set ONLY by `ext/tabs/tabs.js:28-29`, every name → the same `$panel`) → nearest ancestor's `$pages` (set by `ext/catalog/catalog.js:52`, `core/App/App.js:44`, `ext/demo/app.js`, and ~8 `render()` overrides) → `app.$pages`. Visibility is then pure CSS: `Page.css:8` `.page:not(.active-page, .active-ancestor:has(.page.active-page), .default) { display: none }` — an ancestor stays visible only if the leaf is INSIDE it (tabs/catalog) and is replaced if the leaf is a SIBLING (app.$pages).

`--measure` placement, mixed: `Page.css:21` on `.pages` (region) AND `Page.css:79` on `.page` (every page, re-declared because `min(none, …)` drops the grid template); `tabs.css:68` `.tab-panel` (region) · `ext/demo/app.css:58` `.demo-app-pages` (region) · `Doc.css:14` `.page.doc-page` · `DesignTool.css:77` `.page.dt-page` · `styles/layouts/layouts.css:19` `.page.layout-full`. Because `.page` re-declares `--measure`, a region-level `--measure: none` never reaches a nested page's grid — it only reaches non-page readers (`demo.css:81`, `Research.css`, `rank.css`, `framework.css:430 .measure`). `--page-pad` DOES flow region → page (`.page` reads `var(--page-pad, …)` without declaring it). Five modules undo the page shell, each differently.

## Questions — answer each, in this order

1. **Containers.** Every box on the site that holds pages (`.pages`, `.tab-panel`, `.page-catalog-pages`, `.demo-app-pages`, Panel workspace, columns, anything else): selector, file:line, and the inset/measure/min-height it declares. One table.
2. **Shell variants.** Every way a page sets its own box: the default grid (no class); `classes:` words (`standard full fill solo wide bleed` + any others you find); `render()` overrides (how many, one line each on what the override does); per-page token resets. **Two numbers that must agree:** `render(){` overrides found by `grep -rn "render()" --include=page.js` vs by `grep -rn "this.view ??=" --include=page.js` (explain any gap).
3. **Tokens.** `--measure --page-pad --gutter-x --pad-y`: declared where (region vs page), read where, and which declarations are dead. **Prove one dead one** with a single headless `getComputedStyle` read (the `site` MCP `eval`/`shot` tools, or Playwright from the scratchpad — name the script `page-layout-audit-probe.mjs`; memory says a Playwright import path must be `file:///C:/...`). Paste the number.
4. **"full" — the regions that could be replaced.** Viewport · `app.$pages` (right of the site sidebar) · a Doc's tab panel · a catalog's `$pages` · a Panel workspace. For each: the mechanism that exists today (`full`, `fill`, `solo`, `layout-full`'s `position: fixed`, Panel's own), what nav it loses, and whether Back still works. The test case: read `ext/Panel/Workspace/page.js` and `ext/Panel/demo/page.js` and say in ≤ 5 lines what "fullscreen" for a workspace would need — without removing the site sidebar (the owner keeps it).
5. **The simplification, costed.** The owner's sketch: a `.page` is a plain div that fills the region's width; `.standard` (or `.grid.standard`) is OPT-IN and gives `main / wide / bleed`; the REGION owns inset and measure, so `--measure` on a parent's `$pages` becomes a real default for its subtree. Count: pages that rely on the default grid with no class · pages carrying `full/fill/solo` · pages with a `render()` override · CSS rules that would need to move. Say what breaks, what the migration is (a class on N pages? a sed? a one-line `render()` default?), how to dodge the `min(none)` trap once `.page` stops re-declaring `--measure` (e.g. the region sets the template, or `--measure: 100%`), and end with a one-line verdict. **A proposal — do not touch `Page.css`.**
6. **The docs, as a new user.** You land on `/framework/core/Page/`. Propose: the Overview as a VISUAL, BROWSABLE grid of page examples (model: `/framework/styles/layouts/` — `browse()` rail + wall; read `styles/layouts/page.js` and `ext/catalog/browse.js`), the top tabs, and the left-rail items under each — one line per page on what it must SHOW (a live `demo.app()` beats a paragraph). CSS and layout first; JS examples last. Must cover: the tree / children / navigation ("pages are navigation") · where a child mounts (`regions` → `$pages` → `app.$pages`) · the arrangement contract (replace vs keep; two classes, one CSS line) · the shell (`main/wide/bleed`, `--measure`, `--page-pad`, `--gutter-x`) · `full`/`solo` and the regions from Q4 · the nav ladder (top tabs → left rail → ?).
