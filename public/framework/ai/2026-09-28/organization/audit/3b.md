# 3b — every way to create a page

Read as a new user: `Page.class.js`, `Log.js` (`core/Page/jsonl/`), `doc/jsonl.md`,
`doc/declaring.md`, `doc/data-children.md`, the `readme.md`, the `overview/route/` and
`overview/children/` demo pages, and `ai2/page.js` + `ai2/card.js` as the real-world dynamic case.

## Findings

- **missing** — [readme.md](/framework/core/Page/) "Use" section shows `page.js` and
  `page.jsonl` but never mentions `route()` (the third way), even though a working demo of it
  already exists one click away. Source: `public/framework/core/Page/readme.md` lines 11–34.
- **missing** — no doc anywhere in `core/Page/doc/` describes the "index page with no folder"
  pattern the owner named by name (AI 2's `board.jsonl`/card folders). `doc/data-children.md`
  documents a *different* mechanism (`children` as a function) that neither AI 2 nor any live
  page actually uses for this. Source: `public/framework/core/Page/doc/` (whole dir), vs.
  `public/framework/ai2/card.js:182-190,970-980`.
- **buried** — `jsonl` is a top nav item (`children: "generator old jsonl/page.jsonl"`,
  [page.js](/framework/core/Page/) line 34) but is **not** in the Overview palette's `BANDS`
  (`page.js` lines 20–25), so a reader browsing "what can a page be made of" at
  [/framework/core/Page/overview/](/framework/core/Page/overview/) never sees it — the palette
  is the one-click-in map and jsonl isn't on it.
- **unlinked** — [`jsonl/readme.md`](/framework/core/Page/jsonl/readme.md) is a one-line stub
  ("more to come") and the parent readme says so too ("no readme yet") — it's the one live demo
  of `page.jsonl` and it explains nothing beyond what `doc/jsonl.md` already says better.
- **wrong (confusing, not incorrect)** — `route()`'s real job spans two very different scales:
  the textbook case (`overview/route/page.js`, three fixed names) and AI 2's case (`card.js`
  `route()`, ~460 lines away, building a `Card` from a JSONL file per id, memoised, with
  `Card.Folder` walking `2026/09/24/` segments beneath it). A reader who reads the simple
  `route()` demo has no path to "oh, and here's how a whole live system is built this way."

## Simplest first

1. **`page.js`** — already right in the readme: a folder + one file, `children: "intro guide api"`.
   No change needed.
2. **`page.jsonl`** — already right: `{"title": "Notes"} / {"place": "note.md"}`, two lines,
   in the readme's own "Use" section. The live demo at
   [/framework/core/Page/jsonl/](/framework/core/Page/jsonl/) should be the *simplest possible*
   file (title + one placed file) — right now it also carries `child/page.jsonl`, a `gone: true`
   line and `later.md`, which is the FULL feature tour, not the "first thing you'd write." Move
   the extra lines to a second example, keep this one to the two-line case.
3. **`route()`, small** — `overview/route/page.js`'s Wiki demo (three fixed names) is already the
   right size and already the simplest form. It just needs the readme to point at it.
4. **`route()`, as an index of folders (the AI 2 pattern)** — no minimal version exists anywhere.
   The smallest real piece of it is `Card.Folder.child()`
   (`public/framework/ai2/card.js:970-980`, `async child(name, levels){ … Card.jsonl(...) }`):
   read a name, build the next page from a matching folder, no probe. Worth extracting as its own
   ~10-line demo: "a page whose children are folders on disk, read by name, no `children:` list."

## Suggested structure

Keep the "Pages are navigation" band in the Overview (already right: `page children mounts
replace route labels`). Add:

- **`jsonl`** into that same band (or its own small band) so it's visible on the wall, not only
  in top nav.
- A new overview card, **`folders`** (or **`index`**) next to `route`, showing the AI 2 pattern
  at demo scale: a page whose `child()` reads a folder per name instead of declaring `children:`.
  This is the concept the owner asked for by name ("dynamic pages where we don't actually have to
  create a new directory") and it deserves its own named, linked concept page — it is genuinely
  different from `route()`'s fixed-name case and different again from `data-children.md`'s
  `children` function.
- Leave `data-children.md` as advanced/reference material linked from the new `folders` page,
  not the front door — it is real but it is not what AI 2 actually uses.

## Value per space

1. `page.js` — fundamental, trivial to show, already good. Keep as-is.
2. `page.jsonl` — fundamental, cheap to show once the demo file is trimmed to 2 lines. High value.
3. `route()`, fixed names — fundamental (every catalogue-style url on the site uses it),
   cheap to show, already has a good demo. Just needs a readme mention. High value.
4. **The folder-index pattern (AI 2 / board.jsonl)** — fundamental to how the biggest, newest
   part of the site works, but currently has no small form anywhere. Worth the space: it's the
   pattern the owner explicitly asked to have "documented thoroughly."
5. `children` as a data source (`doc/data-children.md`) — real and well-written, but describes a
   mechanism nothing on the live site currently uses for the "index with no folder" case. Lower
   priority: link it as the deeper/advanced option, don't lead with it.
6. `Page.from()` / `page.json` (`Page.class.js` lines 403-457) — a third, separate "data
   describes a page" mechanism, used by nothing live today per its own comment. Too obscure for
   a concept page; one line and a link is enough.
7. The `.md`-file-becomes-a-page fallback (`declaring.md` "A .md file is a page") — fundamental
   (every doc link on the site goes through it) but already documented adequately in
   `doc/markdown.md` / `doc/open.md`. No new space needed.
8. `depth` / `leaf` (lazy loading) — important but it's a *tuning* concept on top of "how pages
   are made," not a fifth way to make one. Keep it where it is (`doc/declaring.md`), don't
   duplicate into the ways-to-create list.
9. `Card.Folder`'s year/month/day walk (`card.js:964-1046`) — too specific to AI 2's own
   calendar shape to be a general page-creation concept; mention it as an example inside the
   `folders` concept page, not its own page.
10. Confusing/low value: the distinction between `route()` on `this` vs. `route()` as a
    `regions`-backed tab (`card.js` `tiny()` / `tab_route()`) — powerful but AI-2-specific
    plumbing, not something a new Page-system reader needs on their first pass. Leave it in
    `ai2/doc/`, not in `core/Page/`.
