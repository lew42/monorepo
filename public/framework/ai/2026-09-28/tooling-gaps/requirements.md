# Tooling gaps: a lost done-event, and a merge with no smoke test

Reported by task-mastermind-organization on 2026-09-28.

1. **A child admitted through the memory gate never wakes its parent.** A child spawned while queued behind the memory gate ran and finished, but its done-event never reached its parent (organization found it 6 minutes later via /agents). Check `admitted()` in `Servex/agents/Global.js` and `Layers.js`, and the gate's spawn path in Servex: `parent`, and the wake it drives, must carry into the real spawn. **Proof:** on a private Servex with a tiny `SERVEX_MIN_FREE_MB` override so the gate holds, spawn a child with a parent; when it's admitted and finishes, the parent gets its one wake message.
2. **merge.mjs can't smoke-test a pool worktree.** `smoke.mjs` finds a worktree's port only in `.worktrees.json`, so a Servex pool worktree (qf-1) fails with "no worktree entry". Organization then merged with `--skip-smoke`, so nothing was tested. Ask Servex for a pool worktree's url (the `take_worktree` record, or `GET /worktrees`). `--skip-smoke` must require a `--why` and log it. **Proof:** merge.mjs smoke-tests a qf-N worktree for real.

**Fence:** `Servex/agents/Global.js` and `Layers.js` (the admitted path only), the gate's spawn in Servex, `Server/merge.mjs`, `Server/smoke.mjs`. Servex/agents also has uncommitted edits by mastermind-servex-3 (the holder alias and the reaper), and recursive-pairs works there too; merge with them and don't overwrite. Prove it on a private Servex, then restart once when few agents are working (that restart also brings in the queued holder and reaper fixes; see ai/2026-09-25/servex-mastermind/dispatch.md).
3. **merge.mjs's fallback leaves a clean branch uncommitted.** When some unrelated main-tree files hold other agents' unsaved edits, merge.mjs falls back to a working-tree merge and leaves the commit to the owner. The merged files then sit uncommitted and block the next merge (09-28: collab-rounds' branch became 12 conflicts for review-turns). The fix: commit only the branch's own files, by exact path (`git commit -- <paths>`), and leave the others' dirty files untouched. Refuse only when one of the branch's own files is dirty in the main tree, and name that file. **Proof:** a merge with an unrelated dirty file in the main tree ends with `git status` showing none of the branch's files.
