## What lands (closed list)

1. **`wrangler.dev.jsonc`** at the repo root — `main`, `run_worker_first: ["/api/*"]`, `assets` → `./public`, a D1 binding, a DO binding for `Room`, `vars: { DEV_LOGIN: "1" }`. ⚠ **Never add `main` to `wrangler.jsonc`** — that file deploys on every push. Diff it at the end to prove it is untouched.
2. **`worker/`** at the repo root (NOT under `public/` — it is not an asset): `index.js` (routes `/api/*`, everything else 404 → assets), `session.js` (HMAC-SHA256 sign/verify with WebCrypto, the `token_epoch` payload, cookie flags from `/notes/auth/` §3), `dev.js` — the DEV ENTRY: `wrangler.dev.jsonc`'s `main` is `worker/dev.js`, which imports `worker/index.js` and adds the one route `/api/dev/login?as=<handle>`; `worker/index.js` never imports `dev.js`, so the production entry cannot contain the route (identity.md ruling 3 — a build-time absence; `env.DEV_LOGIN === "1"` and a `localhost` host check stay as belt, never as the gate), `me.js` (`/api/me` → `{ handle, roles }` or `{ anonymous: true }`), `can.js` (`can(user, action, url)` — the ROUTER calls it before any handler, per identity.md ruling 4; the six rules from its table, nothing more), `room.js` (the `Room` Durable Object: hibernatable WebSockets, one SQLite table of deltas, `getByName(url)`, broadcast to `ctx.getWebSockets()`, resume by row id), `schema.sql` (the `users` table from `/notes/auth/` §4, nothing more), `seed.sql` (five fake users: alice owner, bob moderator, carol member, dave member, eve banned). Zero npm dependencies — WebCrypto and the bindings only.
3. **`dev.mjs`** at the repo root + `"dev": "node dev.mjs"` in `package.json` `scripts` (the only package.json change; no dependency). Spawns `node server.js` on `PORT` and `npx --yes wrangler dev -c wrangler.dev.jsonc --port 8787`, prefixes output, kills both on Ctrl+C. ⚠ For YOUR run, use a private `PORT` (rules file) — never 80.
4. **The room test** — a `ui-test`-style script in your task dir (`room-test.mjs`): two Playwright contexts against `http://localhost:8787`, alice and bob log in via the dev switch, both open `/imagine/platform/local/room/` (a page that connects to `/api/room` for its own url), alice sends a message, bob's context sees it within 2 s; eve (banned) is refused; an anonymous context reads but cannot send. Screenshots of both contexts side by side, saved in your task dir and linked.
5. **`public/imagine/platform/local/page.js`** — the demo page: how to start it (`npm run dev`), what it proves, the screenshots, and the three assumptions' results (verified / refuted, with the evidence). Plus `local/room/page.js`, the room page — it renders WITHOUT the API (the socket is additive; a failed connect shows one muted line). The mastermind wires `local` into the hub — do not edit `public/imagine/platform/page.js`.

## Test first

The foot of local-dev.md names three unverified assumptions (wrangler + node coexistence; the dev socket in a `:8787` tab; cookies on a cross-port WS handshake). Test each before building on it, log the result, and change the design where one fails — a refuted assumption is a first-class result.

## Fences and rules

Write only: `wrangler.dev.jsonc`, `worker/`, `dev.mjs`, the one `scripts.dev` line in `package.json`, `public/imagine/platform/local/`, this task dir. Never `Server/` (the loopback gate lives there), never `app.js`, never `core/`, never `wrangler.jsonc`. No `wrangler login`, no account, no deploy — `wrangler dev` is fully local (`.wrangler/state/` — add it to `.gitignore` if it is not there; that one line is allowed). Kill every process you start. Budget ~300k tokens; if you must cut, cut the anonymous case, then the banned case — never the two-context message.
