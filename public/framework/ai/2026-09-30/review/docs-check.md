# Review docs check

1. Overall it makes sense: shots are taken before the reviewer starts, the report goes to a fixed path, and the question list regenerates itself — nothing hand-typed to go stale.
2. Taking shots is clear only from `Server/doc/review.md` (the exact `layout-check.mjs --bands` command, run by the mastermind before turn 1) — `.claude/skills/review/SKILL.md`'s "What you are given" just says the shots "come from" that command, without saying they're already done by the time the reviewer opens the skill; a reviewer reading only SKILL.md could wonder if it must run the command itself.
3. Where the report goes is under-stated in SKILL.md: it always says `<taskdir>/review/report.md`, but `Server/doc/review.md` says a diff that touches no page instead gets the plain `<taskdir>/review.md` — SKILL.md never mentions this second path or the condition that picks it, so a reviewer following only the skill would write the wrong file on a no-page review.
4. How the questions stay current is clear and well-linked: `public/framework/ai/review/readme.md` explains the `N. <question>? [<skill>: <rule>]` format and that `--questions` (also run at the start of every real review via `main()`) regenerates `questions.json` from each skill's `questions.md`.
5. `public/framework/ai/review/readme.md`'s "Watch out" section is unusually detailed for a readme (three parsing edge cases: nested brackets, markdown links, no-URL skill paths) — useful, but arguably doc/decisions.md material rather than the reader's index.
6. SKILL.md's "Load first" step 2 links to `page`, `layout`, `css`, `content` questions.md files but not to a `navigation`-named file, since Navigation is a section inside `page/questions.md` — consistent with the readme's "nine systems... read live from the skills' own rules," but worth a reader double-checking the section headers rather than expecting one file per system.
7. Nothing is missing for the size/who-reviews decision (`none`/`light`/`full` in `Server/doc/review.md`) or for the merge gate (`Server/merge.mjs` refuses on no review or an unanswered `[fix]`) — both are explicit and cross-referenced.
8. `Server/doc/review.md`'s "Later, not now" (`--model` for a non-Claude reviewer) and "One review pass at a time" (finding numbers not scoped per pass) are honestly flagged as known limits, which is good practice and needs no change.
