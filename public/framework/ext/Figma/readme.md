## Component strategy (current, 2026-11-12)

This is the current truth. Where an older line below contradicts it, that line is marked superseded.

1. **Templatize every duplicate.** Repeated things are instances of one master, unless the copy will be transformed completely ([layer rule](#the-layer-rule-and-the-grids-page-owner-2026-11-12)).
2. **Instances get content overrides only** (text, image, boolean, swap). Never restructure an instance's slot per use; that is what left hundreds of untemplated cards.
3. **A new kind of card or panel is one generic Card shell plus a purpose content master (option D)** (updated 2026-11-12 from a finished test, [Card strategy page](https://monorepo.lew42.com/live/plan/figma-components/), Figma 477:44553; shell 491:10452, content master 491:10451): place a content master (e.g. "Newsletter content") as ONE instance in the shell's Content slot. In the test D followed everything: template reorder or add, base shell padding, radius, and per-card text survived. It costs one more layer (title depth 4 vs 3), but Ctrl/Cmd-click edits the title in 1 click either way. The earlier recommendation, a **rebase** (B: duplicate the base, detach, make a new master such as "Card · Newsletter", re-make the Content slot with `createSlot()`; [slot traps](./doc/use-figma.md#traps), [Flow traps](#the-flow-page-mine-2026-11-11)), lost base padding changes; keep it as the fallback when the shell's structure itself must differ. The base stays thin and fully tokenized. Census: [doc/card-census.md](./doc/card-census.md) (1,265 Card copies, 217 placed by hand, about 8 content masters to make: Basic, Media top, List panel, Rows, Form, Quote, Stat, Toolbar).
   - **Never repeat loose layers inside a slot; repeat an instance.** Editing loose slot layers makes the copy own the whole slot (confirmed); editing text inside an instance in the slot overrides only that text and the slot keeps following (confirmed: a slot gap change reached all D cards).
4. **Most content areas are a slot** (owner, 2026-11-12: "Generally, most content areas should be a slot."): page body, card, panel or section content. Only fixed-structure templates (avatar card, list row, stat) have no slot; they use fixed layers plus text, boolean and swap properties. So: a content area is a slot, a fixed-structure template is not (but see item 12: no component whose only job is one slot).
5. **Tokens keep values in sync; components keep structure in sync** (layers, order, nesting, layout direction). Make a component when there is no token for what must change everywhere. The edge treatment (radius token, shadow as an effect style, fill token) keeps rebased cards in sync; clip and layout direction are the parts that can't be tokens ([Image radius](#the-card-system-pages-voice-apps-listed-2026-11-10), [Scheme contrast](#scheme-contrast-owner-feedback-2026-11-12-ui-kit-one-card-four-schemes)).
6. **Modes for values that should change for everything inside a frame** (theme a section, size or density). A single background is a direct fill (e.g. Colors `light`), with no mode, so the children don't have to be flipped back ([demo backgrounds](#the-layer-rule-and-the-grids-page-owner-2026-11-12)).
   - **The nearest explicit mode above a layer wins** (owner, 2026-11-13, tested on the v2 Scale page "Mode cascade: who wins?", 5 cases; [test](https://www.figma.com/design/ADpu9u2V0BlEZfR3rrMfER/Lew42-v2?node-id=19-449); detail: [doc/modes.md](./doc/modes.md)): it wins whether it was set in the master or on the instance, and an instance override on a layer beats later master edits to that same layer. **Practice: set NO modes on layers inside a master, and set the size mode only on an instance's OUTERMOST frame. Keep labels outside the instance so they don't scale.** Master edits, including newly added layers, then follow at the instance's size. (Case 4: the master set SM on its inner cards and the instance set LG on the Stack around them; the cards stayed SM because their own mode is nearer.)
   - **Scale is one switch per design** (owner, 2026-11-13): "Scale is one switch per design: set it on the outermost frame. The only other place is a major region that acts like its own small page, e.g. a sidebar column set to SM. Never set Scale on individual cards, buttons or sections, and never inside a master; a mode is absolute, so it would stick at every size. Relative sizing comes from role tokens in Scale (pad, section-pad, button-pad, text-gap), not from modes."
   - **Refined 2026-11-13 (owner, tested on V2 at 2600 with two sidebars): Scale goes on REGIONS and matches the region's own width:** the root frame, plus each column. E.g. a 2600 layout with a ~1700 centre column set to LG and sidebars set to SM. Never on cards, buttons or inside masters.
   - **Scheme goes on the thing that should LOOK different** (owner, 2026-11-13): a card, or a band that should flip as a whole (a dark section). A container's background is a direct fill (e.g. Colors `light`), not a Scheme mode, so its cards don't inherit its colour by accident.
   - **Note:** Figma only offers a mode on a frame when something inside it is bound to that collection, so an empty frame shows no Scale option.
   - **Superseded 2026-11-13** (see the lines above): **Put a mode on the exact layer that should change** (owner, 2026-11-13; detail and escape hatches: [doc/modes.md](./doc/modes.md)): "Masters carry no explicit modes, so they render at the default. Put a mode on the exact layer that should change (e.g. the card inside an instance), never on a wrapper or the instance root, because a mode cascades into everything under it, labels included."
7. **Variants only for differing structure,** in a set named "X Set". Properties don't cascade; expose nested instances to show a child's properties on the parent ([Pills](#the-pills-page-mine-2026-11-10), [icon system](#the-icon-system-mine-2026-11-10)).
8. **Where masters live:** a repeat in one place only means the first item is the master; anything reused goes on its family page in the design system, and previews hold instances ([component pages](#component-pages-column-masters-workspace-owner-2026-11-10)).
9. **The layer rule:** text uses approved styles, everything else is an instance, and layout frames are the only loose layers, inside a parent component ([layer rule](#the-layer-rule-and-the-grids-page-owner-2026-11-12)).
10. **Agents edit the master, never an instance-then-push.** Screenshot, then wait for the owner's approval. The Lew42 Design System page is the approved set ([owner's direction](#notes-from-your-asks)).
11. **Grids:** no grid components (a frame with a bound gap; the card is the component); `.grid.gap`, not `.grid.cards` ([Grids](#the-layer-rule-and-the-grids-page-owner-2026-11-12)).
12. **Templatize, but don't add nesting without a really good reason** (owner, 2026-11-12): "Always create things in a templatized way when possible. But don't create extra nesting without a really good reason: wrapping a component in another instance just to templatize it costs extra layers to dig through, and it gets confusing which layer you have selected. A component whose only child is a single content slot is maybe a smell: do we really need a component for that one layer of styling?"
13. **Don't map every Figma feature to a mode, variable or property** (owner, 2026-11-12): "It creates extra work and gives you nothing extra." The card padding switch was added, removed and brought back; don't do that.
14. **Image cards are full bleed** (owner, 2026-11-12): "A padded image is no bueno. If a card has an image, it's full bleed, edge to edge, and the text sits in a padded Content slot beside it." The Content slot is the padded area where text is dropped; it can switch colour modes ([Image cards](#the-card-system-pages-voice-apps-listed-2026-11-10)).
15. **Refine, don't accumulate** (owner, 2026-11-12): "Part of the problem with our whole system is that there are too many things. We keep creating more and more, and we're not refining it into the basic system. There are too many colour tokens." Before adding a token, component, mode or property, check whether an existing one covers it; prefer removing over adding.

16. **Grids are not components** (owner, 2026-11-13): a grid is a fundamental layout frame whose control point is the gap token, so a component adds nothing. A higher-level master (e.g. a whole page wrapped in a master for previews) already templates the layout inside it. Don't pre-build every grid permutation; a small layouts reference with blank cards is enough.
17. **A master feeding a component set buys one extra layer of inheritance** (owner, 2026-11-13): a base master nested inside each variant means base edits reach every variant and every instance of every variant. A test is running on the Images page.
18. **Rebase by paste** (owner, 2026-11-13): copying a component set, or a master+set system, into another file creates brand-new masters, already wired to their instances. It's the quickest way to start a new, separately editable template from the design system. Within one file, there's no easy way to duplicate a master with its instances rewired.

## Plugin ideas

- **Duplicate as new master** (owner, 2026-11-13): duplicate a master (or a component set, or a master+set system) in the same file, rewiring the copies to the new master. Today that takes detach, re-make and re-link by hand, or a paste into another file (item 18).

## Classes

- `Figma` (`Figma.js`) — the system; `Figma.files()` loads every tracked file from `index.jsonl`; `files_sync()` is the one blocking read a cold deep link needs.
- `FigmaFile` (`FigmaFile.js`) — one tracked file: key, name, pages; reads `data/<key>/pages.jsonl` (newest line per id wins); gives every page and frame its slug.
- `FigmaNode` (`FigmaNode.js`) — a page or frame: name, size, screenshot, link back to Figma.
- `FigmaBrowse` (`FigmaBrowse.js`) — the files list (`/framework/ext/Figma/`); `route()` hands off to `FigmaFilePage`.
- `FigmaFilePage` / `FigmaPagePage` / `FigmaComparePage` — one file's pages, one page's frames, and the compare view, each its own routed page (`core/Page/dynamic/`).
- `slug.js`, `sync.js`, `grid.js` — the readable-url helper, the cold-deep-link blocking read, and the one card-grid renderer every browse level shares.

## The Flow page (mine, 2026-11-11)

Page `Flow` (382:26220): a flowchart that lays itself out. Masters at x -954: Step set `382:26291`, Flow set `382:26329`, Branch set `397:12341`. `Page · Flow` (385:11721) shows a path from a bare surface to the hero left to right (A), top to bottom (B), a square fork (C), a rounded 3-path fork (D) and the duplicate test (E, `399:12332`).
- **Arrows are real vector paths** (`createVector` + `setVectorNetworkAsync`, `ARROW_LINES` cap, stroke bound to Scheme `muted`, weight 2), each in an auto-layout wrapper with the vector set to FILL along its axis, so it stretches with its container.
- **Direction is a variant** (Horizontal | Vertical) on Step and Flow, because `layoutMode` cannot be bound to a variable. **Step** = `Content` slot plus its trailing arrow as one unit, with a boolean `Arrow` (on by default). **Flow** = a `Steps` slot of Steps; there is no Add button (the old one is on the Cut list).
- **Duplicate to add:** select a step, Ctrl+D, and you get card and arrow (tested in section E). Turn `Arrow` off on the last step; when you duplicate the last step, turn `Arrow` on for the old last one.
- **Branch** (397:12341; only property `Direction`): a `Content` slot, a trunk and a `Paths` slot holding `Path` instances (first, middle, last). Gap: the trunk meets the fork exactly only when the path rows have equal height.
- **Traps:** a slot must be made with `component.createSlot()` (a plain frame has no `appendChild`); a zero-width vector set to FILL centres itself, so pin a spine to 0.01 and align the parent MIN; moving a node between instance slots leaves stale ids, so `clone()` then `appendChild`; `clone()` of a nested step does not land in its slot, so use `slot.insertChild(i + 1, step.clone())`.
- **Equal node height keeps arrows centred:** in a left-to-right row, a hugging node with a longer caption moves its own arrow. `rescale(k)` works on an instance; wrap it in a clipped frame of fixed width.
- **Pieces (2026-11-11), docs on `Page · Flow` (385:11721):** `Box` (403:18272) is the one content block (padding, fill, stroke only there); `Arrow` set (406:12016: Direction x Head) is the one arrow, its length, weight and gap bound to the `Flow` variables (`arrow-length` 64, `stroke` 5, `arrow-gap` 0); `Step` (408:12549) is a Box instance plus an Arrow instance with no slot (depth: Step > Box); `Flow` holds Steps in its one `Steps` slot. The old slotted Step and the old 8-variant Branch are on the Cut list (the old page flow still uses the old Step). Cloning a variant out of a set loses its slots, so recreate them with `createSlot()` and share one property per name with `set.addComponentProperty` plus `slot.componentPropertyReferences = {slotContentId}`.
- **Two variables style every line, `Flow/stroke` and `Flow/radius`:** Arrow, Branch Trunk and the `Fork piece` strokes bind to `stroke`; each fork piece's single bent corner binds to `radius` (0 = square). Editing a vector's weight by hand silently unbinds it; edit the variable instead. A vertex `cornerRadius` cannot be bound, so the pieces are frames with per-side stroke weights and a bound corner radius.
- **Path** (set 418:12371, `Place` First|Middle|Last (default Middle) x `Direction`): one `Fork piece` instance plus a `Content` slot holding a Flow. A Branch is a stack of Path instances; duplicate a Middle to add a path, switch `Place` to change an end. `Fork piece` (set 417:12300: Position x Direction, 6 variants) is the connector chunk. Square and Rounded Branch variants, the Paths=3 property and the vector Fork piece are on the Cut list.
- **Switching a Branch's `Direction`** keeps an edited Content box; the Paths stack resets to the new direction's defaults, since its rows are different components.
- **Fork test (2026-11-11, [mockup](https://www.figma.com/design/hbolzQ3Xnc78rhxAPj8xK2/Lew42-Design-System?node-id=414-12381)):** a connector cell of two halves that each FILL 50% of the row keeps the line centred on rows of any height; one absolute line is only right at hand-typed insets. Individual stroke weights plus a corner radius draw the rounded bend. Caveat: the trunk joins at the middle of all paths, which can miss the line when the first or last box is huge. A variable mode set on a Flow variant cascades into its slot content, but slot content does not follow variant switches and layout direction cannot be a variable.
- **Native connectors, tested 2026-11-11** (the owner's pasted ones are in `Frame 5`; side-by-side with our kit: `Mockup: native connectors vs our Path/Arrow kit`, 420:12387): `figma.createConnector` does not exist in a Design file, but `clone()` of a pasted connector works, and you then set `connectorStart`/`connectorEnd` (`{endpointNodeId, magnet}`), `text.characters` (a label), `connectorLineType`, `strokeWeight`. The stroke colour binds to a variable (Scheme `muted`); `strokeWeight` cannot be bound (no `setBoundVariable` on a connector) and `cornerRadius` is read-only, so `Flow/stroke` and `Flow/radius` do not reach them. A connector re-routes when an endpoint moves or an auto-layout gap changes (187 to 307 wide at gap 200 to 320), and it is re-pointed to the cloned boxes when a frame is cloned. It cannot sit inside a component (reparenting is refused), so it cannot be part of a Path/Step master; a duplicated Box gets no connector; an endpoint must be a top-level node, not a Box inside an instance (`Invalid endpointNodeId`). Only good for one-off diagrams drawn on the canvas; the Path/Arrow kit stays the reusable, variable-driven one.
- **Design-system gaps this chart exposed:** no Surface component and no Stack component (both are labeled placeholders on the page); a Card's header-and-body layout is an unpadded slot override, not a named mode.

## The layer rule and the Grids page (owner, 2026-11-12)

- **The layer rule (owner, 2026-11-12):** a page holds only three kinds of layer: **text** (always an approved text style), **component instances**, and **layout frames** (grids, stacks), the only loose layers. A layout frame need not be a component when it sits inside a parent component, because the parent still gives live updates. Anything you would design twice becomes a component. Plain grids are frame settings (auto layout wrap, or Figma's Grid layout, plus a gap), not components. **Masonry is the exception:** a component with a column count (`.Masonry`, 99:624).
- **Page `Grids`** (464:10330, right after Layouts; `Page · Grids` 464:10331): the layer rule as cards, Figma grid properties, **Grid vs flex** (the same six cards of unequal text in Grid layout, flex wrap and flex row, at 1000 and on a 1920 page), a recommendation, Scale mode flowing down, a 2/3/4 column matrix at both widths, a `.Masonry` note and a keep/cut inventory (proposals only). All demos use `Card` instances; no new components.
- **Grid layout facts (found by building):** a grid is `layoutMode = 'GRID'` with `gridColumnCount`, `gridRowCount`, `gridColumnGap`, `gridRowGap` (both bind to the Scale `gap` variable). **Set `gridRowSizes` to `[{type: 'HUG'}, ...]`**: the default FLEX rows on a hugging frame collapse to 100 px tall and the cards overlap. Cards set to FILL in both directions equalize heights per row; in flex wrap and flex row they do not. Figma Grid lacks `auto-fill` / `auto-fit`, mixed `fr` sizes, and its `auto` acts like `1fr`.
- **Padded vs flush** (section on Grids, 469:10977): padded = Card instances, gap bound to `gap`, clip off. Flush = grid gap 1 px over a hairline fill (Scheme `muted`), clip ON with the radius bound on the grid frame only, and each Card instance overridden to `cornerRadius = 0` with `effects = []`. Flush items never carry their own radius. Applied to `Grids & sizes` (photos flush grid: image radius 0, grid clips, one outer radius).
- **Clip content off:** a card shadow is an outer effect and any ancestor with clip on cuts it. Every grid on Grids has `clipsContent = false`. Clip is also off (2026-11-12, checked first: no section content bleeds or uses an image fill, so nothing relied on it) on `.Section`'s `Content` slot (48:608) and `Label` (48:602), and on the Layouts example frames 50:810, 50:816, 50:818, 50:822, 50:824. The `Card` master keeps its own clip (its own shadow is not cut by itself). A flush grid keeps clip on by design.
- **Demo backgrounds (2026-11-12):** a Demo layer carries NO Scheme mode (a mode would also recolour the cards inside it) and its fill is bound to Colors `light` (6:4), not Scheme `fill`. Only the page root frame sets Scheme White. Other pages still using Scheme Light gray + `fill` on Demo/Page frames: Live, Start here, Text layouts, Grids & sizes, the four device pages, Pages (not changed).
- **Names:** a card grid only adds a gap, so its class is `.grid.gap` (both exist in `framework.css`); radius and shadow belong to the child `.card`. Uneven-height demo on Grids ("Uneven card heights"): Grid rows are as tall as the tallest card; cards set to FILL vertically equalize per row; cards that hug keep their height and `gridChildVerticalAlign` (MIN/CENTER/MAX) places them in the cell; wrap and `.Masonry` keep every height.
- **Grid widths and counts** (Grids page, G1 to G19): a grid has no typed width; put it in a GRID section frame with `gridColumnSizes` `[{FIXED 1000},{FLEX 1}]` and set the grid child to FILL. Track sizes (FIXED, FLEX, HUG) and `gridColumnCount` are settable in code; only the gap binds to a variable, the counts do not. Flex wrap with card `minWidth` and `maxWidth`: cards squeeze and stretch between them, and a last row with one card stretches full width with only a min, but stops at the max when one is set. Pick a Scale mode whose `pad-x` is about a tenth of the card width (2/3/4 columns at 1000: Default/SM/XS; at 1600: LG/Default/SM). A flex row with no wrap squashes cards (G5, a "don't").
- **Grids & sizes, section 4 and 5 (2026-11-13):** section 4 is one master, `Size · Default` (`505:12390`, 1000: label, Scale-mode line, one Card with kicker, title, line, button), which carries no Scale mode; every other column is an instance of it with its Scale mode set on the Card layer inside the instance (never the instance root, so the label stays unscaled): XS 360, Mobile 390, SM 600, LG 1600, Desktop 1920, XL 2600, Mega 3440. The proposed ladder (4b) is on the Cut list. There is no Desktop mode, so Desktop uses LG. Section 5 (`503:13180`) is one 5-block view per width under the same columns, with the sweet-spot column count per width. Responsive recipe that works: auto layout horizontal, Wrap on, frame width fixed and height hug, each card FILL width with Min width 320 (Max width optional). Min width makes it stack; Max width stops the orphan stretching; a Grid keeps a fixed column count and equal heights but never reflows. **Section 6, Layouts reference** (`516:11818`, owner 2026-11-13: no grid components, the gap token is the control): one 1920 frame in Scale mode SM with small blank-card grids (2, 3, 4, 6 col, 2+1, 1+2, 12 tiles, hero+3; gap bound to the Scale gap) and three flush styles to pick from (white + gray hairline, transparent + border, transparent + 3 px gap). ## Notes from your asks

- Rules, preferences and ideas you said about this module: [doc/notes-from-asks.md](doc/notes-from-asks.md)

**Native connectors (FigJam arrows pasted into a design file), learned 2026-11-11:** a script can't create one or move its midpoint or label (`createConnector`, `connectorControlPoints`, `connectorTextPosition` are refused). Clone a connector whose route already looks right, then set `connectorStart` / `connectorEnd`. The clone keeps its midpoint at the same distance from the source box's left edge, so charts whose source boxes share a width (416 on the Flow page) route cleanly. To force a re-route, point `connectorEnd` at another node and back; re-setting the same endpoint does nothing. Labels sit at the path's middle (the shared trunk on a branch), so keep them to short words like yes / no.

**Owner's direction, 2026-11-12:**
- **Demos teach.** Each one shows the problem or the solution at a glance, clickable, with the master and its instances side by side. Put masters at the page root so Figma's name label sits above each one. Small pages, one topic per page. Use our components, not loose frames. Keep them visual: masonry grids of familiar things.
- **Layouts:** design at 1920 pages holding 1600 sections. The breakpoints are open: 1440 and 768 are designer habit, and 1000 is a nice round one. He wants one rule across all widths: padding based on width, clamped, which is CSS `clamp()` on the web.
- **Image cards:** a big image runs edge to edge with no padding (a Panel layout); only the text gets padding.
- **Hidden from publishing:** start the name with `.`, which Figma documents for components. `_` is documented only for variable collections, and the forum reports it stopped working for components.
- **Naming:** every component set ends in `Set` (see Component pages above).
- **Agents edit the master, never an instance** (owner, 2026-11-12). To change something you see in a preview, go to its main component and change it there, so every copy follows. Never edit an instance and then push it. Overriding and pushing is a human shortcut, and it causes the drift: slot content on an instance belongs to that instance, so a preview stops following its master. Pushing back has no merge, so one side always wins. Push always goes to the main component of whichever instance is selected, so a nested button pushed from the card only changes Card.
- **Screenshot, then wait for approval** (owner, 2026-11-12): screenshot everything before calling it done; the owner approves. The Lew42 Design System page is the approved set. What's on it is pre-approved, and agents build only from it. An "Approved" tag for signed-off pages is an idea, not built yet.
