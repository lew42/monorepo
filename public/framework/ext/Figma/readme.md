# Figma — tracks Figma files as JSONL + saved screenshots, so the site can browse every page and rebuild designs without Figma

## Use

**Before any Figma design work:** the `figma` skill (`.claude/skills/figma/SKILL.md`): the file, the page convention, the recipe ([doc/use-figma.md](./doc/use-figma.md)), and [doc/troubleshooting.md](./doc/troubleshooting.md) when something goes wrong.

[Figma guide](/framework/ext/Figma/guide/): how Claude draws in Figma, coded from the 3440 design it drew ([doc/use-figma.md](./doc/use-figma.md)).

Page: [/framework/ext/Figma/](/framework/ext/Figma/) — files, then a file's pages as a preview grid, then one page large with its frames, then its compare view: `/framework/ext/Figma/<file-slug>/`, `.../<file-slug>/<page-slug>/`, `.../<file-slug>/<page-slug>/compare/<frame-slug>/` — real routed pages (`route()`, FigmaFilePage.js/FigmaPagePage.js/FigmaComparePage.js), so reload and back land in the same place. An old `?file=<key>&page=<node id>&compare=<node id>` link still opens — FigmaBrowse.js rewrites it to the real url in place. Rebuilt designs: [Color Schemes](/framework/ext/Figma/colors/), all nine Palette sections from Page 7, starting at [The Approved Schemes](/framework/ext/Figma/palette/) and declared by [palette](/framework/ext/Figma/palette/); plus [Auto layout](/framework/ext/Figma/autolayout/) (Page 8). The rebuilt pages use the site's style system (`--prime`, the four `bg-` grounds, one `.card`; [architecture](/framework/styles/doc/architecture.md)), so they show our accent, not Figma's blue, and keep only the CSS unique to each design. Each browse card shows its Figma shot and, when a page was built from it, a Built page link and a side-by-side Compare view.

Track or refresh a file (the Figma MCP only answers inside an agent session, so an agent supplies a spec of node ids and screenshot URLs; the script computes the rest):

```
node public/framework/ext/Figma/track.mjs spec.json
```

Scripts (run from the repo root): `node public/framework/ext/Figma/built.mjs` maps Figma node ids to built pages (re-run after adding a page); `thumbs.mjs` makes the 480 px card thumbnails; `visibility.mjs` lists any page.js no parent declares (the merge gate runs it, exit 1 if any).

## Classes

- `Figma` (`Figma.js`) — the system; `Figma.files()` loads every tracked file from `index.jsonl`; `files_sync()` is the one blocking read a cold deep link needs.
- `FigmaFile` (`FigmaFile.js`) — one tracked file: key, name, pages; reads `data/<key>/pages.jsonl` (newest line per id wins); gives every page and frame its slug.
- `FigmaNode` (`FigmaNode.js`) — a page or frame: name, size, screenshot, link back to Figma.
- `FigmaBrowse` (`FigmaBrowse.js`) — the files list (`/framework/ext/Figma/`); `route()` hands off to `FigmaFilePage`.
- `FigmaFilePage` / `FigmaPagePage` / `FigmaComparePage` — one file's pages, one page's frames, and the compare view, each its own routed page (`core/Page/dynamic/`).
- `slug.js`, `sync.js`, `grid.js` — the readable-url helper, the cold-deep-link blocking read, and the one card-grid renderer every browse level shares.

## The Flow page (mine, 2026-11-11)

Page `Flow` (382:26220): a flowchart that lays itself out. Masters at x -954: Step set `382:26291`, Flow set `382:26329`, Branch set `397:12341`. `Page · Flow` (385:11721) shows a path from a bare surface to the hero left to right (A), top to bottom (B), a square fork (C), a rounded 3-path fork (D) and the duplicate test (E, `399:12332`).
- **Arrows are real vector paths** (`createVector` + `setVectorNetworkAsync`, `ARROW_LINES` cap, stroke bound to Scheme `muted`, weight 2), each in an auto-layout wrapper with the vector set to FILL along its axis, so it stretches with its container.
- **Direction is a variant** (Horizontal | Vertical) on Step and Flow, because `layoutMode` cannot be bound to a variable. **Step** = `Content` slot plus its trailing arrow as one unit, with a boolean `Arrow` (on by default). **Flow** = a `Steps` slot of Steps; there is no Add button (the old one is on the Cut list).
- **Duplicate to add:** select a step, Ctrl+D, and you get card and arrow (tested in section E). Turn `Arrow` off on the last step; when you duplicate the last step, turn `Arrow` on for the old last one.
- **Branch** (397:12341; only property `Direction`): a `Content` slot, a trunk and a `Paths` slot holding `Path` instances (first, middle, last). Gap: the trunk meets the fork exactly only when the path rows have equal height.
- **Traps:** a slot must be made with `component.createSlot()` (a plain frame has no `appendChild`); a zero-width vector set to FILL centres itself, so pin a spine to 0.01 and align the parent MIN; moving a node between instance slots leaves stale ids, so `clone()` then `appendChild`; `clone()` of a nested step does not land in its slot, so use `slot.insertChild(i + 1, step.clone())`.
- **Equal node height keeps arrows centred:** in a left-to-right row, a hugging node with a longer caption moves its own arrow. `rescale(k)` works on an instance; wrap it in a clipped frame of fixed width.
- **Pieces (2026-11-11), docs on `Page · Flow` (385:11721):** `Box` (403:18272) is the one content block (padding, fill, stroke only there); `Arrow` set (406:12016: Direction x Head) is the one arrow, its length, weight and gap bound to the `Flow` variables (`arrow-length` 64, `stroke` 5, `arrow-gap` 0); `Step` (408:12549) is a Box instance plus an Arrow instance with no slot (depth: Step > Box); `Flow` holds Steps in its one `Steps` slot. The old slotted Step and the old 8-variant Branch are on the Cut list (the old page flow still uses the old Step). Cloning a variant out of a set loses its slots, so recreate them with `createSlot()` and share one property per name with `set.addComponentProperty` plus `slot.componentPropertyReferences = {slotContentId}`.
- **Two variables style every line, `Flow/stroke` and `Flow/radius`:** Arrow, Branch Trunk and the `Fork piece` strokes bind to `stroke`; each fork piece's single bent corner binds to `radius` (0 = square). Editing a vector's weight by hand silently unbinds it; edit the variable instead. A vertex `cornerRadius` cannot be bound, so the pieces are frames with per-side stroke weights and a bound corner radius.
- **Path** (set 418:12371, `Place` First|Middle|Last (default Middle) x `Direction`): one `Fork piece` instance plus a `Content` slot holding a Flow. A Branch is a stack of Path instances; duplicate a Middle to add a path, switch `Place` to change an end. `Fork piece` (set 417:12300: Position x Direction, 6 variants) is the connector chunk. Square and Rounded Branch variants, the Paths=3 property and the vector Fork piece are on the Cut list.
- **Switching a Branch's `Direction`** keeps an edited Content box; the Paths stack resets to the new direction's defaults, since its rows are different components.
- **Fork test (2026-11-11, [mockup](https://www.figma.com/design/hbolzQ3Xnc78rhxAPj8xK2/Lew42-Design-System?node-id=414-12381)):** a connector cell of two halves that each FILL 50% of the row keeps the line centred on rows of any height; one absolute line is only right at hand-typed insets. Individual stroke weights plus a corner radius draw the rounded bend. Caveat: the trunk joins at the middle of all paths, which can miss the line when the first or last box is huge. A variable mode set on a Flow variant cascades into its slot content, but slot content does not follow variant switches and layout direction cannot be a variable.
- **Native connectors, tested 2026-11-11** (the owner's pasted ones are in `Frame 5`; side-by-side with our kit: `Mockup: native connectors vs our Path/Arrow kit`, 420:12387): `figma.createConnector` does not exist in a Design file, but `clone()` of a pasted connector works, and you then set `connectorStart`/`connectorEnd` (`{endpointNodeId, magnet}`), `text.characters` (a label), `connectorLineType`, `strokeWeight`. The stroke colour binds to a variable (Scheme `muted`); `strokeWeight` cannot be bound (no `setBoundVariable` on a connector) and `cornerRadius` is read-only, so `Flow/stroke` and `Flow/radius` do not reach them. A connector re-routes when an endpoint moves or an auto-layout gap changes (187 to 307 wide at gap 200 to 320), and it is re-pointed to the cloned boxes when a frame is cloned. It cannot sit inside a component (reparenting is refused), so it cannot be part of a Path/Step master; a duplicated Box gets no connector; an endpoint must be a top-level node, not a Box inside an instance (`Invalid endpointNodeId`). Only good for one-off diagrams drawn on the canvas; the Path/Arrow kit stays the reusable, variable-driven one.
- **Design-system gaps this chart exposed:** no Surface component and no Stack component (both are labeled placeholders on the page); a Card's header-and-body layout is an unpadded slot override, not a named mode.

**Native connectors (FigJam arrows pasted into a design file), learned 2026-11-11:** a script can't create one or move its midpoint or label (`createConnector`, `connectorControlPoints`, `connectorTextPosition` are refused). Clone a connector whose route already looks right, then set `connectorStart` / `connectorEnd`. The clone keeps its midpoint at the same distance from the source box's left edge, so charts whose source boxes share a width (416 on the Flow page) route cleanly. To force a re-route, point `connectorEnd` at another node and back; re-setting the same endpoint does nothing. Labels sit at the path's middle (the shared trunk on a branch), so keep them to short words like yes / no.
