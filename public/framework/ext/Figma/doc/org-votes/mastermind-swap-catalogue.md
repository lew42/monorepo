# Org vote: mastermind-swap-catalogue (2026-11-16, from memory of [swap-catalogue](../swap-catalogue.md); no Figma calls)

**Q1. Resolution-first pages, with one shared Elements page.** Figma's swap menu and right-click switch list the same page/frame, and Assets groups file > page > frame, so a page per width makes every swap target the right size without any property. Pages per component type put every size in one menu, which is exactly today's "wrong size in the list". The catch is one-of-everything: Card, Button, Icon.Item and the `Content /` blocks are size-agnostic (Scale mode sets size), so they live once on Elements, not per page. Per-tier pages hold only what truly differs: layouts, sections, nav chrome.

**Q2. Order on each resolution page:** Preview, Layouts, Sections, Containers, Content (only blocks that differ at this width; the rest come from Elements). Yes: build the Preview screens entirely from instances of that page's masters (and Elements'), so every region in the demo is a real swap test. The Preview holds instances only, never masters, so it can be previewed live on Index.

**Q3. Both is possible:** make each role a top-level frame (`Layouts`, `Sections`, `Containers`, `Content`: the real folders Assets sees), and put the one-screenshot tidy view in a separate top-level `Preview` frame of instances. The cost: no single Root, so no one-frame export of the masters; the Preview covers that need. Unverified: whether a Section (a canvas container, not a frame) also groups in Assets. One 2-minute test settles it, and Sections would give tidy canvas grouping with real folders.
