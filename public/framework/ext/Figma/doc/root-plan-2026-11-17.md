# Root system and size-page previews: plan (2026-11-17)

Source: [owner-words-2026-11-17-root.md](./owner-words-2026-11-17-root.md) (verbatim). Rules: [rules.md](./rules.md) 7, 17, 19, 20.

## Decided (owner)

1. **One Root per page, the same on every page, tokenized and not a component.** A component would need a slot, which he doesn't want. Everything on the page is inside Root.
2. **Root spec.** His reference is the Index page, which he configured himself today.
   - Fill: Colors `tint` (black 5%, a token he created today).
   - Scale mode: **3440 Mega**, set on Root itself, which gives Root big padding.
   - Padding: `section-pad-x` / `section-pad-y`. Gap: `section-pad-x` (tentative).
   - Direction: **horizontal**. Root holds **Root columns**.
3. **Root columns.**
   - Each column has a title and sets its own Scale mode: the tier it shows, for example 1920 Desktop.
   - Width is fixed at **1920** when possible, wider only when needed.
   - Height hugs. Nothing grows to 5000 or 13000 wide.
   - Nothing sits directly in Root except columns, plus a hidden Archive.
4. **Ground colours are locked:** Root is `tint`, each preview sheet is Colors `light`, and cards are white. Each page shows one dark card as the scheme example, and keeps the image cards.
5. **Size-page previews show only that page's width.**
   - Every layout in the 1000 preview is 1000 wide: a mini viewport. Inside it, the cards can be any size.
   - A 1600 content area holds roughly a 500 label column plus a 1000 layout.
   - Show 1-, 2- and 3-column layouts at each width, different splits, and schemes: a white sidebar on a light gray background, and one dark example.
   - Later: widgets such as icon items, file explorers and image overlays.
   - Maybe a specimen master per example, so a page is a list of them.
6. **Index:** a link to every preview page, in titled Root columns. The Sizes column stacks the 1920-wide previews; 3440 previews break out or shrink. The Big Sloppy `Page Set` on the Index isn't ours. The old Index screenshot is `image 1`, in Index's Archive.
7. **Look at sizes and screenshots first.** The 1920 Desktop Root is 13000 × 9000 and about 80% empty. His screenshot of it is `image 1` on that page. A fixed 13000 width becomes Hug.

## Proposed (voice-app, for the owner to confirm)

- **Modes are set in exactly three places** (rule 19): Root (Mega), each Root column or specimen viewport (its tier), and a Container whose cards should look different from its Section (the [wrapper](./mode-split.md)). Cards never get a Scale mode. Today, Scale cards that inherit a section's 3440 padding need per-card overrides. Under this rule, the Container takes the card mode once, and the Card master still drives everything else.
- **Before Root goes to Mega, freeze its children.** Each direct child of Root first gets its current resolved Scale mode set explicitly, so nothing inside changes when Root switches.
- **Token remap is a proposal only.** Today 1920 has section padding 68 and LG 64. He floated 1920 → ~72, 2600 → ~120, 3440 → ~256. The modes research agent checks this against what real systems do, and nothing changes until he approves.
- **Size tiers:** he is open to only Mobile and Default, or 400 / 1000 / 1920. This is decided after the 1000 pilot.
