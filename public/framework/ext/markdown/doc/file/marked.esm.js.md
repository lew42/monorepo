## Why vendored, not a CDN import or an npm dependency

The site's whole thesis is files served as-is, no build step. A CDN import
would make every markdown render depend on a third party and break offline
dev; an npm dependency would need a bundler this repo doesn't have, since
`node_modules` isn't shipped to the browser. Vendoring is the only shape that
keeps `md.js`'s `import { marked } from "./marked.esm.js"` a real, static
ES-module import that runs unmodified in the browser. Cost paid only by pages
that actually import `ext/markdown`.

## Never edited

The file's own header says so — `DO NOT EDIT THIS FILE` — and this doc
repeats it because that instruction is otherwise invisible to anything that
doesn't open the file: it's a generated build artifact from `marked`'s own
`./src/`, not hand-maintained source. `md.js`'s fence-renderer override
(`marked.use({ renderer: { code(){…} } })`) is the sanctioned way to change
`marked`'s behavior — patch the running instance from outside, never the
vendored file itself.
