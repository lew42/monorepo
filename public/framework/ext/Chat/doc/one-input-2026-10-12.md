# One input everywhere; every mic refines live — 2026-10-12

Brief: `/framework/ai/2026-10-12/refine-haiku-live/one-input/requirements.md` (parent: `/framework/ai/2026-10-12/refine-haiku-live/`, contract: `/framework/ai/2026-10-12/refine-haiku-live/contract.md`).

## The decision: a textarea, not a single-line `<input>`

**Shape:** `Composer.js`'s own `$input` is a textarea, one line tall when empty (`rows="1"`, `Chat.css`'s `.chatbox-compose-input` `min-height: 1.7em`), growing to about 5 lines (`max-height: 5lh`, `Mic.js`'s `SETTINGS.box_lines: 5`) before it scrolls inside itself. It never pushes the row below it.

**Alternative recorded, not taken:** a single-line `<input>` that scrolls sideways (the owner's own suggestion, worried a growing textarea "looks wrong and eats the area above it"). Rejected because it cannot show a paragraph of raw dictation on screen at once — and the raw-while-speaking reference (below) is exactly a paragraph building up as you talk. A sideways-scrolling input would hide most of it off-screen.

This was already roughly the shape `Composer.js` had (a full-width growing textarea under one control row) from earlier work (`doc/decisions.md`); this pass tightened the ceiling from 3 lines back up to ~5 (it had been cut to 3 on 2026-10-04 when the ceiling was 7) and started it at one line instead of two.

## Mic → refine, built into `ComposerMic` itself

Every composer with a mic already showed **raw text in the box while speaking** (`Mic.js`'s `build_tail`/`draw_caption` — unchanged, already true before this task). What's new:

- **`refine_live()`** (`ext/Refine/RefineSystem.js`) is a standalone function, not only a `RefineSystem` method — so `ComposerMic` can call it directly without building a full `RefineSystem` (which owns its own named Whisper session; instantiating one per composer would have mislabeled every mic's session as "Refine demo"). `RefineSystem.live()` wraps the same function for a caller (the Refine demo) that already owns a `RefineSystem`.
- **`ComposerMic.refine_tick(text)`** — debounced (400 ms), fires on every `draw_caption()` while `this.revise` is set (the same switch `clean_active()` already reads — a plain composer with `revise: false`, e.g. a bare typed box, is untouched).
- **`ComposerMic.refine_final(text)`** — called right before a send goes out (`send_screen()`, `flush_held()`), `final: true`. If the route answers with `slots`, **`ComposerMic.paragraph_from_slots()`** joins the slots' clean text into paragraphs (a break at a topic change — the slot's cite moves to a different outline section — or every ~4 sentences) and that replaces the plain joined text the bubble shows. Until `Servex/ext/refine/LiveRefine.js` lands and the dev server restarts, every call 404s and is swallowed (`refine_live()` returns `null`) — sends behave exactly as before this task.

## Surfaces

- **The Refine demo** (`ext/Refine/RefineDemo.js`) dropped its own `VoiceStrip` + plain `<textarea>` and now builds THE composer. `VoiceStrip` is not kept even as a status line: it ran a second, separate `Dictate` instance, and `ComposerMic`'s "one microphone at a time" guard only covers composer mics — running both at once risked two live mics. The composer's own status line (`.chatbox-compose-diag`) already says the same mic/whisper health in one line. Pressing the toolbar's own "Refine" button still works exactly as before (stops the mic, reads the box, calls `system.go()`); the composer's own Send (or the mic's pause auto-send) now ALSO runs a real Refine, reading `entry.text` — the words as they were AT SEND TIME, since `Composer.js`'s own `send()` clears the box before `deliver()` runs.
- **`Prompt.View`**'s "3 · Outline" section (`Prompt.js`) now shows `prompt.refined` the moment there is any (`RefineSystem.live()`/`on_refine_live` writes it there), not only once a full Refine is `done` — "live" is the new interim label.
- **Dictate page, the drawer AI tab, card composers** were already on `composer()` (via `ux/Dictate/Widget.js`'s own `Widget.Composer`) before this task — nothing structural changed there; they get the shape/line-count change and the mic→refine wiring for free, gated the same way (`revise`).
- **Session detail chat** is @mastermind-sessions-detail's own surface — not touched here.

## What's still open

- The live outline's paragraph breaks (`paragraph_from_slots`) are untested against a real server answer — `/api/refine/live` doesn't exist yet in this worktree (the other minion's own task). The client fails quietly to a 404 today; re-verify the paragraph grouping once the route is live.
- `refine_final`'s extra round trip runs on every send with `revise` set, even on a fast LAN — it resolves in well under the UI's own notice ("sending…"), but worth a real latency measurement once the route answers for real.
