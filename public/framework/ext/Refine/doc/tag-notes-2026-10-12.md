# Tag notes: a tagged prompt reaches its module's page

The owner's ask (2026-10-12): when a refined prompt card is tagged with a module (`ext/Refine`, `core/Page`, `ext/Figma`), the item reaches that module's own page by itself, as a note in that page's inbox. No second inbox.

## How it works
- The Haiku notes (`Servex/ext/refine/Annotator.js`) already tag each sentence with repo paths.
- `Servex/ext/refine/TagRouter.js` turns tag -> page by looking at the real tree on every run: `public/framework/<tag>/` (or `public/<tag>/`) with a `page.js` or `page.jsonl`. Nothing is remembered or hand-listed.
- Each tag with a page gets one note, written by the existing `Inbox.note` (`Servex/agents/inbox.js`, the `page_note` writer) as a `{"note": ...}` line on that page's `page.jsonl`. The page's rail (`core/Page/ext/Inbox`) shows it.
- The note holds a link to the source (`/framework/ai/sessions/<session>/`, the prompt id, sentence numbers like S2, S5), never the prompt's words.
- A tag with no page gets no note; `/api/refine` returns it in `tag_notes.unrouted`. A re-run of the same prompt adds nothing (`tag_notes.already`).

## Proof
`Servex/ext/refine/test/tag-router.mjs`: a throwaway tree with the real `Inbox`; one note on the right page, none for a tag with no page, nothing on a re-run. Not yet seen on a live page rail after a real refine; that needs a Servex restart.

## Not built
- Cards (not just sentences) as the unit: today the tags come from the sentence notes.
- A `to:` agent for the wake: the Inbox wakes the page's coordinator when one exists, which is the intended route.
