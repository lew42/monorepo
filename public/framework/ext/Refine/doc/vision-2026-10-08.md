# Prompt refinement — the owner's design, dictated 2026-10-08

Recorded so the intent survives chat. Nothing here is built as written; check each stage against `Refine.js`, `engine.js`, `structure.js` and the Dictate/Chat widgets before building. Related: [refine-engine.md](./refine-engine.md), [raw-match.md](./raw-match.md).

## The pipeline: every sentence accounted for
1. **Raw**: audio → the Whisper server (run by Servex) → raw text, mistakes included.
2. **Clean transcript**: near-verbatim. Fix capitalisation and obvious transcription errors toward what was *meant*; turn spoken paths ("something slash something") and names into real references. **Keep the owner's wording and word choice.** Number every sentence so each can be cited. (The fast assistant used to do this cleanup in the live voice chat.)
3. **Refined prompt**: organised, deduplicated (the owner loops back on topics), summarised wording allowed, but **nothing is dropped**. Built from UI **cards** (request / task / question / suggestion), interactive, in the chat. Every card cites the clean-transcript sentence(s) it came from, and a click opens that sentence in its own context.
4. **Coverage with a confidence level per sentence**: each clean sentence is marked handled (which card), observation/thinking-out-loud (no card needed), or **unhandled**. The point is that no request or important detail is missed between clean and refined.
5. **Handoff**: the refined prompt (its request cards) goes to a mastermind or minion.

## Context cards (instead of one-line links)
An **icon item** (the pill: icon + name, linking to a class/page/file) can be rendered as a full row: icon + name as the title and *context* inside (a few log lines of what happened there), not a preview of the whole thing. While the owner speaks, mentioned things appear as context cards so requests and suggestions land in the right place almost immediately.

## Where requests live (open design)
- Put requests and suggestions where they belong on the file system (a class's or page's inbox / `page.jsonl`) so future minions working in that directory see them, rather than leaving them in one session's pile.
- **Never lose the source.** The raw and clean prompts stay in the session, as the record and the accounting. A request moved to a class/page keeps a **reference** (path + id) back to its session; the content is stored once, not copied. Cost stays attributed to the session that spent it: moving a task's output must not make the session look cheaper.
- Open question: how to reference one item inside a `page.jsonl` by id without loading the whole file (instantiate the page and ask for the item by id? an index?). Route to the session/page-stream work.

## Addendum (owner, 2026-10-08, later) — the pipeline is session-coordinated, and it streams
- **Any prompt in any session** can go through the refinement pipeline: agentic filtering, editing, cross-referencing, logging. The **session system coordinates it**: a session is configured with the tools and agents the pipeline needs (see `ai/sessions/doc/session-as-container-2026-10-08.md`).
- **Streaming, per sentence.** The browser's Whisper transcription arrives as a raw stream; a cheap agent turns it into a clean transcript, chunked on the period and processed **per sentence** (capitalisation and other basics could be faster still). Batch audits of old prompts need not go sentence by sentence, but the system must support streaming. Refinement appears on screen as it happens.
- **Shape in code (to architect):** a `Prompt` class holding `raw`, `clean` (numbered sentences) and `refined`; `refined` is a content type of one or more cards, each with its own sub-cards and its own link. This belongs to the streaming system (JSONL tail), not a poll.
- **The fast assistant** (voice cleanup agent) was scrapped by the owner for now because it only produced useless chatter; the cleanup must come from this pipeline instead. Document the smart/fast assistants' history in the AI docs.
- **Replay on past data:** if tokens allow and pace holds, run the pipeline over old raw prompts from the SDK session logs (newest first) as the test of the system; the prompt audit (`2026-10-08/task-audit`) is the same job.

## Addendum 2 (owner, 2026-10-08, evening) — scores, flags, alternates, names, and the demo
Goal of the whole system: **be 100% sure every line of every prompt was handled properly.** Old sessions hold a lot of direction and requests, some followed, many not. Record these design ideas; keep it simple now, no token-burning multi-agent voting yet.
- **Clarity score per sentence** (how clear the statement is: do we understand its meaning, intention and purpose; logic is part of clarity). Include how sure we are of each **reference** identified in the sentence (a path, a class, a page): a confidence on each identification feeds the clarity score. Low clarity = probably garbled transcription (or a vague point). **Don't nag the user.** Show a small **yellow flag/question mark** by the sentence and move on, unless it is something very important.
- **Weight (relevance/importance) per sentence**: the AI's judgement of how important it is and how likely useful, how well it applies now. Separate from clarity (a sentence can be clear and no longer apply because something changed), though low clarity naturally lowers weight. Clarity + weight together drive how the UI treats each sentence.
- **Alternate wordings** for any sentence, section or chunk: shorter, simpler, same essence, shown as suggestions; the clean transcript itself stays near-verbatim. The human decides, unless confidence is high. Later maybe several agents propose and rank (clarity, simplicity, closeness to the original); not now.
- **Naming**: always look for good short names for core ideas to refer to again: one word best, two words great, three okay if clear. Each named idea gets a page (CLAUDE.md "Name things").
- **A `Prompt` class** (raw, clean with numbered sentences, refined as cards with sub-cards, each sentence with `clarity`, `weight`, `flags`, `alternates`, `names`), usable for VS Code prompts, voice dictation and plain text chat. One class, one view (`Prompt.View`).
- **The `ext/Refine` page should be a working demo**: a dictation widget on the page (usable on the phone) that refines **one prompt at a time**: speak, see raw to clean to structured with the scores and flags, record again. Beside it, the **debug/class view** of the live `Prompt` instance (see CLAUDE.md "Show the class") so the structure changing is visible as you use it.
- **Unknown to find out** (a Haiku minion, report in the AI docs): how Dictate (`ux/Dictate`), the Chat class, `ext/Refine`, `Server/refine.mjs` and the old fast assistant connect; where the clean step really ran, and where the token cost shown in the chat window during dictation came from.
